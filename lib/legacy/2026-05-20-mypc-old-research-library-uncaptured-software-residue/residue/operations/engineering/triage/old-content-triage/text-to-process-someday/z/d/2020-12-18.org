 So a [[file:../record.org][record]] is [[file:../serialization.org][serialized]] [[file:../information.org][information]], so is itself information (its [[file:../data.org][data]] being the information and [[file:../meta_data.org][meta-data]] being the serialization format.)

 In order for information to be serialized as a record, it needs to be associated with a [[file:../schema.org][schema]]. The specification for handling a serialized schema is a [[file:../record_type.org][record type]].

 So, this writing lives inside the =2020-12-18.org= record, which is of the [[file:../daily_record.org][daily record]] record type.

 Does this translate into a step-by-step for "I have identified a new type of information" to "[[file:../groundhog_emacs.org][Groundhog Emacs]] can capture this information as an appopriate record?"

 1) Identify a new type of information: something that defines what a word or phrase means.
 2) Name this type of information: =term definition= seems like a good one
 3) Determine the information's data and meta-data.
 4) Craft the information's schema
 5) Define a record type based on the schema
 6) Create a template record of that type
 7) Create a capture template based on that record

 A few of these definitely need more specification, but at a glance, this does indeed bring me from "identify new information" to "can capture it in Groundhog Emacs."

 I think it also begs the question, "what qualifies as 'new type of information,'" which for now I'm going to answer off-the-cuff as "information that can be cultivated into an asset in a better way than existing information types account for.
