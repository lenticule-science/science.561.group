# Encoding

## What this node is

Where [predication](../predication/predication.md) unfolds [relation](../../relation.md) into *what is said of the related* — categories, types, logics, order — **encoding** unfolds the same base into *how the related is written down*. It is the second branch off relation, the corpus's other generative chain: the codec restriction-lattice `path → object → attribute → file → flatfile → serialization → json → jsonl → eavt`, where each segment conjoins one more conjunct of recognition and the leaf carries evidence only.

This is the generative home for **encoding knowledge categorically** — the corpus's own method, the discipline by which this entire library is organized. A POSIX filepath is not a shelf coordinate; read with Curry–Howard directionality it is a typed term, a proof of the proposition that is its type, and a node is determined by its morphisms (the Yoneda embedding `𝒴(A) = Hom(−, A)`) rather than by the folder that contains it. Encoding is where that claim is made precise: the term ⇄ path codec `address`/`termOf`, the round-trip canonicality test, classification-as-tag-not-directory, and the recursive `topic/content/topic/content` unfolding.

## Orientation

Encoding and predication are two faces of the one relational base, exactly as a category and a type are two faces of predication. Predication tells you *what mathematics the related generates*; encoding tells you *how to write any of it down so that the writing is itself a proof*. Read the node below for the codec; read [the generative unfolding](../../docs/explanations/the-generative-unfolding-of-mathematics.md) for how the predication branch is derived. Both branches are the corpus's own research made walkable: the codec restriction-lattice for encoding, the predication chain for the structures.
