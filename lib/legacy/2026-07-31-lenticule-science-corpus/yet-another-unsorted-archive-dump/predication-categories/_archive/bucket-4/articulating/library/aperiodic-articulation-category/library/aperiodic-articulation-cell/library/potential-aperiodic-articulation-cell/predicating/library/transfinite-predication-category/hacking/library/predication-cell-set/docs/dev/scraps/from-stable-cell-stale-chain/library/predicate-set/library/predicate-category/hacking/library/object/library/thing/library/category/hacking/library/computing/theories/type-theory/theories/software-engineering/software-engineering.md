Software engineering is treated here as a discipline within [computing](../../_index.md) — the practice-side counterpart to the substrate-side studies of [predicated-computing](../predicated-computing/_index.md). Computing studies what computers *are*; software engineering studies what humans (and increasingly agents) *do* to produce, evolve, and operate them.

The discipline's content decomposes into the *activities* that produce or change software (development, refactoring, testing, deployment, observation, deletion) and the *paradigms* that organize those activities (waterfall, agile, continuous-delivery, kernel-and-modules, monorepo-and-trains, etc.). The fusion theory — [predicated-software-engineering](../predicated-computing/theories/predicated-software-engineering/_index.md) under predicated-computing — re-presents these activities as operations on a substrate-algebraic codebase: a codebase as a predication-cell-system, a change as a witness-increment, a refactor as an invisible automorphism.

## Subtheories

- [`software-development/`](theories/software-development/_index.md) — the activity of building and evolving software: the cycle from requirement to deployed artifact, and the sub-activities (refactoring, testing, code review) that compose it.
- [`structured-work-paradigms/`](theories/structured-work-paradigms/_index.md) — paradigms (agile, waterfall, etc.) for organizing the work of software production; how they map onto work-vocabulary structures (cadence, recurrent-practice, dispatch).
- [`research/`](theories/research/_index.md) — research methods specific to studying software engineering practice.

## Status

The discipline has long-standing literature; the theory-tree here is being assembled to anchor 561's running practice. Current focus: software-development → software-refactoring, with predicated fusions developed in parallel under predicated-computing.
