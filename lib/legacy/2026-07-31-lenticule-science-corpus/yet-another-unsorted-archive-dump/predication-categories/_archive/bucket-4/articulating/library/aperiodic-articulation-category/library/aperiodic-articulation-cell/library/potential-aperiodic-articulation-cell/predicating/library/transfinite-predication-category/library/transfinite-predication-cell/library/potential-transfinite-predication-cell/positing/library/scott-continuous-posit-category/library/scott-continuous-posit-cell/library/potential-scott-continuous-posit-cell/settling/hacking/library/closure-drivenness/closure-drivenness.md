# Closure-drivenness

A settlement `v = (v_τ)_{τ<λ}` is **closure-driven** by a closure-operator family `cl = (cl_p)_{p ∈ C}` if each successor step has the form

$$v_{\tau+1}(p) \;=\; \mathrm{cl}_p\bigl(v_\tau(p) \;\vee_k\; u_{\tau+1}(p)\bigr)$$

for some increment-sequence `(u_τ)_{τ<λ}`, with `∨_k` cellwise.

Equivalently, for each cell `(s, p, o)`:

$$v_{\tau+1}(p)(s, o) \;=\; \mathrm{cl}_p\bigl(v_\tau(p) \vee_k u_{\tau+1}(p)\bigr)(s, o).$$

## What the formula encodes

The successor step is **never arbitrary**. It is always:

1. Take the previous state `v_τ(p)`.
2. Knowledge-join with the new increment `u_{τ+1}(p)` — merge new evidence in.
3. Apply the closure operator `cl_p` — derive all inferential consequences.

The result is `v_{τ+1}(p)`. This decomposition is the **operational signature of settling**: at every step, settling does the join-then-close pattern. No other shape of step is allowed.

## Why "driven by closure"

The closure-operator decides what the successor MUST be, given the prior state and the new evidence. The settling is not free; it is constrained by what `cl_p` will derive.

Equivalently: closure-drivenness is the condition that the settling implements an **observable inferential dynamic**. Each step's content is a function of (previous state, new evidence, closure rule); knowing those three determines the next state uniquely. The orbit's evolution is therefore **deterministic** given the closure-operator and increment-sequence.

This is the formal condition that supports **reproducibility**: two independent runs of the same settlement-with-same-rule-system-and-same-increment-sequence produce literally the same orbit. The orbit is a function of its data, not a choice that observers can vary.

## Closure-drivenness implies settling-monotonicity

Closure-drivenness automatically gives settling-monotonicity on successor steps:

1. `v_τ(p) ≤_k v_τ(p) ∨_k u_{τ+1}(p)` (the `≤_k`-join is `≤_k`-above each operand).
2. `v_τ(p) ∨_k u_{τ+1}(p) ≤_k cl_p(v_τ(p) ∨_k u_{τ+1}(p))` (closure is inflationary).
3. Combining: `v_τ(p) ≤_k v_{τ+1}(p)`.

So closure-driven ⟹ monotone on successors. For limit ordinals, settling-continuity completes the argument: if `v_μ(p) = ⋁_k {v_σ(p) : σ < μ}`, then by monotonicity at preceding steps, `v_σ ≤_k v_μ` for `σ < μ`, so monotonicity continues through limits.

**Conclusion**: closure-driven + continuous ⟹ settling-monotone. Closure-drivenness is therefore the **structural source** of settling-monotonicity; the latter is a consequence, not an independent axiom, for closure-driven orbits.

## Identifiability: the inverse problem

Given a settlement `v`, **can we recover the closure-operator and increment-sequence**?

If `v` is closure-driven by exactly one `(cl, u)` pair, yes — `cl` is determined by its action on each cell-value combination seen in the orbit, and `u_{τ+1}` is forced by `v_τ` and `v_{τ+1}` via the formula. The settlement is then **fully identifiable** from its data.

If `v` is closure-driven by multiple `(cl, u)` pairs (different operators producing the same orbit), the settlement is **underdetermined** with respect to its driving data. This can happen: different closure-rule-systems may agree on the realized orbit while differing on counterfactual inputs.

The realizability program (archive narrative, not yet pulled) studies which orbits arise as closure-driven settlements for some closure-rule-system in a given language fragment. This is the **forward direction** of identifiability: characterizing the space of possible `v` for fixed `(cl, u)`-variability.

## Non-closure-driven settlements

Non-closure-driven settlements are settling-monotone families that DON'T fit the join-then-close pattern. These can exist mathematically (any monotone family is allowed if one drops the closure-drivenness condition) but they are **pathological** in the substrate: they are not produced by any settling-endofunctor on any closure-rule-system.

The four-regime tower classifies **closure-driven** settlements. Non-closure-driven settlements are outside the substrate's regime stratification; they are not generated by primitives.

## Worked example: a closure-driven orbit

Take `L = 2`, single predicate `p`, `E = {a, b}`. Closure-operator: `cl_p(v)(s, o) = t` if `v(s, o) ≥_k t`, else `v(s, o)`. (Rule: if positive evidence is held, keep it; never demote.)

Initial state `v_0(p)(s, o) = ⊥` for all `(s, o)`.

Increment-sequence: `u_1(p)(a, b) = t`, `u_1` otherwise = `⊥`. `u_2(p)(a, a) = t`, `u_2` otherwise = `⊥`. `u_τ = 0` for `τ ≥ 3`.

Orbit:
- `v_0 = ⊥` (everywhere).
- `v_1(p)(a, b) = cl_p(⊥ ∨_k t) = cl_p(t) = t`. Other cells: `v_1(p)(•, •) = cl_p(⊥) = ⊥`. So `v_1` has `t` only at `(a, b)`.
- `v_2(p)(a, a) = cl_p(⊥ ∨_k t) = t`. `v_2(p)(a, b) = cl_p(t ∨_k ⊥) = t`. Other: `⊥`.
- `v_3(p)` = `cl_p(v_2(p))` = `v_2(p)` (closure is idempotent on `v_2`). Quiescence.

Closure-ordinal `κ = 3` for this orbit — quiesces in the strict-finite regime.

## Worked example: a non-closure-driven family

`v_0(p)(a, b) = ⊥`, `v_1(p)(a, b) = f`, `v_2(p)(a, b) = t`, `v_3(p)(a, b) = ⊤`. (Cells progress arbitrarily.)

This IS settling-monotone (`⊥ ≤_k f`, `f ≤_k ⊤`, `t ≤_k ⊤` all hold — but `f ≤_k t` does NOT hold). Wait — `v_1 = f` and `v_2 = t`: is `f ≤_k t`? No, `f` and `t` are knowledge-incomparable. So this family is not even settling-monotone, let alone closure-driven.

A genuinely non-closure-driven monotone family: `v_0 = ⊥`, `v_1 = t`, `v_2 = ⊤`, `v_3 = ⊤`. Monotone (each `≤_k`-above previous). But there's no single `cl` such that `cl(⊥ ∨_k u_1) = t` and `cl(t ∨_k u_2) = ⊤` for some natural `u_1, u_2`: the closure changes the rule between steps. Such a family does not arise from any single closure-operator; it's monotone but not closure-driven.
