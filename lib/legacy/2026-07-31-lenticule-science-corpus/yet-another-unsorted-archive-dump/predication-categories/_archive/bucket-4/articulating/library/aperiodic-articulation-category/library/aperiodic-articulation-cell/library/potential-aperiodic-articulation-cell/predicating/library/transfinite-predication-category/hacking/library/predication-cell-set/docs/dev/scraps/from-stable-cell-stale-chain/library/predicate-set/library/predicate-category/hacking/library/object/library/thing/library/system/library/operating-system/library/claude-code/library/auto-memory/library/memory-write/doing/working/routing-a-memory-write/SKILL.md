---
name: routing-a-memory-write
description: Blocks Write/Edit/MultiEdit calls targeting the auto-memory location and tells the caller to write to the in-repo location instead. Use as a PreToolUse hook to keep all memory writes in the in-repo location.
---

## Requirements

- Invocation from a Claude Code PreToolUse hook with matcher `Write|Edit|MultiEdit`.
- Hook payload on stdin as JSON, containing `tool_name` and `tool_input.file_path`.

## Steps

1. Read stdin JSON; extract `tool_name` and `tool_input.file_path`.
2. If `tool_name` is not one of `Write`, `Edit`, `MultiEdit`, exit 0 (allow).
3. If `file_path` is empty or does not match `~/.claude/projects/<project-id>/memory/<filename>`, exit 0 (allow).
4. If the filename is `MEMORY.md`, exit 0 (allow — the index is regenerated by `loading-the-character-memory`).
5. Parse the filename for the type prefix: one of `feedback_`, `reference_`, `user_`, `project_`. If no prefix matches, exit 2 with a stderr message naming the expected prefixes.
6. Compute the in-repo target path: `prose/journals/memories/<type>/<slug>.md`, where `<type>` is the prefix without the trailing underscore and `<slug>` is the rest of the filename with underscores converted to hyphens and the `.md` removed.
7. Exit 2 with a stderr message naming the in-repo target path and telling the caller to write there.

## Outcomes

- Writes to the auto-memory location are blocked with a redirect message.
- Writes targeting `MEMORY.md` in the auto-memory location pass (handled by SessionStart sync).
- Writes anywhere else pass.
