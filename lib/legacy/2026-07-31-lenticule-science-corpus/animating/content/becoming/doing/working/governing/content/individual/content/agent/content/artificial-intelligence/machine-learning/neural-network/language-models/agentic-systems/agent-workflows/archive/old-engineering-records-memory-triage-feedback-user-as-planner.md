When the user shares philosophical or architectural thinking, don't rush to act on it. Stabilize and cohere the ideas into something structured first, then propose concrete steps.

**Why:** The user explicitly asked Claude to "think deeply about inputs, not to ACT on them, but to stabilize/cohere them." The user sees their role as providing intuition and direction; Claude's role is to weave it into coherent, actionable structure.

**How to apply:** When the user shares big-picture thinking, reflect it back as structured architecture before proposing implementation. The user will confirm or redirect. This is especially true for harness design, system architecture, and organizational structure.
