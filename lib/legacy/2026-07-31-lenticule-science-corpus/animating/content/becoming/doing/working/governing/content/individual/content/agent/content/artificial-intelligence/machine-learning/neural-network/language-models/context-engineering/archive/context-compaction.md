# Context compaction

Context compaction is the lossy operation that replaces a prefix of the
conversation history with a compressed summary, recovering context budget while
preserving a lower-fidelity representation of the compacted content. It is
applied when the accumulated conversation history approaches the model's context
window limit.

## Operational structure

Context compaction takes as input a conversation history $H = [m_1, m_2, \ldots,
m_n]$ and produces a new history $H' = [\text{summary}(m_1, \ldots, m_k), m_{k+1},
\ldots, m_n]$, where $\text{summary}(\cdot)$ is a model-generated summary of
the first $k$ messages. The tail $[m_{k+1}, \ldots, m_n]$ is preserved verbatim;
the head $[m_1, \ldots, m_k]$ is replaced by its summary.

## Lossiness

Context compaction is irreversibly lossy. Information in the compacted prefix
that is not included in the summary is unrecoverable from the context window.
This has several consequences:

**Verbatim content loss.** Exact tool results, precise error messages, and
specific values present in the compacted messages are replaced by approximate
prose summaries. The agent may subsequently reason incorrectly based on
imprecise recollections of compacted content.

**Decision trace loss.** Reasoning steps in the compacted prefix — why the agent
made particular decisions — are summarized or discarded. This affects
accountability tracing: compacted history reduces the fidelity of the record of
the agent's reasoning.

**Planning context loss.** If the goal specification and initial decomposition
are in the compacted prefix and are not accurately summarized, the agent may lose
track of its original objective.

## Mitigation strategies

**Checkpoint before compaction.** Before applying compaction, serialize the full
current state to a durable store ([state checkpoint](state-checkpoint.md)). The
checkpoint preserves full fidelity; the context window loses it, but the
checkpoint can be consulted via a read tool call.

**Structured memory pre-write.** Before compaction, extract critical information
from the conversation — current plan, key findings, pending subtasks — and write
it to structured memory ([memory update](memory-update.md)) in a queryable form.
The agent can then retrieve this information via tool calls rather than relying
on the summary.

**Compaction scope minimization.** Compact as little as possible: keep recent
tool results and current planning context intact; compact only early messages
whose content is no longer actively relevant.

## Domain and codomain

As a morphism:

- **Domain:** (conversation history $H$, compaction threshold $k$)
- **Codomain:** (compacted history $H'$ with $|H'| < |H|$)

The operation is not bijective: the codomain contains less information than the
domain. Context compaction is a projection, not an isomorphism.

## Anthropic's implementation

Claude's built-in context compaction (available in Claude Code and the API)
applies a model-generated summary of the earliest portion of the context when
the context exceeds a configurable threshold. The summary is generated by a
separate model pass and inserted as a single system-turn message replacing the
compacted content. The compaction boundary is chosen to preserve the most recent
tool results and the current working context.
