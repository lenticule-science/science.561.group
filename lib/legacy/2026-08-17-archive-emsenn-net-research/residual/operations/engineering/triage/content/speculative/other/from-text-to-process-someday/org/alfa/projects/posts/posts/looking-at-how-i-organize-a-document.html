Looking at How I Organize a Document

Overview

In this document I'm going to explain how I'm organizing my documents these days. By documents, I mean written texts - stories, essays, posts like this one, but also, software. Software might not seem like a document, but I use the literate programming paradigm when I work with a computer, so I write my software as snippets of code inside longer essays.

I'll use my Brutstrap project as an example in this document. It's a relatively simple CSS theme I made, so should be an opportunity to demonstrate a lot of things without its content getting in the way.

Document Project Layout

Each document exists in its own directory on my computer, under the ~/org/projects/ directory. It's called projects because within Org-mode, the name for collections of files published together is a "project," so each document exists as a "document project." Brutstrap's "identifier" is brutstrap-css - that means it's at ~/org/projects/brutstrap-css/.

The root of that directory contains the document in various formats (HTML, plain-text, Markdown, and others), as well as a README.md and a media-package.json.

There's also a subdirectory, src/, which contains an index.org and subsubdirectory, build/ which has in it an index.html and brutstrap.css.

The only file I edit by hand is src/index.org, which is an Org-mode text file. All the other files are created by using Org-mode features on that file.

The Source File

Here's a walkthrough of what's in that file. I'll break it up into the front-matter, introduction, document contents, and supplements.

Front Matter
#+TITLE: Brutstrap
#+AUTHOR: emsenn
#+EXPORT_FILE_NAME: ../brutstrap
#+MACRO: document-type CSS theme
#+HTML_HEAD: <link rel="stylesheet" type="text/css" href="./src/build/brutstrap.css">
{{{document-brief}}}
#+TOC: headlines local 4

Let's look at this line by line:

  • #+TITLE: Brutstrap
    • This sets the document's title. Fairly self-evident. It's used when exporting the document, and also available as a macro: {{{title}}}. I use Org-mode macros a fair amount, they're a way to quickly insert pre-assigned text.
  • #+AUTHOR: emsenn
    • This set's the document's author. Works similar to title.
  • #+EXPORT_FILE_NAME: ../brutstrap
    • This tells Org-mode where to put exported copies of the file. When I tell Org-mode to export ./src/index.org as HTML, it'll export to ./brutstrap.html.
  • #+MACRO: document-type CSS theme
    • This sets the document-type macro, which is used by some other macros to say what sort of document this is - in this example, it's a "CSS theme". Due to how it's used, the document-type is assumed to be a singular noun.
  • #+HTML_HEAD: <link />
    • I cut out the specifics, but this line tells Org-mode: when exporting as an HTML file, link to ./src/build/brutstrap.css as a stylesheet.
  • {{{document-brief}}}

    • This is a macro I've defined in my Org-mode configuration, so it's available in all my Org-mode files. Here's what it's defined as: 

      "{{{title}}}" is a {{{document-type}}} created by {{{author}}}.

      As you can see, it makes use of the macros defined above.

  • #+TOC: headlines local 4
    • This generates a table of contents linking to sections and through three depths of subsections. (1+3=4)

Past here, the document is divided into three sections: an "Introduction," the document contents itself (here, "Brutstrap,") and "Supplements."

Introduction Section

Here's the Introduction: 

* Introduction
  :PROPERTIES:
  :CUSTOM_ID: introduction
  :END:
{{{document-is-draft}}}

In this document I explain...

{{{document-eli}}}

Again, line by line:

  • * Introduction declares the start of what Org-mode calls a subtree, but what normal people would call a "section". How many asterisks lead determine the depth of the section - **** Pumpkin means that "Pumpkin" is a subsubsubsection.
  • :PROPERTIES: declares the start of what Org-mode calls a drawer, which is container for data associated with an element of the document - in this case, the Introduction section.
  • :CUSTOM_ID: declares what the identifier for this section should be, when it's exported. It's a part of the PROPERTIES drawer that was just opened. This is the name that anchor links in an HTML export will point to, for example. If this isn't set, Org-mode will generate an identifier automatically, something like org3507c8b.
  • :END: declares the close of the PROPERTIES drawer.

  • {{{document-is-draft}}} is another macro from my Org-mode configuration: 

    This {{{document-type}}} is a /draft/: it is unfinished and that
should be considered when reading it. Special attention should be paid
to text marked DRAFT, EDIT, or TK.
  • In this document I explain... is an abridged version of the paragraph that's actually there, that explains the broad strokes of what Brutstrap is, how it's meant to look, and so on.

Document Contents

That's it for the "Introduction". The "Brutstrap" section contains the Brutstrap theme itself - explaining how I literately program CSS is beyond the scope of this document. In short, using Babel, I'm able to write short blocks of CSS, and extract them out to ./src/build/brutstrap.css.

Supplements Section

The "Supplements" section contains four subsections:

  • "Example Texts" This section contains two subsections:
    • "Complete Stylesheet," uses Org-mode's inclusion feature to pull in ./src/build/brustrap.css - which is itself extracted from the "Brutstrap" section above.
    • "Demonstration HTML," is a source block that, again using Babel, is written to ./src/build/index.html
  • "Index"

    • This section uses Org-mode's dictionary list feature to present a list of proper terms mentioned in the document. Here's an excerpt from Brutstrap's index: 

      - brutalism :: {{{ref(brutalism)}}}
- Brutstrap :: {{{ref(brutstrap)}}}
- CSS :: {{{ref(css)}}}
- HTML :: {{{ref(html)}}}

      This introduces a new macro: ref. This is, like the others, defined in my Org-mode configuration, and is: {{{define($1)}}} {{{source($1)}}}. define is defined as {{{$1-definition}}} and source is defined as {{{$1-source}}}.. For each term, then, I have two macros, for example for Brutalism I have brutalism-definition and brutalism-source. The definition is simple a sentence defining the term, and the source is... a call to yet another macro: {{{source-link(https://en.wikipedia.org/wiki/Brutalist_architecture)}}}.

      source-link is defined as See [[$1][$1]] which is Org-mode formatting for a link whose anchor text is the URI it directs to.

      So, the final entry for brutalism would be: 

      - Brutalism :: A style exaggerating the pragmatic functionality
               present in modernist design. See
               https://en.wikipedia.org/wiki/Brutalist_architecture.
  • "Media Package"

This section contains a JSON source block which implements a specification I'm developing for what I'm calling a media package, which is a manifest of information about a piece of media content.

Explaining that is beyond the scope of this document, in part because it's in development, so I'll just show the JSON here: 

"brutstrap-css": {
    name: "Brutstrap",
    creator: "emsenn",
    license: "CC0",
    languages: ["en_US","CSS","HTML"],
    versions: {
        "current": {
            "sourcehut": {
                "location": "https://git.sr.ht/~emsenn/brutstrap-css/blob/master/",
                "formats": ["html","md","pdf","tex","txt"]
            }
        }
    }
}

  • "README"

    • The "README" section is used to generate a README.md at the root of the project, as that file is often used by Git forges to generate the project's "homepage" on the forge. It contains three thing:

      • It sets the PROPERTY of EXPORT_FILE_NAME to

      ../README, so that when this section is exported, as say Markdown, it will be exported to ./README.md.

      • Then, it has the line *** {{{title}}} which creates a subsection under itself using the document's title.
      • Then, it includes the "Introduction" section from ./src/index.org - itself - but only the contents, not the title.

    Here's what the section looks like in the source file: 

    *** README
    :PROPERTIES:
    :EXPORT_FILE_NAME: ../README
    :CUSTOM_ID: readme
    :END:
**** {{{title}}}
#+INCLUDE: "./index.org::#introduction" :only-contents t

    And here's what ./README.md looks like - with the paragraphs cut down. 

    # Brutstrap

This CSS theme is a *draft*...

In this document I explain...

This CSS theme was created by...

Conclusion

And so that's it, how I manage a document as a project, exporting it to various different formats, maintaining a README, and so on, by just editing one file for each document, one at ./src/index.org.
