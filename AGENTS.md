# Lenticule Science — agent entry

Use the existing research methods and authoritative knowledge. Do not create a rival encyclopedia, proof record, engine or task queue.

1. **Recover the question and held theory.** Read the actual allocation/issue, current PRs/branches, subject glossary, original field literature and receiving office before another note. Follow the [research skill](lib/agency/skills/research/SKILL.md) and [Group Operational Method](https://github.com/561-group/561-group-services-section/blob/main/content/text/glossary/concepts/method-for-work-in-the-561-group.md). A scientific question belongs to its established field or separately owned specialist section. Consolidate an existing canonical statement before opening a parallel one.
2. **Keep formal claims lawful.** Record hypotheses, counterexamples, original sources, premises, units and actual tested/Lean proof identity. PTGAE is specified at [docs/plain-technical-general-american-english.md](docs/plain-technical-general-american-english.md); label unknown/disputed versus proved. The [service-section custody ontology](services/philosophy-services-section/services/relationality-services-section/services/agency-services-section/data/records/service-section-custody.ttl) distinguishes Science Knowledge from Red Cup implementation, Coesite operating parameters and Group/Public instance data. It is normative, not an automatic compliance certificate.
3. **Use shared Github entry forms.** [Work/Defect issues](.github/ISSUE_TEMPLATE/) must identify a falsifiable receiver, and [PR review](.github/pull_request_template.md) must distinguish research-source receipt from Engineering adoption. These are local GitHub projections of canonical [Coesite computer-operations templates](https://github.com/coesite-operations/computer-operations-services-section/tree/main/data/templates/github). Change generic definitions there, never in one receiver alone.
4. **Do not spend imaginary compute.** Private GitHub-hosted Actions allowance is exhausted and an unverified runner label is not a test run. Preserve original source/test context, review existing CI paths, and use independently received permitted compute through the actual [Continuous Delivery owner](https://github.com/red-cup-engineering/continuous-delivery-services-section). A science commit does not by itself update the house's unreceived superrepo gitlink or a public consumer.
