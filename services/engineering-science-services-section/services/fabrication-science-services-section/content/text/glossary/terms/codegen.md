Codegen is the projection of executable code from an admitted specification or schema. Its output retains the identity of the specification it came from and can be checked for drift against it ([software development work](../../../../../../../../../engineering-services-section/services/computer-engineering-services-section/services/computer-systems-engineering-services-section/services/agent-computer-system-engineering-services-section/apps/agent-organization-engine/content/text/documents/specifications/software-development-work.md), lines 17-21). A schema or specification is identified input to generation, never prose inferred from the output. Where code is generated from an unidentified schema, or a codemod runs without a declared transformation, the tooling is running ahead of its specification (lines 30-34). A generated proposal cannot witness its own deployment (line 110).

Codegen is one of three distinct units of software-change work, beside the [codemod](../../../../../computer-science-services-section/content/text/glossary/terms/codemod.md), which applies a declared semantic transformation to admitted source, and relocation, which changes the ownership or location of a capability and migrates its consumers. The Agent Organization Engine owns all three as agent work. Its `aoe-codegen` command reads identified `*.schema.json` inputs, asks the code-layer JSON Schema renderer for a projection, compares or writes the exact output, and records input and output identities and ordered evidence. A write requires a prior journaled proposal and refuses a changed schema or output, and the nearest declared package must own both the schemas and the output (lines 265-275). The six software-change carrier schemas are the standing example: the schema changes first and the generator's check runs after generation (lines 93-99).

Codegen is the deterministic lane of [generative programming](../../../../../computer-science-services-section/content/text/glossary/terms/generative-programming.md), whose generator takes one specification and projects every artifact from it. Fabrication through a provider is the other lane: the jsnode line derives modules from a source-free module order, derives clause-assay tests before source, and refuses rather than buying a retry of a rejected candidate ([code fabrication from a specification](../../../../services/computer-fabrication-science-services-section/services/computer-code-fabrication-science-services-section/content/text/documents/articles/specifications/2026-09-04-code-fabrication-from-a-specification.md)). What fraction of admitted work orders a deterministic generator can derive without purchasing inference is an open question ([deterministic derivation lane coverage](../../documents/articles/research-articles/questions/deterministic-derivation-lane-coverage.md)).

The Leader's position on aligned code is that it is "derived from research papers I can read, specs I can read, SAS, HLD, LLD: etc.; fixable via codemod, codegen, actual requirements being handled by requirement-management-operation-services-section" ([recovery index](../../documents/articles/notes/2026/10/09/2026-10-09-note-recovering-the-fabrication-research.md), line 61). In that chain codegen is the step that projects code from the specification, and the specification is a [system architecture specification](../../../../../systems-engineering-science-services-section/content/text/glossary/terms/system-architecture-specification.md), [high-level design](../../../../../systems-engineering-science-services-section/content/text/glossary/terms/high-level-design.md) and [low-level design](../../../../../systems-engineering-science-services-section/content/text/glossary/terms/low-level-design.md) answering to a [software requirements specification](../../../../../systems-engineering-science-services-section/content/text/glossary/terms/software-requirements-specification.md).
