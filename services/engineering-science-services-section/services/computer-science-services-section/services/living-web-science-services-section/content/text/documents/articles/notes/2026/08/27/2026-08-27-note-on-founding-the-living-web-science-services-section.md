## Standing

This is the constitution-style founding record for
`living-web-science-services-section`. The section itself was seated on
2026-08-26 in commit `8a4541f278cb22fb9eb89cd933f9fe15e5160be4` ("found
website-server-services-section; place VICTOR 0.1.0 and the Hugo lineage
under it"), whose body states plainly: "Also founds
living-web-science-services-section as the 561 Group's own Living Web
initiative." That commit, and the section's own README and its 2026-08-26
founding note (`2026-08-26-note-on-the-living-web-initiative.md`) and
frontier-and-engineering-program note, are this record's primary corpus
evidence. This note adds the explicit rationale and the ruling that grounds
the section's existence, which the prior two notes assumed rather than
stated.

## The ruling

emsenn ruled, in a Codex session on 2026-08-26/27 (the "Webby Wednesday"
session — 2026-08-26 fell on a Wednesday), that **Living Web is the 561
Group's own invented discipline**, not a borrowed or externally-named field.
It needs a science service of its own because it names a real, distinct
object of study: the web read as a continuously revised, never-finished
system of living standards, protocols, and practices — not a fixed
specification to implement once, but a moving target whose conformance is a
process property, checked continuously, rather than a badge earned at
launch.

The ruling is explicit that this is a coinage, not a discovery of an
existing body: the W3C has no initiative by this name (confirmed by survey
in the 2026-08-26 founding note), and the section is honest about that
distinction wherever it states its own scope. The real referents it
studies — the WHATWG HTML Living Standard, the W3C Recommendation track
(WCAG, ARIA in HTML, Webmention), the CSS Baseline process, IndieWeb
building blocks (microformats2, Micropub, WebSub), ActivityPub federation,
syndication formats, and well-known-URI/sitemap discovery — are real and
external; "Living Web" as the name binding them into one object of study is
the Group's own.

## Applications, not the science itself

The ruling seats the web engineering apps as the discipline's applications,
not as the discipline:

- **VICTOR** (Voxelized Information Catalog Topos Orienting Relations), the
  walking-skeleton website server at
  `engineering-services-section/services/computer-engineering-services-section/services/computer-systems-engineering-services-section/services/computer-systems-publishing-engineering-services-section/apps/victor/`,
  is named directly in the section's README as "the initiative's engineering
  realization" — the build system that checks conformance continuously
  rather than at launch.
- **TUFTE**, the Tiling User Frontend Topology Engine at
  `engineering-services-section/services/computer-engineering-services-section/services/computer-systems-engineering-services-section/services/web-services-section/services/web-interface-services-section/services/web-tufte-gui-services-section/`,
  is the interface layout contract this section's applications compose
  against; the README names it alongside VICTOR as responsible for product
  decisions and implementation.

This section owns the study — tracking standards as they move, recording
positions, grading the field — while VICTOR and TUFTE own the build and the
interface. The science does not own the applications' claims, matching the
same general-to-specific discipline the rest of the science forest follows.

## Seat

`living-web-science-services-section` sits under
`engineering-science-services-section` › `computer-science-services-section`
in the science forest, paired with the web engineering apps under
`engineering-services-section` › `computer-engineering-services-section`.
This is the same science/engineering split the rest of the corpus draws:
theory in science, code in engineering, meeting at named application
seams.
