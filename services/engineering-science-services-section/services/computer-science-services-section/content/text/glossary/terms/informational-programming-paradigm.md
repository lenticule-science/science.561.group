The informational programming paradigm is the programming discipline the org's admitted mathematics forces once a unit of behavior is required to be a typed, addressable term rather than an object's method or a host-language closure. It admits exactly two primitives — a Mark, an atomic surface string built from nothing, and an Utterance, the pairing of a token-mark with a claim-mark — and derives every further shape a program needs, including a type, a term, a reduction, and a witness row, rather than declaring any of them as ontological givens.

This contrasts with the two paradigms it is named against. Object-oriented programming admits object identity plus mutable state as an unproved runtime given, and recognizes a value's type by polymorphism scattered across every subclass's own override, so recognition is distributed rather than centralized. Functional programming admits a host language's algebraic data types and opaque closures as primitive, then recognizes a value's type through typeclass or trait instances declared independently per type-and-operation pair. The informational programming paradigm instead recognizes what a piece of data is exactly once, at the apex of a cone of representations — the Curry-Howard-Lambek and RMN term language's own typing judgment — with every other representation, JSON, EAVT rows, prose, or Lean, admitted as one translation leg reaching that apex.

The engineering consequence: a new representation costs one new apex-reaching translation leg, never a new per-representation recognizer, so a hand-grown array of independently authored matching predicates dispatched by lookup is the paradigm's named anti-pattern regardless of what its fields are called.
