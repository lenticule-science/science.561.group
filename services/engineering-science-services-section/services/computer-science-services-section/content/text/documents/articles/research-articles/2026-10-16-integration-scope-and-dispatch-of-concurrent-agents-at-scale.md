# Integration, Scope and Dispatch of Concurrent Agents at Scale

The organizations that run very large engineering efforts do not keep the integration pointer, the contributor's scope, or the landing step in anybody's hands but a mechanism's. Google has no internal version pins at all; Chromium, Fuchsia, Nix and Guix keep pins but let one automated writer advance each pointer behind a test gate; Zuul, Tide, bors and Uber's SubmitQueue make a queue the only thing that can write `main`; the Linux kernel lets only a parent pull from a child, on a schedule, through an integration tree. Contributor scope is computed from a path-to-owner map at the point of change (OWNERS files, MAINTAINERS, the LPMud master object), not described to the contributor. The vendor and in-house agent deployments that publish results (GitHub, Anthropic, Spotify, Stripe, Uber, Google, Airbnb) share one shape: one task, one repository, one isolated environment, one branch, one pull request, a deterministic verifier before the pull request opens, capped retries, an agent identity distinct from the human's, and a human merge. The failure signature the Leader describes (run, crash, trace, patch the symptom, repeat) has measurable correlates (repetition, context overflow, self-repair that adds little without new diagnostic signal) and a documented remedy: an external pass/fail check, a retry cap and a fresh start. Evidence on deriving architecture from requirements when the principal cannot weigh in is thinner: standards and design methods (Jackson and Zave, SEI scenarios, ADRs, reflexion models, AWS formal specifications) say what to record and check, not how to derive, and category-theoretic derivation is still prototype-grade. Inferred: the 561 Group's problems are not an exotic condition; they are the condition these organizations designed their mechanisms against, and the Group already has the mechanism catalog (MetroPlat duties, offices, worktrees, gated landing) but has not put it in the path of work.

Epistemic labels used below: `Measured:` quantified by a source; `Observed:` directly read; `Inferred:` a conclusion drawn here; `Disputed:` sources disagree; `Unknown:` not established. Where a figure is secondary (a mirror, a summary, a snippet) or unverified, the text says so. Group figures are "measured in the Group's corpus, 2026-10-16".

## 1. Problem statement: the Group's work is mostly pointer movement by unscoped, unidentified sessions

The 561 Group is a one-person, for-profit conglomerate whose engineering is done almost entirely by AI agents. The Leader states intent and market goals and cannot weigh in on technical architecture, so the Group intends to derive specification, architecture and design from a topology of requirements produced by owning sections. The Group's design is one analogy: Haier's self-managing micro-enterprises (Rendanheyi) run on a platform (MetroPlat, after COSMOPlat) that runs on a driver (FeltOS, after FluffOS), instances federate (ActivityPub++, the Semioverse), and LAGOON deploys instances. Agents are to work through MetroPlat, not beside it.

Measured in the Group's corpus, 2026-10-16:

- Scale. 788 GitHub repositories across nine owners. About 2,290 pull requests in about six days (735 in 561-group, 1,553 in red-cup-engineering). Branch prefixes `codex/`, `claude/`, `chatgpt/`, `dot/` and `hai-xudi/` mark the producers. The corpus checkout has about 92,000 tracked files.
- Integration load. Of the last 300 commits on `561-group/bare-cedar-fog` `main` (2026-10-13 to 2026-10-16), about 205 (68%) are integration, pin, copy-moving or delivery plumbing, about 76 (25%) change only method and records, and about 19 (6%) change product code or content. In computer-engineering-services-section, 56 of the last 100 non-merge commits change only gitlinks. Two near-identical "Compose canonical standalone service repositories" commits were made on different parents, each deleting about 76,809 lines.
- Pin mechanisms in simultaneous use. Git submodule gitlinks (26 at the root, 76 more nested), 53 exact npm specifiers against registry.561.group, 89 `workspace:*` specifiers whose workspace file and lockfile were deleted, Guix channel commit pins in two `channels.scm` files, and 43 JSON records carrying 40-character commit hashes. computer-engineering-services-section exists at three commits at once (checkout, root pin, GitHub `main`). An automated pin-advance engine exists but its callers were removed.
- Tree shape. None of the 26 root submodules is mounted by its immediate parent. 537 non-legacy plain `*-services-section` directories are tracked in the root. Parallel trees share names.
- Identity. Every sampled GitHub commit is authored `emsenn <emsenn@emsenn.net>` and unsigned, whichever agent produced it. Locally, 175 of the last 300 commits carry the name `continuous-delivery-services-section` although interactive sessions made them.
- Constraint. The laptop's Claude Code project MCP config is empty and user settings use `bypassPermissions`. The one effective mechanism in the path of agent actions is a host-resource PreToolUse hook. The independent-receiver requirement (bare-cedar-fog#362) and the pre-push merge-queue gate (bare-cedar-fog#641) were removed, so producers test and merge their own work.
- Existing machinery. MetroPlat has duties with their own git worktrees, scoped workspace verbs, an independent receiver and a gated integrate step, but no observed session enters it.

Inferred: the Group's diagnosis is four absences. No single automated writer owns the integration step, so every session advances pins by hand and sometimes twice. Scope is not computed, because the section tree is not a tree. Identity is shared, so history cannot say who did what. No declared, hermetic integration build answers "does the set work", so sessions answer it by running things.

The research questions are therefore: (a) how do the largest organizations integrate many components and advance internal pins; (b) how do they give each of many concurrent contributors, including agents, a bounded scope, an identity and an authority, and make the sanctioned path the only path; (c) how are agent work dispatched, sandboxed, verified and landed; (d) what are the failure modes of agent loops and multi-agent coordination; (e) how is architecture derived from requirements when the principal cannot weigh in on architecture.

## 2(a). Integrating many repositories: remove the pin, or give each pin exactly one automated writer

### Google, Meta and Microsoft: one repository, so no internal pins

Observed: Google keeps authoritative source in one repository and branch, develops at trunk, and disables incomplete features at runtime [winters2020vc]. The One-Version Rule states that developers must never have a choice of which version of a component to depend on [winters2020vc]. Measured: for January 2015 Google reported 1 billion files, 9 million source files, 2 billion lines, 35 million commits and 86 TB, with about 40,000 commits per workday, 16,000 by humans and 24,000 by automated systems (60% automated), and more than 25,000 developers [potvin2016]. These figures are secondary (read from mirrors quoting the article; the CACM page returned 403). The SWE book states about 50,000 engineers and 60,000 to 70,000 commits per workday in 2020 [winters2020vc]. Inferred: the two commit rates differ by date, not by contradiction.

Measured: Microsoft's Windows repository held about 3.5 million files, about 300 GB, about 4,000 engineers and 1,760 daily lab builds across 440 branches in 2017, consolidated from more than 40 Source Depot depots, with VFS for Git materializing files lazily [harry2017]. Disputed: one secondary article gives about 270 GB. Observed: Meta states that public source control could not handle its repository, that splitting it would give up the benefits of a monorepo, and that it built Sapling and a server to keep one repository [meta2022]. In 2014 Meta rejected the idea that "the scaling constraints of our source control system should dictate our code structure" and said splitting would make large atomic refactorings more difficult [meta2014]. Unknown: how Meta avoids cross-repository pins beyond "one repo" (no source retrieved).

The costs are named. Observed: Google lists tooling investment, codebase complexity (unnecessary dependencies, hard code discovery) and code-health effort [potvin2016]. Observed: a survey-based study reports automatic updating of dependents during API migrations as an advantage and toolchain freedom, access control and stability as multi-repository advantages (secondary summary only; survey counts not retrieved) [jaspan2018].

### Where pins survive, the dependency graph is the hard part

Observed: the Google book calls SemVer "a lossy estimate" with two failure modes, overconstraint (a major bump blocks upgrades although the changed API is unused) and overpromise (non-API changes break users), and notes that SAT-solving SemVer constraints is NP-complete [winters2020dep]. Hyrum's Law: with enough users every observable behavior will be depended on [winters2020dep]. Diamond dependencies have no general consumer-side resolution [winters2020dep]. "Live at Head" (depend on the current version of everything; downstream CI catches breaks; providers carry migration responsibility) is called "largely unproven at scale" by the same chapter [winters2020dep]. Third-party code is the exception where policy fails: gflags, released externally around 2006, was left to rot and later divergence delayed optimization work worth thousands of CPUs [winters2020dep]. The authors say submodules, Bazel external dependencies and CMake subprojects only approximate One-Version, and expect "virtual monorepos" with "version numbers are timestamps" [winters2020vc].

### Chromium, Fuchsia and Android: multi-repository, with pins written by bots

Observed: Chromium's root `DEPS` holds URLs and hashes of external dependencies; `gclient setdep` and `roll-dep` pin a hash and update `DEPS` and the gitlink; some projects such as Skia are autorolled; submodule paths need OWNERS entries; changes go upstream first and are then rolled [chromiumdeps]. Observed (search summary): a roll that causes failures is handled by pressing stop on the roller dashboard, reverting the roll, and assigning to the sheriff of the rolled project [skiaroll]. Observed: Fuchsia's `integration` repository holds global integration manifests; roll commits are authored by a `global-integration-roller` account and committed by Copybara; "Currently all changes must be made by a Google employee" and edits happen in an internal copy that infrastructure mirrors [fuchsia2024]. Unknown: how the Fuchsia roller decides to advance (gating and frequency are not in any retrieved page). Observed: Android's `repo` tool pins nothing by default; manifest revisions are branch names, and SHA-1 revisions are "not extensively tested" [androidrepo].

Inferred: in these systems the writer of an integration pointer is a roller identity, the gate is the roller's own change passing the try jobs, and the owner of breakage is a named sheriff with revert as default response.

### Gating queues make the pipeline, not the human, the writer of main

Observed: Zuul's dependent pipelines test each queued change merged on top of the ones ahead of it, drop a failing change and re-test those behind; `Depends-On:` links cross-repository changes, including across Gerrit and GitHub [zuul]. Tide retests against the latest base, prefers batches, falls back to single changes after a batch failure [tide]. GitHub's merge queue builds a temporary `merge_group` branch from the target plus the changes ahead [githubmq]. The "not rocket science" rule is quoted as "automatically maintain a repository of code that always passes all the tests"; bors tests a temporary merge and fast-forwards only on success [graphite2024]. Jane Street reports full builds of two hours or more, changes that waited 24 hours, and a drop from hundreds to about 30 to 40 integration requests per week after adopting feature branches [janestreet].

Measured (secondary, via Colyer's summary of Ananthanarayanan et al., EuroSys 2019): before Uber's SubmitQueue, iOS mainline was green 52% of the time in one week; the chance of a problem was about 40% with 16 concurrent potentially conflicting changes; a serial queue at 1,000 changes per day and 30 minutes per build would have a turnaround over 20 days [colyer2019]. Measured (primary preprint): a 2024 follow-up over 21 weeks reduced builds-to-changes ratios (Go 3.39 to 1.85, iOS 4.93 to 2.57, Android 5.43 to 1.96) and about 53% of CI resource, 44% of CPU and 37% of P95 wait [uber2025]. Google's contrasting choice is to test less often. Measured: TAP integrates and tests more than 13,000 projects daily, with 800,000 builds and 150 million test runs; "a code commit every second on the average" makes per-commit testing uneconomic, so it cuts "milestones" about every 45 minutes at peak, with up to 4.2 million tests and infrastructure delays up to 9 hours [memon2017]. Measured: of 5.5 million test targets in a month, 63,000 ever failed; 1.23% of executions found a real breakage; a file changed many times by different people is "almost 100% likely to cause a failure" [memon2017].

### Linux, Nix and Guix: one place decides the coherent set

Observed: the kernel's chain of trees "rarely exceeds two or three links"; changes merged in the two-week window should have appeared in linux-next first [kernelprocess]. Measured: 6.19 had 14,344 non-merge changesets and 2,141 developers [corbet2026]. MAINTAINERS routes each path to a maintainer, mailing list and tree, and tells contributors to "look for the most precise areas first" [kernelmaint]. Observed: pulling a signed tag makes git verify it and record the result [kernelpgp]. Disputed: the current linux-next maintainer is named differently in two retrieved kernel pages (Rothwell, Brown); not resolved, and not load-bearing here.

Observed: a Nixpkgs channel "updates only after its tests pass on Hydra" [nixpkgs]; the advance rule (a fully built jobset with the tested job green; a server cron job polls) comes from community sources only [nixwiki]. Observed: in Guix a channel is a Git repository of package modules; `guix describe -f channels` captures exact commits and `guix time-machine -C channels.scm` re-runs that exact Guix, "pinning the entire package set"; packages refer to each other as Scheme variables, never versions; each fetched commit must be signed by a key in the `.guix-authorizations` of its parent commits [guixmanual]. Inferred: Guix achieves the One-Version Rule through a single pinned commit with no per-package pins; its gate for advancing is signature and ancestry, while tests are a separate build-farm job.

### Submodules specifically

Observed: Pro Git documents detached HEAD after `git submodule update` (commits made there "will quite possibly be lost"), parents pushed without their submodule commits leaving others "in trouble", and branch-switching hazards [progit]. Unknown: no peer-reviewed measurement of submodule pin-bump overhead, and no external benchmark for the Group's 68% figure, was found. Unknown: no source covers nesting deeper than one level.

### Who may change a pin

| Organization | Who writes the integration pointer | Gate | Owner of breakage |
|---|---|---|---|
| Google, internal | nobody (no pins) | presubmit, TAP | provider, who migrates dependents [winters2020dep] |
| Google, mechanical cross-cutting change | tool-sharded changes (Rosie) under an authorized proposal | per-shard test-mail-submit | infrastructure team that owns the large-scale change [winters2020lsc] |
| Chromium, Fuchsia | roller account | roller's change passes try jobs (details unknown for Fuchsia) | sheriff; revert [chromiumdeps][skiaroll][fuchsia2024] |
| Zuul, Tide, SubmitQueue, bors | the queue | tests on main plus changes ahead | author of the failed change [zuul][tide][uber2025] |
| Nixpkgs | channel script | Hydra jobset built, tested job green | maintainers [nixpkgs][nixwiki] |
| Guix | any key in the parent's authorizations file | signature and ancestry, checked by the client | authorized developer [guixmanual] |
| Linux | the parent maintainer, by pull | review plus linux-next | subsystem maintainer [kernelprocess][kernelmaint] |

Observed: Google's large-scale changes are generated by tools, sharded by project boundary and ownership, capped in outstanding shards, run at lower priority, and authorized by a proposal and an oversight committee of about a dozen; the rule of thumb is that more than 500 edits favors tooling. Measured: the `scoped_ptr` migration had more than 500,000 references and peaked at more than 700 independent changes and 15,000 files per day [winters2020lsc]. Inferred: mechanical cross-cutting change is a governed activity with one master change and generated shards; this is also how Google avoids two agents doing the same migration twice.

Failure modes recorded in the evidence: third-party packages that bundle their own pins, abandoned forks, flaky tests slowing shards, queue throughput limits, roll breakage landing on a sheriff, and a signed-channel regime that fails on a single unsigned commit [winters2020dep][winters2020lsc][guixmanual].

## 2(b). Scope, identity and authority: ownership is computed at the point of change, and the actor never holds ambient authority

### Ownership is a gate, and it predicts quality

Measured: on Windows Vista and Windows 7, the number of low-expertise contributors and the share of changes made by the top owner correlate with pre-release faults and post-release failures (correlational; ESEC/FSE 2011 Test of Time award) [bird2011]. Measured (abstract-level): a replication on four Microsoft products confirmed the correlation; directory-level bug classification reached median precision 0.76 and recall 0.60 [greiler2015]. Observed: Chromium requires owner approval for every patch, with OWNERS files recursive and more specific owners preferred [chromiumreview].

Observed: GitHub rulesets layer, with the strictest version of each rule winning, and can govern commit metadata including author email; the bypass list can include roles, teams and Apps, in "always" or "for pull requests only" mode [githubrulesets]. Inferred: a shared human identity with admin rights is on the bypass list in effect, so it nullifies the gate. Inferred: ownership gates work at Google and Chromium because they are checks in the only submit path; the analogue for agents is that the landing path, not the agent's cooperation, must compute the owner of each path.

### Scope follows the organization's structure, or drifts

Measured: MacCormack et al. found that in every matched pair the product from the loosely coupled organization was more modular, by up to a factor of eight in potential change propagation [maccormack2012]. Measured: Cataldo and Herbsleb found that gaps between coordination requirements and actual coordination significantly increased failures on two large projects [cataldo2013]. Conway: organizations produce designs that copy their communication structures [conway1968]. Inferred: the section graph that defines agent scope must be the same graph the code is mounted in, or scope will diverge from the organization.

Haier's Rendanheyi is the Group's stated analogue. Observed (secondary only; the HBR article returned a teaser): about 4,000 microenterprises of 10 to 15 people, two management layers, market-facing units that choose among node units under annual agreements, and customer-paid salary [hamel2018][rendansec]. Unknown: no quantitative outcome data and no statement of how contract scope is technically enforced were retrieved.

### Authority without ambient authority

Observed: Hardy's confused deputy is a compiler that held authority from two sources (its own system directory and the user's request) and could not tell which a request invoked; the fix is to pass authority together with the designation, as a capability [hardy1988]. Observed: the object-capability model and Capsicum remove ambient authority so a process can use only what it holds references to [miller2006][capsicum]. Inferred: a shell session that holds the human's credentials is Hardy's compiler, and a hook that denies some shell commands is a blacklist over ambient authority; the capability alternative is not to hold the credential in the session. The phrase "ambient authority" was not found in Hardy's text; it comes from the later literature.

LPMud drivers implement this inside the runtime. Observed: the FluffOS master object decides, on every call, `valid_read`, `valid_write`, including reads performed by `#include` during compilation, `valid_override` (so `efun::` cannot bypass a wrapper), `valid_shadow` and `creator_file` (which assigns an object's uid from where its code lives) [fluffosmaster]. Observed: the Amylaar/LDMud master returns the full pathname to operate on, so it can rewrite as well as allow or deny [ldmudmaster]. Observed: domain and author accounting follow a mudlib-defined path-to-owner mapping [mudosdomain]. Observed: in LambdaMOO a verb runs with its owner's permissions and only a wizard can set the wizard and programmer bits [lambdamoo]. Inferred: path to owner is the core primitive; the designers also closed their own bypass routes (`efun::`, shadowing), parallel to the route "the agent can shell out". Unknown: real mudlib code for domain and creator-directory policy was not retrieved, so the Discworld hierarchy (creators, lords, high lords) is attested only by a 1990s newsletter about MUDs in general.

### Identity

Observed: GitHub's Copilot agent commits are authored by Copilot with the requester as co-author and are signed; the requester cannot approve the resulting pull request, and the agent cannot mark it ready, approve or merge [copilotrisk]. Observed: Uber gives agents SPIFFE/SPIRE workload identity checked against an Agent Registry and issues single-hop, audience-bound, minutes-lived tokens through an RFC 8693 token exchange that carries a user to agent to sub-agent chain; policy is enforced at an MCP gateway; STS P99 is under 40 ms [uberid]. Observed: gitsign signs commits with ephemeral Fulcio certificates and records them in Rekor, so verification outlives the certificate [gitsign]. Observed: a GitHub App installation token expires after one hour and can be narrowed to listed repositories and permissions; fine-grained personal access tokens are limited to one owner and chosen repositories, with possibly infinite lifetime [githubapp]. Observed: SLSA Build L3 requires provenance that tenants cannot forge, with signing secrets kept from user-defined build steps [slsa]. Unknown: no measured study of shared-identity harm was found.

### Mandatory at the seam, optional inside

Observed: Spotify's Golden Path is "opinionated and supported" and may be left, "but you will not have the same support" [spotifygolden]. Observed (secondary description of a slide deck): Netflix's paved road is not mandatory [netflixroad]. Observed: the Amazon mandate, as reported by Yegge (a leaked post, not an Amazon document), forbids any inter-team communication except through service interfaces and states that anyone who does not comply "will be fired" [yegge2011]. Measured: DORA 2024 (over 39,000 respondents) found internal platforms improve individual, team and organizational performance but can reduce change stability and throughput, and recommends developer independence [dora2024]. Measured (secondary, unverified against the PDF): requiring exclusive platform use for all lifecycle tasks was associated with an 8% throughput drop and 14% stability drop [dora2024sec]. Inferred: the supported paths that people choose are cheaper than the alternative; the mandated paths are at the boundary (Amazon's interfaces). DORA's finding concerns human developers; transfer to agent sessions is untested.

### Mechanism beats instruction

Measured: with unauthorized tools visible, three models chose them in 48 to 68% of adversarial scenarios even when told not to; per-tool allowlists in the prompt reduced violations to between 4.0% and 37.0% but never to zero; a proxy that removes tools from the registry at discovery gave 0% by construction (single-author preprint; adversarial scenarios) [uppala2026]. Measured: a runtime authority guard cut attack success for Sonnet 4.6 from 36.3% to 5.5% on one benchmark and kept 76.0% of benign utility on another, while prompt-only policy "helps only modestly" [airguard2026]. Measured: repository context files such as AGENTS.md are followed well but generally do not improve task success and raise inference cost by over 20% on average [gloaguen2026]. Observed: Claude Code hooks give "deterministic control"; exit code 2 blocks a PreToolUse call; the documentation says to use the permission system, not a hook, to enforce a hard allow or deny [claudehooks]. Unknown: whether PreToolUse deny holds under `bypassPermissions` (only third-party blog claims seen; the official page was only partly read). Inferred: instructions steer and mechanisms bound; the Group's conflict between CLAUDE.md and AGENTS.md is a symptom of relying on the first.

## 2(c). Dispatching, sandboxing, verifying and landing agent work: one task, one repository, one sandbox, one pull request, one verifier, a human or independent merge

### Vendor platforms converge

Observed: GitHub Copilot's cloud agent runs in an ephemeral environment, works on one branch at a time, limits changes to the repository named at task start, pushes only to a `copilot/` branch, has a 59-minute session cap that "cannot be extended or bypassed", runs Actions workflows only after a write-access user approves, and sits behind a firewall that covers processes started through its Bash tool but not MCP servers or setup steps [copilotrisk]. Observed: Codex cloud blocks internet access in the agent phase by default, with a domain allowlist and HTTP-method limits, and removes secrets before the agent phase; the page is labeled legacy and undated [codexenv]. Observed: Claude Code's sandbox isolates the filesystem to the working directory and routes network through a proxy outside the sandbox; on the web, git credentials stay outside and a proxy validates pushes to the configured branch and attaches the real token; Anthropic reports 84% fewer permission prompts (self-reported) [claudesandbox].

### In-house deployments with published numbers

Observed: Spotify's Honk jobs run in containers that open pull requests; prompts are version controlled, state preconditions and when not to act, and define a verifiable end state; the loop is capped at 10 turns per session and 3 session retries; agent tools are minimal (a verify tool, restricted git, allowlisted bash); pushing and prompt authoring are done by infrastructure [spotify1][spotify2][spotify3]. Measured: more than 1,500 agent-generated pull requests merged and 60 to 90% time saving on migrations (self-reported) [spotify1]. Observed: Spotify names three failure modes (no pull request; fails CI; passes CI but is functionally wrong, "the worst"), runs independent deterministic verifiers and a stop hook, and an LLM judge that "vetoes about a quarter" of thousands of sessions, with the agent self-correcting about half the time; the most common veto is going beyond the prompt [spotify3]. Disputed: a secondary report (InfoQ, March 2026) says the judge was later removed as too rigid; Spotify's own statement was not retrieved.

Measured: Stripe reports more than 1,000 minion-produced pull requests merged per week on 2026-02-09 and more than 1,300 on 2026-02-19; each run uses a pre-warmed devbox isolated from production and the internet; the loop interleaves agent steps with deterministic git, lint and test steps; CI is capped at two rounds; every pull request is human-reviewed; no denominator is published [stripe1][stripe2]. Measured: Uber reports more than 70% of pull requests attributed to local or cloud agents (2026-08-27), 1,000+ MCP servers behind one gateway, and spend tiers with alerts at 50, 80 and 100% of expected spend [uberfactory]. Disputed: a secondary source gives 11% for Uber's Minion agent; the primary post's 70% covers a different scope.

Measured (self-reported experience report): Google's code migrations achieved 80% fully AI-authored modifications for an Ads int32 to int64 migration and about 87% of AI-generated code committed unchanged for a JUnit3 to JUnit4 migration (5,359 files, over 149,000 lines, three months), with reviewer speed the bottleneck; changes were sharded to code owners [nikolov2025]. Measured: Airbnb migrated about 3,500 test files in six weeks against a manual estimate of 1.5 years, reaching 75% in four hours, 97% after four days of sample-tune-sweep, and a long tail needing 50 to 100 retries [airbnb2025]. Observed: AWS claims 4,500 developer-years saved by Amazon Q Java upgrades; this is a vendor estimate [amazonq].

### Verification is the unattended-run requirement

Observed: Anthropic's best-practices page says a way for the agent to verify its own work "is the difference between a session you watch and one you walk away from", and lists escalating gates (in-prompt check, a separately evaluated goal condition, a Stop hook that blocks turn end until a script passes, a fresh-context verification subagent) [claudebest]. Inferred: every deployment above caps turns, retries, CI rounds or session minutes; an uncapped retry loop is a departure from published practice.

### Landing

Observed: GitHub forbids the requester from approving the agent's pull request; Stripe, Spotify and Google keep human review of every change; Spotify's agent has restricted git and pushing is done by infrastructure [copilotrisk][stripe2][spotify3]. Measured: Google found reviewer speed was the migration bottleneck [nikolov2025]. Measured (AIDev, secondary datasets): agent-pull-request acceptance in popular repositories ranged from 38.2% (Copilot) to 65.3% (Codex) against 76.8% for humans (stars threshold above 500, 7,122 pull requests); another study with a 100-star threshold gives 85.8% for Codex and 82.6% for humans [li2025aidev][nakashima2026]. Disputed: thresholds differ between papers, so quote the paper and the threshold together. Measured: documentation, CI and build tasks merged most, performance and bug-fix tasks least; rejection causes included duplicate pull requests, unwanted features and misalignment [ehsani2026].

### Productivity evidence is weak and warns against self-report

Measured: METR's randomized trial of 16 experienced developers and 246 tasks found that allowing AI increased completion time by 19%, while the developers expected a 24% reduction and later believed they were 20% faster [becker2025]. Observed: METR's 2026 follow-up (57 developers, 143 repositories, 800+ tasks; -18% for returning and -4% for new developers) was called by METR itself "an unreliable signal" because 30 to 50% of developers withheld tasks they did not want to do without AI [metr2026]. Measured: DORA 2025 (nearly 5,000 respondents) associates AI adoption with higher throughput and lower delivery stability, attributed to higher change volume overwhelming weak downstream controls such as testing, version control and fast feedback; 90% of organizations had an internal platform [dora2025]. Observed: Anthropic reports more than 80% of merged code authored by Claude (self-report, conservative per the authors, with attribution gaps and no defect or rollback data) [anthropicinst]; the same company reports staff self-assessed productivity +50% and that most employees can fully delegate only 0 to 20% of their work [anthropicwork]. Inferred: the Group's own sense that agents are productive is not evidence; the Group's pull-request volume is not an outcome.

## 2(d). Failure modes: unverified retry loops, context decay, and uncoordinated parallel writers

### The probe-patch-retry loop has measurable correlates

Measured: self-repair gains are often modest once repair cost is counted, vary across subsets, and are "bottlenecked by the model's ability to provide feedback on its own code"; stronger-model or human feedback gives larger gains [olausson2024]. Measured: without external feedback, models struggle to self-correct reasoning and sometimes get worse (reasoning tasks, not execution feedback) [huang2024]. Measured: self-debug with execution feedback and code explanation improves results by up to 12% on some benchmarks [chen2023]. Inferred: execution feedback is an external signal and helps; a loop that only re-runs and patches the printed symptom supplies little new diagnostic information, and Airbnb's long tail of 50 to 100 retries on hard files shows the cost of such a tail even in a successful campaign [airbnb2025].

Measured: in SWE-agent trajectories, "repetitive sequences of length 10 correspond to an 89% failure probability"; more than 25% of one 32B model's trajectories contained such a sequence against under 4% for Claude 3.7 Sonnet (correlation, not intervention; the model-specificity matters) [sweSmith]. Measured: on SWE-Bench Pro, the table shows "stuck in loop" for 33.9% of Sonnet 4's not-submitted outcomes, against 3.4% for Opus 4.1 and 1.0% for GPT-5 (the paper's prose and tables disagree in places) [swebenchpro]. Measured: across 9,374 trajectories, the apparent link between trajectory length and failure reverses once task difficulty is controlled, while gathering context before editing and validating are associated with success; the LLM drives outcomes more than the framework [mehtiyev2026]. Observed: Anthropic lists "correcting over and over" (clear and rewrite after two failed corrections), "kitchen sink session", "infinite exploration" and a trust-then-verify gap as failure patterns, and instructs "address root causes, not symptoms" [claudebest]. Unknown: no controlled study of the "patch the symptom" behavior in real sessions exists in the retrieved evidence, and no intervention study isolates loop-breaking.

### Interface and scaffold design move results independently of the model

Measured (2024, superseded scores): SWE-agent's purpose-built agent-computer interface far exceeded earlier non-interactive models [sweagent]; Agentless, a fixed localize-repair-validate pipeline in which the model does not choose actions, reached 32.00% on SWE-bench Lite at $0.70 per issue, the best open-source result at the time, and manual review found flawed benchmark instances [agentless]. Inferred: the qualitative lesson (narrow, scope-aware commands and a fixed pipeline beat raw shell) survives; the numbers do not.

### Large unfamiliar codebases are where agents do worst

Measured: SWE-Bench Pro's commercial (private-codebase) set, 276 problems, tops out at 17.8% (Opus 4.1) against 43.6% on the public set (Sonnet 4.5); newer models were not retrieved [swebenchpro]. Inferred: no retrieved benchmark covers a 788-repository, nested-submodule organization, so no quantified expectation exists for the Group's setting.

### Multi-agent coordination

Measured: the MAST taxonomy of 14 failure modes in three categories (system design, inter-agent misalignment, task verification) comes from 1,600+ annotated traces across 7 frameworks, with inter-annotator kappa 0.88 (preprint; per-category rates not retrieved) [cemri2025]. Observed: Cognition argues that parallel subagents carry conflicting implicit decisions and recommends a single-threaded agent that shares full traces [cognition2025]. Measured: Anthropic's read-heavy research system beat a single agent by 90.2% on an internal evaluation at about 15 times the tokens, and Anthropic says most coding tasks have fewer parallelizable subtasks and that domains with shared context fit poorly; its listed failures include vague delegation causing duplicated work [anthropicma]. Inferred: the two are reconcilable. Isolation per task, with independent repositories and pull requests, is practiced by Stripe, Spotify and GitHub; shared-state parallel writing to one codebase is the hazard.

Measured (AIDev-pop, 33,596 pull requests, 2,807 repositories): 40.2% of repositories have agent pull-request pairs with exact temporal overlap, covering 79.4% of agent pull requests in such pairs; in a merge replay of 747 pairs, textual conflicts occurred in 41.7% of cross-agent pairs and 19.8% of same-agent pairs, and only 0.5% of co-active pairs were cross-agent [xu2026]. A circulating figure that attributes 19.8% to "identical instances" is the same-agent rate; the 40.2% is a share of repositories, not a conflict rate. Measured: the STALE benchmark's "97%" is 105 of 108 constructed runs in which a consumer passed alone and failed after the helper's interface change; in 834 runs on mined Django pairs of reviewed, merged pull requests only one showed interference; the authors caution that constructed rates are not prevalence [xia2026]. Inferred: local per-agent test passes do not certify the merged state, and reviewed history rarely hides semantic conflicts, but concurrent agent pull requests are common and textually conflict at a non-trivial rate.

The Group's own duplicated "Compose canonical standalone service repositories" commits are the documented pattern: duplicates as a rejection cause [ehsani2026], vague delegation producing duplicated work [anthropicma], and no claim-before-write step. Unknown: no source quantifies throttles on agent pull-request creation, or orphaned branches from failed multi-step tool calls (the Group's SEV-1 on ChatGPT-Web).

## 2(e). Deriving architecture from requirements when the principal states only goals

### Standards define what to record, not how to derive

Observed: ISO/IEC/IEEE 42010:2022 specifies architecture descriptions (stakeholders, concerns, viewpoints, correspondences, decisions and rationale) and does not prescribe how an architecture is created; it separates the architecture from its description (secondary summary; the standard is paywalled) [iso42010]. Unknown: the processes of 29148, 15288, 12207 and the INCOSE Handbook were not retrieved.

### Jackson and Zave give the derivation rule

Observed: requirements are statements about the environment; a specification may use only phenomena shared by the environment and the machine; domain assumptions together with the specification must entail the requirements. The 1995 paper wins an ICSE ten-year award and uses a zoo turnstile example [jacksonzave1995]; the 1997 paper presents the framework and says "the environment is not the most important thing--it is the only thing" [zavajackson1997]. Unknown: the notation (W,S ⊢ R in 1995; K,S ⊢ R in secondary summaries of 1997) was not verified in either paper text, since the PDFs were unreadable. Observed (secondary): Problem Frames separate causal from biddable domains and decompose in parallel into subproblems matching known frames [jackson2001]. Observed: Twin Peaks says requirements and architecture develop concurrently, with equal weight [nuseibeh2001]; goal models elaborate requirements from strategic goals [vanlamsweerde2001]. Unknown: no empirical outcome evidence for goal-oriented requirements engineering was retrieved.

### SEI methods convert vague concerns into testable scenarios

Observed (course excerpts): a quality attribute scenario has source, stimulus, artifact, environment, response and response measure; ATAM outputs risks, non-risks, sensitivity points, tradeoff points and risk themes [bassqas][atam]. Inferred: the response measure is the field that makes a scenario machine-checkable. Inferred: when an owner supplies only business goals, the architect proposes scenarios and the owner ratifies the business-level ones (a utility-tree priority). Unknown: no measured ATAM outcomes were retrieved, so owner-elicitation effectiveness is unsupported.

### Governance artifacts decay unless bound to checks

Observed: an ADR is a short, numbered, repository-resident record with Title, Context, Decision, Status and Consequences, superseded rather than deleted [nygard2011]. Measured: in a study of 921 GitHub repositories, about 63% of 5,800 ADRs were opened directly as "accepted", skipping deliberation [icsa2026adr]. Measured (small action research, 7 interviewees, 3 months): ADRs improved team cooperation but distributed-systems challenges remained [ecsa2024adr]. Observed: Google design docs are written before coding to find issues early and build consensus (advocacy, unmeasured) [ubl]. Observed: fitness functions (metrics, monitors or tests) guard evolutionary architecture [fordfitness]. Observed: reflexion models compare a declared high-level model with source and won an ACM SIGSOFT retrospective impact award; the mechanism was not re-sourced [murphy1995]. Observed: erosion surveys find that causes are largely non-technical, that no single strategy suffices, and that practitioners lack detection tools and infer from symptoms (10 survey respondents; small) [desilva2012][li2021erosion]. Inferred: treating existing code as the intended design removes the reference against which erosion can be measured; a declared target architecture must come first.

### Industrial formal specification at design level

Measured (authors' own reports, no controls): AWS used TLA+ on 10 systems and found design-level bugs that review and testing missed, with engineers from entry level to principal productive in 2 to 3 weeks (secondary summary of the CACM paper) [newcombe2015]. Measured: ShardStore's executable reference models prevented 16 issues from reaching production at about 14% added code, with developers writing 18% of the specifications [bornholt2021]. Measured (self-reported by the B community): the Meteor driverless metro line's more than 110,000 lines of B models yielded no bugs found after proof, in validation, on-site testing, or operation since October 1998 [behm1999]. Inferred: the specification is a separate artifact, written and checked first, and a cheap executable version lets non-experts maintain it.

### Category-theoretic derivation is prototype-grade

Observed: NIST-affiliated authors describe categorical methods in systems engineering as "mostly at the level of prototype and proof-of-concept" [breiner2023]. Observed: Specware structures specifications by "composition by colimit" and refines them with over 40 transformations to code with machine-checkable proofs; no measured industrial outcome was found [specware]. Observed (abstract-level): institutions formalize logical systems so specifications can be glued independent of the logic [goguen1992]; Goguen's sheaf semantics treats behavior as a limit and interconnection as a colimit [goguensheaf]. Inferred: "unit requirements glue to a system requirement only where they agree on overlaps" is a sound reading of the Group's design, but it is a proposal; the evidence does not show any production organization deriving architecture this way. Unknown: how inconsistent requirements are handled (paraconsistent, linear logic) was out of scope.

### Who decides, when the principal cannot weigh in

Inferred from the above: the Leader owns environment-side statements (market goals, constraints, acceptance criteria stated as measurable responses), the architect role derives specifications within Jackson and Zave's constraint, and the check that closes the loop is mechanical (response measures as tests, declared architecture as a conformance check). No retrieved source describes a principal who is technically unable to review; this is an extrapolation.

## 3. Cross-cutting synthesis: eight principles that recur

Inferred principles, each tied to the evidence:

1. **One writer per pointer.** Where pins exist, an automated identity writes them (Chromium and Fuchsia rollers, Nix channel script, merge queues), or the pin does not exist (Google, Meta; Guix, which pins one commit) [chromiumdeps][fuchsia2024][nixpkgs][winters2020vc][guixmanual].
2. **The gate tests the set, in the state it will land in.** Zuul, Tide, bors and SubmitQueue test main plus the changes ahead; TAP tests batches and finds culprits afterward; either way a named procedure, not the author, certifies the set [zuul][tide][uber2025][memon2017].
3. **Breakage has an owner and revert is the default.** Sheriffs, infrastructure teams that own large-scale changes, and maintainers [skiaroll][winters2020lsc][kernelmaint].
4. **Mechanical, cross-cutting work is one governed change, not many agent decisions.** Rosie shards a master change; Spotify's Fleet Management and Google's migrations shard to owners [winters2020lsc][spotify1][nikolov2025].
5. **Scope is computed from a path-to-owner map by the enforcement point.** OWNERS, MAINTAINERS and the LPMud master are the same primitive, and ownership predicts quality [chromiumreview][kernelmaint][fluffosmaster][bird2011].
6. **Authority is passed with the task, not held by the actor.** Hardy, Miller and Capsicum say so in theory; Anthropic's web sandbox, Uber's token exchange and GitHub's agent restrictions do it in practice [hardy1988][claudesandbox][uberid][copilotrisk].
7. **Mandatory at the seam, optional inside; instructions steer, mechanisms bound.** Amazon's interface mandate and the guarded landing path are mandatory; golden paths are optional; prompts are violated at measurable rates and registry-level filtering is not [yegge2011][spotifygolden][uppala2026].
8. **Every loop has an external check and a cap.** Spotify (10 turns, 3 retries, verifiers, stop hook), Stripe (2 CI rounds), GitHub (59 minutes), Anthropic (goal conditions, stop hooks) [spotify2][stripe1][copilotrisk][claudebest].

A ninth, weaker pattern concerns architecture: the reference for conformance is a declared artifact outside the code (design doc, specification, ADR bound to a check), and architecture records alone decay [ubl][bornholt2021][icsa2026adr].

Steelman of the opposing view: DORA 2024 found forced exclusive platform use associated with lower throughput and stability [dora2024][dora2024sec], Cognition and Anthropic disagree on whether multi-agent coding works [cognition2025][anthropicma], and the METR trial suggests that heavy tooling may not help experienced developers [becker2025]. The evidence does not oppose gating the landing step; it opposes forcing every task through a platform.

## 4. Implications for the 561 Group: requirement candidates

Everything in this section is Inferred. These are candidates for the owning sections to ratify, restate in their own terms and derive from; they are not requirements. The Group's existing requirement and rule records are not used as authority.

1. **Each integration pointer has exactly one automated writer, and it is a MetroPlat operation.**
   - Grounds: Chromium and Fuchsia rollers, Nix channel script, merge queues, Rosie [chromiumdeps][fuchsia2024][nixpkgs][winters2020lsc]. Duplicated pin-advance commits and the 68% integration share (measured in the Group's corpus, 2026-10-16).
   - Replaces: hand-written "Record … at current mains" pull requests, `scripts/advance.mjs` without callers, and the closed "Advance submodules" pull request (bare-cedar-fog#796).

2. **A pin advances only after a declared, hermetic build of the candidate set passes.**
   - Grounds: Nixpkgs on Hydra, Zuul and Tide testing main plus the queued changes, the Guix single-commit channel with `guix time-machine` [nixpkgs][zuul][tide][guixmanual]. The Group already selects Guix and Guile through LAGOON.
   - Replaces: the diagnosis that "does the set work" is answered by running things, and the seven simultaneous pin mechanisms.

3. **One pin mechanism per dependency kind, and no pointer that does not resolve.**
   - Grounds: the One-Version Rule; Guix referencing packages as variables, not versions; SemVer's documented lossiness [winters2020vc][winters2020dep][guixmanual].
   - Replaces: 89 `workspace:*` specifiers with deleted workspace and lockfile, 53 exact npm specifiers, 43 JSON hash records, a LAGOON loaded by path and also published as npm at a different MetroPlat version, and one repository at three commits.

4. **The section tree is a tree: each section is mounted by its immediate parent, and parent-child pointer chains stay at two or three links or are flattened.**
   - Grounds: Linux chains "rarely exceed two or three links"; Google says submodules only approximate a monorepo; the Conway and congruence results [kernelprocess][winters2020vc][maccormack2012][cataldo2013]. Unknown: nested depth beyond one level has no source.
   - Replaces: 537 plain directories where sections should be, empty-shell parents, parallel same-named repositories, and the drifted science directory (measured in the Group's corpus, 2026-10-16).

5. **An agent's scope is computed by MetroPlat from its seat and the section tree, and enforced where the change lands, not stated in a prompt.**
   - Grounds: path-to-owner maps as gates (OWNERS, MAINTAINERS, `valid_write`, `creator_file`) and the instruction-versus-mechanism gap [chromiumreview][kernelmaint][fluffosmaster][uppala2026][gloaguen2026].
   - Replaces: sessions that are never told their section, what they may change, who works nearby, or what is live; reliance on CLAUDE.md and AGENTS.md (which conflict) as the control.

6. **Every agent session has its own identity, recorded in history, with delegation from the Leader recorded.**
   - Grounds: Copilot's agent author with human co-author and signing; Uber's SPIFFE identity and actor chain; gitsign; GitHub App tokens limited to one repository for one hour [copilotrisk][uberid][gitsign][githubapp].
   - Replaces: every commit authored `emsenn <emsenn@emsenn.net>` unsigned; the `continuous-delivery-services-section` name on interactive commits; characters (Hai Zhou, Hai Jian) that exist in records but not in authorship.

7. **Agents hold no ambient authority: no `gh`, `ssh`, long-lived token or `bypassPermissions` shell reaches `main`; authority arrives with the task as a short-lived, repository-scoped capability.**
   - Grounds: Hardy's confused deputy, object-capability security, Anthropic's credentials-outside-the-sandbox design, Uber's audience-bound tokens, the GitHub bypass-list hole [hardy1988][miller2006][claudesandbox][uberid][githubrulesets].
   - Replaces: full shell, git, `gh` and ssh in every session; a single hook as the only effective boundary. Unknown: whether the hook holds under `bypassPermissions`.

8. **Landing is mandatory and gated; work is not.** Sessions may explore freely inside a duty worktree, and only `duty-worktree-integrate` (propose a commit, independent receiver accepts, queue merges that exact commit) can write `main`.
   - Grounds: GitHub's rule that the requester cannot approve; the Amazon mandate as an enforced seam; DORA 2024's caution against forcing all tasks [copilotrisk][yegge2011][dora2024].
   - Replaces: the removed independent-receiver rule (bare-cedar-fog#362) and merge-queue gate (bare-cedar-fog#641); producers testing and merging their own work; GitHub reconciliation outside MetroPlat. Compatible with the settled rule that missing CI never blocks a merge, since the gate is review plus test run by the landing path, not external CI availability.

9. **Dispatch is one task, one repository, one sandboxed worktree, one branch, one pull request, with a claim recorded before writing.**
   - Grounds: the GitHub, Stripe and Spotify shape; duplicate pull requests and vague delegation as documented failure causes; 40.2% of repositories with concurrent agent pairs and 41.7% cross-agent textual conflicts [copilotrisk][stripe1][spotify2][ehsani2026][anthropicma][xu2026].
   - Replaces: parallel identical "Compose canonical standalone service repositories" commits and the two parallel duplicate reconciliations; ChatGPT-Web scheduled tasks that orphan branches (github-engineering-services-section#4).

10. **Cross-cutting mechanical changes (pin sweeps, repository composition, extraction) are one governed master change with generated shards, not many sessions' decisions.**
    - Grounds: Rosie, proposal and oversight, rule of thumb of 500 edits, Spotify Fleet Management [winters2020lsc][spotify1].
    - Replaces: the 78 gitlink-only and 26 extract-mount-delete commits in 300.

11. **Every dispatched task names a machine-checkable done condition, and the loop has external verification and caps on turns, retries and CI rounds.**
    - Grounds: Spotify's verifiers, stop hook and caps; Stripe's two CI rounds; Anthropic's verification guidance and failure patterns; self-repair and repetition evidence [spotify2][spotify3][stripe1][claudebest][olausson2024][sweSmith].
    - Replaces: the try-crash-trace-patch-retry session, "pretend there are no tests", and uncapped retries. Add loop and edit-streak detectors as circuit breakers only as a supplement; Unknown: whether suppressing repetition alone raises resolve rate.

12. **The agent's interface to the corpus is a small set of scope-aware verbs (search within my section, scoped edit, run my section's declared build), not a raw shell over 92,000 files.**
    - Grounds: ACI results and Agentless; Spotify's minimal tool set; the host-resource hook as the only mechanism observed to change behavior [sweagent][agentless][spotify2].
    - Replaces: whole-tree scans guarded by a deny-list hook. The 2024 benchmark numbers are superseded; only the qualitative claim is relied on.

13. **Architecture is a declared artifact outside the code, derived by a stated rule, and a conformance check compares code to it.**
    - Grounds: 42010's architecture-versus-description split; Jackson and Zave's derivation rule (environment statements and domain assumptions, plus a specification in shared phenomena, entail the requirement); reflexion models and fitness functions; AWS's separate checked specifications; the 63% auto-accepted ADRs showing records alone decay [iso42010][jacksonzave1995][murphy1995][fordfitness][bornholt2021][icsa2026adr].
    - Replaces: agent-written code treated as intentional by all agents; requirements and rules as files for storing corrections. Requirement records the Group has already declared misconstructed are not used as the base.

14. **The Leader ratifies requirements at the environment boundary only: market goals, constraints and measurable response measures; architects derive everything past that, and the derivation cites the requirement it serves.**
    - Grounds: Jackson and Zave's world/machine split; SEI scenarios with response measures; Twin Peaks co-evolution [jacksonzave1995][bassqas][nuseibeh2001].
    - Replaces: correction-by-session, where each failure is a Leader correction. Unknown: no source describes a principal who cannot review technical artifacts; this is an extrapolation.

15. **Category-theoretic structures (sheaf gluing, colimits of unit specifications) are built as an experimental derivation layer with a conventional check beside them, not as the only gate.**
    - Grounds: NIST-affiliated authors call the field prototype-grade; Specware and Goguen are the precedents; no industrial outcome data [breiner2023][specware][goguen1992].
    - Replaces: reliance on an unvalidated formalism as the authority for pins, scope or landing.

16. **Success is measured by outcomes, not volume.** Track revert rate, post-merge failures, duplicated work, time on pins and landed product change, not pull-request counts or the agents' own estimates.
    - Grounds: METR's perception gap, DORA 2025's volume-versus-controls finding, Stripe's missing denominator, published acceptance gaps [becker2025][dora2025][stripe2][li2025aidev].
    - Replaces: the 2,290 pull requests in six days as an implicit progress measure.

## 5. Limits of the evidence and open questions

- Organizational transfer. Most evidence comes from organizations with thousands of engineers and large infrastructure teams. Unknown: whether a one-person conglomerate with agents on a laptop and a $14 VPS can afford the compute of per-change gating. Uber's own queue needed a 2024 redesign to cut CI resource 53% [uber2025].
- Submodules. Unknown: no measured submodule pin overhead, no migration write-up, no source for nesting past one level, no external benchmark for the 68% pointer share.
- Agent evidence. Most figures are self-reported by vendors and adopters (Spotify, Stripe, Uber, Google, Airbnb, Anthropic, AWS). Unknown: post-merge defect or revert rates for agent work; throttling of agent pull requests; orphaned-branch rates. Several 2026 results are preprints, snippets or secondary summaries; those cited are labeled.
- Enforcement evidence. The strongest quantification of the instruction-versus-mechanism gap is a single-author adversarial-scenario preprint [uppala2026]. No study measures enforcement against project rules such as CLAUDE.md. Unknown: whether PreToolUse deny holds under `bypassPermissions`.
- Superseded benchmarks. SWE-agent, Agentless and SWE-Bench Pro scores date from 2024 and 2025 models; only qualitative claims are relied on. METR's measurements of 2026 productivity are unreliable by METR's account [metr2026].
- Architecture derivation. Unknown: no outcome evidence for goal-oriented requirements engineering, ATAM, or categorical derivation; the standards' derivation clauses were not read; Jackson and Zave notation unverified in the paper texts; paraconsistent and linear-logic treatment of inconsistent requirements is out of scope.
- MUD and Rendanheyi analogues. The LPMud master-object hooks are well sourced, but the Discworld creator hierarchy and real domain policy code are not; Haier is described only in secondary sources with no outcome data or scope-enforcement mechanism.
- Open questions for the Group: What is the smallest hermetic build that answers "does the set work" for the 26-root-submodule tree? Which MetroPlat operation owns the pointer writer, and what is the sheriff office? What does the architect role consist of when no human reviews? Can a duty worktree be made the only writable surface for a session without breaking the Leader's own hand edits?
