# Section materialisation: three naturality-preserving regimes (A/B/C) and the exclusion of state-dependent caches

**Claim.** Let $\mathcal{F} : \mathcal{C}_{\mathrm{sub}}^{\mathrm{op}} \to \mathbf{Bilat}$ be the substrate's [presheaf-indexed fiber](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/concepts/presheaf-indexed-fiber.md), and let $\pi_c : \mathcal{F} \to \mathcal{F}(c)$ be a [knowledge-join](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/morphisms/knowledge-join.md)-natural projection at context $c$ (a section of the presheaf at $c$). A *materialisation* of $\pi_c$ is a substrate-side artifact $M_c$ that the substrate produces and a reader consults in lieu of recomputing $\pi_c$ from $\mathcal{F}$ on each read.

We identify three structurally distinct regimes — A (durable cell), B (on-read derivation), C (virtual cell) — each of which preserves [projection-merge naturality](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/projection-merge-naturality.md) by construction. The substantive content of the claim is the *exclusion result*: any materialisation $M_c$ that is keyed by data not uniquely determined by the input fiber (e.g., entity slug + filesystem mtime, opaque generation counter) admits a stale-cache failure mode and is not a section materialisation under this theorem. We do not claim A/B/C are the *only* naturality-preserving schemes — a clever encoding may hybridise them — but every naturality-preserving scheme reduces, on the function-of-input-fiber requirement of Part 1 below, to one of A, B, C, or a fibrewise composition of them.

- **A — section-as-object (durable cell).** $M_c$ is a substrate cell whose subject is the projection-target entity, whose predicate names $c$, and whose object is content-addressed by $\mathrm{SHA\text{-}256}(\mathrm{canonical}(\pi_c\mathcal{F}))$. The cell lives in the [event log](../objects/event-log.md), federates by the standard cell-receive path, and is recovered byte-identically on replay. Per [cache-coherence-via-functorial-projection](cache-coherence-via-functorial-projection.md), the cell is a content-addressed cache entry whose key uniquely determines its value; staleness is structurally impossible.
- **B — section-as-morphism (on-read derivation).** $M_c$ does not exist outside read-time. Each read invokes $\pi_c$ on the input atoms and discards the result post-query. Naturality is preserved trivially: there is no materialised artifact whose freshness must be argued for. Per [cost-discipline-reads-free](cost-discipline-reads-free.md), the read is bounded by the input fiber's content-addressed lookup cost and the projection's per-atom application cost.
- **C — section-as-functor (virtual cell).** $M_c$ is queryable as if it were a cell — addressable by the same content-hash key as in regime A — but is computed on each query and not durably stored in the event log. Naturality is preserved by the projection's functoriality (per [projection-merge-naturality](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/projection-merge-naturality.md)); the substrate's storage layer recognises the virtual key and dispatches to the on-read computation.

The three regimes are mutually exclusive at any single $(\mathrm{entity}, c)$ pair; they are independently choosable across distinct $(\mathrm{entity}, c)$ pairs. Any materialised artifact that is neither content-addressed (under a key uniquely determining the input fiber) nor on-read-derived fails [projection-merge-naturality](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/projection-merge-naturality.md) and is not admissible as a section materialisation under this theorem; per Part 3 below, the failure surface is exactly the stale-cache class.

## Why this holds

The argument turns on what "preserves naturality" demands of $M_c$.

**Part 1: Naturality demands a function of the input fiber.** Per [projection-merge-naturality](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/projection-merge-naturality.md), $\pi_c \circ \odot = \odot \circ (\pi_c \times \pi_c)$: projecting a merge equals merging the projections. Any materialisation $M_c$ that purports to represent $\pi_c$ must satisfy $M_c(\mathcal{F}_1 \odot \mathcal{F}_2) = M_c(\mathcal{F}_1) \odot M_c(\mathcal{F}_2)$ on every input pair. This is the categorical statement that $M_c$ is a function of the input fiber: same input, same output, no auxiliary state.

**Part 2: A function of the input fiber admits three structurally distinct storage regimes (A/B/C).** A function $M_c$ of $\mathcal{F}$ can be stored in the following three ways, each preserving naturality by construction:

- *Stored under a key that uniquely determines the input.* Regime A: the key is $\mathrm{SHA\text{-}256}(\mathrm{canonical}(\pi_c\mathcal{F}))$ per [hash-injectivity-under-canonical-form](hash-injectivity-under-canonical-form.md). The stored value is the function's output; per [cache-coherence-via-functorial-projection](cache-coherence-via-functorial-projection.md), staleness is structurally impossible.
- *Not stored.* Regime B: the function is invoked at read time and the output is discarded. Naturality is preserved trivially because the stored representation is empty.
- *Stored under a key that uniquely determines the input, but recomputed on each query.* Regime C: the key is the same content-hash as A; the storage layer reserves the key but does not persist the value. Naturality is preserved by recomputation; the key reservation is a query-routing affordance.

**Part 3: Any storage scheme outside this trichotomy admits stale-cache failure.** A materialisation that stores $M_c$ under a key that does *not* uniquely determine the input — e.g., keyed by entity slug alone, or by entity-slug-plus-mtime, or by an opaque generation counter — admits two distinct fibers $\mathcal{F}_1 \neq \mathcal{F}_2$ at the same key with $\pi_c\mathcal{F}_1 \neq \pi_c\mathcal{F}_2$. The cache then has a stale-cache failure mode: a read after $\mathcal{F}_1$ followed by a write of $\mathcal{F}_2$ may return the $\mathcal{F}_1$ projection at the $\mathcal{F}_2$ key. Per the [cache-coherence](cache-coherence-via-functorial-projection.md) discipline, this is exactly the state-dependent-cache class the theorem rules outside the structural-coherence envelope. The substrate may run such a cache as a separate artifact (with explicit invalidation policy and out-of-band validity argument), but it is not a section materialisation of $\pi_c$ under this theorem. Hybrid schemes that fibrewise combine A, B, and C remain inside the envelope; schemes that introduce a non-fiber-determined key on any fibre fall outside it.

## Engineering consequence

- **A is admissible when reads of $\pi_c$ are dominant and federation ships projections.** When a dashboard or audit traversal reads $M_c$ at high frequency, A pays the disk-duplication cost once and amortises it over every read. When [federation](../theorems/federation-convergence.md) needs to ship projections without re-deriving them on the receiving side, A is the only regime that produces a federation-shippable artifact (B has no artifact to ship; C's key is shippable but not its value). Per [cross-peer-stratum-projection-via-naturality](cross-peer-stratum-projection-via-naturality.md), A's federation discipline is exactly the naturality square applied to ship-then-merge.
- **B is admissible when reads of $\pi_c$ are rare and inputs are content-addressed.** When the projection is consulted only at audit time or during error investigation, the recomputation cost is amortised over rare reads and the substrate avoids the disk-duplication cost. B is the substrate's default regime; per [cost-discipline-reads-free](cost-discipline-reads-free.md), the on-read computation is bounded by input-fiber content-addressed lookup, which is cheap on small inputs and super-linear on large ones.
- **C is admissible when the read surface wants cell-shape uniformity but the storage budget refuses A.** A higher-level reader (a CLI, a dashboard, a federation-receive validator) may want to address $M_c$ by content-hash key — same shape as any other cell — without the disk-duplication cost of A. C provides the key-routing affordance without the storage. The trade-off: each query pays B's recomputation cost; the surface pays a key-recognition cost (the storage layer must dispatch on the virtual key).
- **Election is per-$(\mathrm{entity}, c)$.** A substrate may elect A on the by-stratum projections of an entity that is read on every dashboard refresh, B on the by-session projections of the same entity that are consulted only at audit time, and C on the by-peer projections that federation peers query by hash without persisting. Per the [predication fibration](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/objects/predication-fibration.md), the election is fibrewise; no global "all projections are A" or "all projections are B" mandate is required.
- **Replay reproduces the election.** Under A, replay reproduces the projection cell byte-identically per [cache-coherence-via-functorial-projection](cache-coherence-via-functorial-projection.md); under B, replay reproduces the input fiber and the on-read computation produces the same result; under C, replay reproduces the input fiber and the virtual cell's hash key. In all three regimes, the substrate's [source-of-truth](teaching/explanations/source-of-truth.md) discipline is preserved — the event log determines the projection's value, materialised or not.

## What the theorem rules out

- **Mtime-keyed projection caches.** A materialisation keyed by entity slug + filesystem mtime does not uniquely determine the input fiber (mtime is a host-side coordinate that may not coincide with the substrate's event-ordinal cursor) and does not preserve naturality across federation merges (peers may have different mtimes for the same content). Per Part 3, the substrate refuses; if disk-budget is the concern, regime B or C is the disciplined alternative.
- **Generation-counter-keyed projection caches.** A materialisation keyed by an opaque generation counter (incremented on every fiber mutation) is structurally a state-dependent cache — the counter is not a function of the input. Per [cache-coherence-via-functorial-projection](cache-coherence-via-functorial-projection.md)'s state-dependent-cache distinction, such a cache requires explicit invalidation policy and is not a section materialisation under this theorem.
- **Lazy materialisation that "hardens" into A.** A materialisation that is C until first read, then converts the virtual cell into a durable A cell, is admissible — but the conversion is itself an event-log entry per [source-of-truth](teaching/explanations/source-of-truth.md), not an in-memory cache update. The substrate's discipline is that the regime transition is observable in the event log.
- **Cross-context materialisation that ignores $c$.** A materialisation $M$ that stores "the projection" without recording $c$ — i.e., implicitly assumes a single context coordinate — fails naturality across context restrictions. The substrate refuses; $c$ is part of the materialisation's identity, per [presheaf-indexed-fiber](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/concepts/presheaf-indexed-fiber.md).

## What the theorem requires

- The projection $\pi_c$ is a [knowledge-join](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/morphisms/knowledge-join.md)-natural restriction morphism in $\mathcal{C}_{\mathrm{sub}}$ (per [projection-merge-naturality](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/projection-merge-naturality.md)).
- The substrate's atom identity is canonical-form-injective (per [hash-injectivity-under-canonical-form](hash-injectivity-under-canonical-form.md)).
- Under A, the projection-cell shape and predicate are fixed (a schema change at the projection-cell predicate retires existing A entries and admits fresh ones).
- Under C, the storage layer's virtual-key dispatch is part of the substrate's read-side primitives (not a separate runtime cache).

## Position

This theorem is the structural account of "should we materialise this projection?" — the question that arises every time the substrate is asked to optimise a derivation read. The trichotomy makes the choice explicit: A trades disk for read-throughput and federation-shippability, B trades read-latency for disk and surface simplicity, C trades surface-uniformity for read-time recomputation. None is universally correct; the captain-electable choice is recorded as substrate content (per [self-representation](teaching/explanations/self-representation.md), e.g., `(projection:<entity>/<context>, materialisation-regime, A) = t`) and the conformance check enumerates the cells and tests each elected regime against its naturality witness. Composes with [storage-as-projection](storage-as-projection.md) (the substrate's storage is itself a projection of the event log; section materialisation is the next-level projection of an entity's stored fiber), with [cache-coherence-via-functorial-projection](cache-coherence-via-functorial-projection.md) (regime A is a structurally-coherent content-addressed cache), and with [host-projection-substrate-adjunction](host-projection-substrate-adjunction.md) (when $M_c$ is rendered onto a host position, the K/L/M election composes with the A/B/C election fibrewise).
