A worker is the performing party in the [work](./work.md) vocabulary: given
a work unit — an instance of work naming what it acts on, which aspect
changes, how the change is produced, and the parameters that make this
instance distinct from others of the same operation — the worker is whoever
or whatever actually carries it out. This is a role, not an identity: the
same person, team, or agent can be a worker on one task and a
[steward](../../../../../../../../content/text/glossary/terms/steward.md) or planner on another, and nothing about being a
worker requires exclusivity or permanence in that role.

A worker's relationship to the surrounding structure is precise. A
[task](./task.md) is a named planning container for work units with a
completion condition; the worker is who satisfies that condition by doing
the units the task groups. A [workflow](./workflow.md) is a set of work
units composed so that its overall input type equals its overall output
type; a worker executing within a workflow is bound by that composition,
not merely by the individual unit in front of them. Work with a documented,
repeatable [method](./method.md) is skillful work, and a worker following
such a method is engaged in [practice](./practice.md) — practice being what
a worker does with work, exactly as method is what governs it. A worker
without any task is idle capacity; a task without any worker is an
unexecuted plan.
