## OpenClaw Heartbeat System - Educational Overview

Based on the documentation I found, here's how the OpenClaw heartbeat system is supposed to work:

### What is a Heartbeat?

A heartbeat in OpenClaw is a **periodic agent turn** that runs in the main session so the model can surface anything that needs attention without spamming you with constant notifications.

Key characteristics:
- Runs in the **main session** (not isolated like cron jobs)
- Does **not** create background task records (those are for detached work like ACP runs or subagents)
- Designed for lightweight, frequent check-ins

### How Heartbeats Are Supposed to Work

According to the documentation, here's the intended flow:

1. **Configuration**: The heartbeat system is controlled via `gateway config` under `agents.defaults.heartbeat` or per-agent settings
2. **Triggering**: The system automatically sends a heartbeat prompt at configured intervals
3. **Execution**: When a heartbeat triggers:
   - The agent receives some form of system event or user message with the heartbeat prompt
   - The agent reads `HEARTBEAT.md` (if it exists) from the workspace
   - The agent follows the instructions in HEARTBEAT.md
   - The agent either replies with `HEARTBEAT_OK` (if nothing needs attention) or provides a substantive response
4. **Delivery**: Based on configuration, the response may be:
   - Sent as a notification/alert (`showAlerts: true`)
   - Accompanied by a `HEARTBEAT_OK` acknowledgment (`showOk: true`)
   - Accompanied by indicator events (`useIndicator: true`)
   - Or suppressed entirely if all three are false

### The HEARTBEAT.md File

As you already have in your workspace, `HEARTBEAT.md` serves as your "heartbeat checklist":
- Should be small, stable, and safe to include every 30 minutes
- Tells the agent what to check during each heartbeat
- If effectively empty (only blank lines/headers), the heartbeat run is skipped to save API calls
- If missing, the heartbeat still runs but the agent decides what to do based on the default prompt

### Default Heartbeat Prompt

The default prompt that gets sent to the agent during each heartbeat is:
```
"Read HEARTBEAT.md if it exists (workspace context). Follow it strictly. Do not infer or repeat old tasks from prior chats. If nothing needs attention, reply HEARTBEAT_OK."
```

### Configuration Options

From the documentation, key heartbeat configuration options include:

1. **Timing/Cadence**:
   - `every`: Heartbeat interval (default: `30m` or `1h` for Anthropic OAuth/token auth)
   - Can use `0m` to disable heartbeats entirely

2. **Session/Execution Context**:
   - `lightContext`: When true, only injects HEARTBEAT.md from bootstrap files (saves tokens)
   - `isolatedSession`: When true, runs each heartbeat in a fresh session (no conversation history)
   - `skipWhenBusy`: When true, defers heartbeats when subagent/nested lanes are busy

3. **Delivery/Visibility**:
   - `target`: Where to send heartbeat output (`"last"`, `"none"`, or channel ID like `"discord"`)
   - `to`: Optional recipient override (phone number, chat ID, etc.)
   - `accountId`: For multi-account channels
   - `directPolicy`: Controls direct/DM delivery (`"allow"` or `"block"`)

4. **Content/Features**:
   - `includeReasoning`: When true, also delivers separate `Reasoning:` message
   - `prompt`: Custom heartbeat prompt body (overrides default)
   - `ackMaxChars`: Max chars allowed after `HEARTBEAT_OK` before delivery (default: 300)

5. **Time Restrictions**:
   - `activeHours`: Restricts heartbeats to specific time windows (useful for avoiding night notifications)

### How Heartbeats Should Be Triggered

According to the docs, heartbeats should be triggered automatically by the OpenClaw system based on the configuration. The system:
1. Schedules heartbeat prompts based on the `every` setting
2. Sends the heartbeat prompt (verbatim from config) as a user message to the agent's main session
3. The agent processes this and responds appropriately
4. The response is then handled based on visibility configuration (`showOk`, `showAlerts`, `useIndicator`)

4. **Are responses being delivered?**

### Advanced: HEARTBEAT.md with tasks: blocks

As an advanced feature, your HEARTBEAT.md can include a structured `tasks:` block for interval-based checks:

```md
tasks:

- name: inbox-triage
  interval: 30m
  prompt: "Check for urgent unread emails and flag anything time sensitive."
- name: calendar-scan
  interval: 2h
  prompt: "Check for upcoming meetings that need prep or follow-up."

# Additional instructions

- Keep alerts short.
- If nothing needs attention after all due tasks, reply HEARTBEAT_OK.
```

With tasks: blocks, OpenClaw:
- Parses the tasks and checks each against its interval
- Only includes **due** tasks in the heartbeat prompt for that tick
- Skips the heartbeat entirely if no tasks are due (`reason=no-tasks-due`)
- Preserves non-task content as additional context
