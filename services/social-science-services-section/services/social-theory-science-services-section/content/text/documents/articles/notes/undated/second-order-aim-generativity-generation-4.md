# Generation-4 pilot: mutating an aim-generator

This is an experimental example for the open question
[second-order aim-generativity](second-order-aim-generativity.md).
It records a bounded mutation of one problem-selection mechanism. It is not a
theorem and does not establish autonomous institutional imagination.

## Experimental question

Can a mutation of an aim-generating practice produce a *different class of
research aim* from its parent practice while the relevant hard-core constraints
and evidence environment are held fixed?

The test uses the `@emsenn/relating` operations-manifold surface as a bounded
developmental niche.

## Fixed hard-core constraints

The experiment treats the following as fixed constraints rather than mutable
fitness targets:

1. carrier identity remains the law for exact action composition;
2. derived reads do not invent semantic compatibility or organizational intent;
3. lossy representation must remain distinguishable from preservation;
4. candidate generation is read-only research and grants no execution authority;
5. evidence must retain repository/commit provenance.

These constraints are a local experimental (C), not a claim that they exhaust
the hard core of the larger 561 Group or of `@emsenn/relating`.

## Fixed niche

The shared niche (N) contains:

- `emsenn/relating@63287195de694fc6997ec4e1fa880fe98aa0d5d8`;
- the accessible git history of `src/running/manifold.mts`;
- the accessible git history of `examples/operations-manifold.mjs`;
- current repository documentation describing the operations manifold;
- repository search sufficient for a bounded ancestor audit.

The full L-Space semantic corpus was unavailable during this experiment, so
ancestor-distance claims remain provisional.

## Parent aim-generator: static frontier morphology

Call the parent mechanism (Gamma_0).

Its noticing rule is:

> Read the current operations-manifold graph. Treat current incoming and
> outgoing carrier frontiers as candidate capability gaps. Prefer questions
> whose answers could increase lawful composition without inventing semantics.

Its valuation discipline (V_0) rewards present compositional leverage,
testability, explicit carrier identity, and low adapter cost.

A prior generation using this mechanism produced the research candidate
`emsenn/relating#1`: inspect complementary current frontiers for lawful bridge
relations while making loss and missing obligations explicit.

## Mutation: temporal residue

The mutation (m_t) adds one noticing/valuation trait:

> Do not read a frontier only as a present gap. Read its *trajectory* across
> independently identified repository states. Persistence, closure, recurrence,
> migration, split/merge, and loss of observability may themselves be evidence.

The descendant mechanism is

[
Gamma_1 = m_t(Gamma_0).
]

The mutation does not change the exact-composition law. It changes what counts
as salient evidence for proposing an investigation.

## Bounded observation

The inspected repository history supplied a non-empty temporal signal.

### Manifold persistence

`src/running/manifold.mts` is present by commit
`f93182c92b97e370596526ab1be1c98fcb290655` (2026-06-25), remains present at
`96a8066490a2300614b6bbc9752f4d2c0c9b113d` (2026-06-26), and remains in the
current inspected revision `63287195de694fc6997ec4e1fa880fe98aa0d5d8`.

Across the inspected source, incoming/outgoing frontier semantics remain
substantially stable: they are still derived from consumed carriers without
visible producers and produced carriers without visible consumers.

### Assay observability changed

At commit `96a8066490a2300614b6bbc9752f4d2c0c9b113d`,
`examples/operations-manifold.mjs` exists as a runnable source/sink fixture. It
constructs a shared-carrier cross-package edge and prints the graph's remaining
incoming and outgoing frontier.

At the current inspected revision, repository code search does not find that
example or its distinctive fixture identifiers, while current documentation
still describes `examples/operations-manifold.mjs` as the runnable example.

This observation does not establish why the example disappeared. It establishes
only that **observability of the same product changed over time**.

## Descendant-generated candidate aim

(Gamma_1) generated the following candidate:

> Determine whether the trajectory of operations-manifold frontiers carries
> useful evidence for capability evolution: frontier birth, persistence,
> closure, recurrence, migration, and observability loss.

This candidate was recorded as `emsenn/relating#2`, “Research temporal
operations-manifold frontier history.”

The proposed discriminator is intentionally bounded: reconstruct a small
sequence of manifold snapshots, derive temporal frontier events
deterministically, and test whether temporal features distinguish later useful
capability changes from random static frontiers. If they do not, the candidate
should die rather than become infrastructure.

## Feasibility provenance

The candidate is feasible because:

- ordinary operations-manifold snapshots already expose exact current
  frontiers;
- git/artifact identities provide ordered historical cuts;
- the operation can remain a pure read over supplied snapshots;
- no consequential action is required for the assay.

## Valuation provenance

The candidate was elevated because the mutated (Gamma_1) assigns value to
**residue that persists through structural change** and to **changes in the
institution's ability to observe its own capability topology**.

That valuation rule is absent from the parent (Gamma_0), which evaluates only
the current frontier configuration.

The valuation is a research heuristic, not a truth criterion. A persistent
frontier may be healthy architecture, debt, or irrelevant.

## Ancestor audit

Bounded GitHub searches over the accessible estate for phrases including:

- “temporal operations-manifold”;
- “operations-manifold history”;
- “frontier trajectory” + capability;
- “frontier persistence” + capability;
- “frontier birth” / “frontier recurrence” in software context;
- “manifold history” + carrier

returned no direct named ancestor.

This is supporting evidence only. The unavailable semantic L-Space prevents a
full-estate novelty certificate.

## Selection receipt

The mutation receives a **provisional survival**, not promotion.

Reasons to retain for another generation:

- it produced a candidate aim of a different type from the parent current-bridge
  aim;
- the candidate has separate feasibility and valuation provenance;
- a bounded historical observation makes the candidate non-vacuous;
- failure of the proposed discriminator would still teach whether temporal
  frontier features are informative.

Reasons promotion is blocked:

- full semantic ancestor search is unavailable;
- the candidate has no downstream implementation or reuse receipt;
- only one bounded historical example has been examined;
- the experimenter still chose the domain and the mutation family.

## What this pilot demonstrates

It demonstrates a weaker fact than autonomous agenda evolution:

[
	ext{same } C,N
;+;
	ext{changed noticing/valuation rule}
;Longrightarrow;
	ext{different candidate-aim class}
]

in one documented case.

The stronger success condition still requires a descendant mechanism whose
productive mutation was not supplied by the experimenter, whose generated aim
survives full ancestor audit and empirical/formal/economic discrimination, and
whose mechanism is subsequently inherited or reused.
