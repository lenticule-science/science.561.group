# Forward-compatible migration preserves prior substrate content

**Claim.** Let $V_1$ be a [closure-rule-system](../objects/closure-rule-system.md) version, $V_2$ a successor version that adds rules without removing or weakening any rule from $V_1$ (a *forward-compatible* migration). Let $S$ be a substrate at $V_1$ with predication valuation $v$. Then [migrate-rule-system](../morphisms/migrate-rule-system.md) from $V_1$ to $V_2$ produces a substrate $S'$ whose predication valuation $v'$ satisfies $v \leq_k v'$ cellwise — every $V_1$-derived predication remains, and $V_2$ may have produced additional derivations.

The migration is *content-preserving*: nothing the substrate held under $V_1$ is lost.

## Why this holds

The argument follows directly from [closure-driven-settling-monotonicity](../../../../../../../humanities/theories/math/theories/categories/theories/predication-categories/theorems/closure-driven-settling-monotonicity.md) applied to the rule-system extension.

**Part 1: Forward-compatible migration adds rules.** Per [schema-evolution](teaching/explanations/schema-evolution.md)'s definition of forward-compatible additions, $V_2 \supseteq V_1$ as rule sets. Every rule in $V_1$ is also in $V_2$.

**Part 2: Adding rules is monotone in the closure operator.** The closure operator $\mathrm{cl}^{\mathcal{S}}$ generated by a rule system $\mathcal{S}$ is monotone in $\mathcal{S}$: if $\mathcal{S}_1 \subseteq \mathcal{S}_2$ then $\mathrm{cl}^{\mathcal{S}_1}(v) \leq_k \mathrm{cl}^{\mathcal{S}_2}(v)$ for every valuation $v$. This is structural in the math: the larger rule system has more inflationary constraints, so its least operator satisfying all constraints is larger in $\leq_k$.

**Part 3: The migration replays under the new rule system.** Per [migrate-rule-system](../morphisms/migrate-rule-system.md), the migration re-applies the closure operator generated by $V_2$ to the substrate's current valuation. Per Part 2, the result is $\mathrm{cl}^{V_2}(v) \geq_k v$, since $\mathrm{cl}^{V_2}$ has all of $V_1$'s rules plus more.

**Part 4: The substrate's audit chain extends.** Per [stepping-laws](stepping-laws.md), each new derivation under $V_2$ is recorded as a settling step. The substrate's event log accumulates these as new witnesses; per [settlement-determinism](settlement-determinism.md), the migration is replayable.

## Engineering consequence

Forward-compatible migration is *zero-cost in correctness terms*: the substrate's prior content is preserved, additional content may be derived, the audit chain extends naturally. Several engineering uses follow:

- **Iterative rule-system evolution.** A team can add closure rules to the rule system incrementally, with each addition being a forward-compatible migration. The substrate evolves while preserving everything it has accumulated.
- **Multi-substrate compatibility.** Two substrates federating, one at $V_1$ and one at $V_2 \supseteq V_1$, can exchange content per [federation-convergence](federation-convergence.md): the $V_1$ substrate's content is admissible under $V_2$, and the $V_2$ substrate's $V_2$-derived content is also admissible under $V_2$. Forward-compatibility is the structural condition for cross-version federation.
- **Conformance testing across versions.** A conformance test suite for $V_1$ remains valid for $V_2$ on the operations $V_1$ covers; per [conformance-implies-substrate-properties](conformance-implies-substrate-properties.md), the suite's properties are preserved.
- **Model supersession.** A learned-model upgrade (a successor model $M_2$ replacing a predecessor $M_1$) compiles to a forward-compatible migration when the substrate encodes "model $M_1$ derived cell $c$" as the witnessed predication rather than baking $c$ into the rule system: $V_2$ adds rules from $M_2$ alongside $V_1$'s, leaving $M_1$'s prior derivations intact and witness-tagged. Per [model-supersession-as-forward-migration-corollary](model-supersession-as-forward-migration-corollary.md), the corollary lifts this theorem to the model-retraction case — the predecessor's derivations are not erased; they are *superseded* by the successor's rules producing the corrected cells, with the bilattice tag carrying the disagreement explicitly.
- **Cross-substrate merge.** Two substrates whose rule systems are both forward-extensions of a common ancestor $V_0$ can merge per [federation-convergence](federation-convergence.md) without rule-system reconciliation: the merged rule system is the union (still a forward-extension of each side), and the merged content is the closure under that union. Each side's prior content is preserved by this theorem applied at each side individually; the merge introduces no content loss.

## What the theorem rules out

- A migration that removes rules from $V_1$ is *not* forward-compatible. The new rule system's closure operator may produce *less* content than the old's; cells $V_1$ derived may not be derivable under $V_2$. Such migrations are *breaking changes* and require explicit recipes per [migrate-rule-system](../morphisms/migrate-rule-system.md).
- A migration that *weakens* an existing rule (changes its consequent value to a smaller $\leq_k$-element) is similarly breaking.
- A migration that changes the predicate-category structure (renaming predicates, changing morphism generators) breaks the $\mathcal{C}$-naturality of pre-existing content. Such migrations require federation-bridge-style translation.

## What the theorem requires

- $V_2$'s rule set contains $V_1$'s rule set as a subset.
- Both rule systems share the predicate-category $\mathcal{C}$ and value-domain $\mathbf{L}^\bowtie$.
- The substrate's [closure-rule system](../objects/closure-rule-system.md) version chain links $V_1$ to $V_2$ via `predecessor`.
- Per [settlement-determinism](settlement-determinism.md), both rule systems' closure operators are deterministic.

## Position

This theorem is the *additive* axis of the substrate's evolution discipline: it says that growing the rule system never costs the substrate prior content. It is one half of a pair — the *retractive* axis is handled by [model-supersession-as-forward-migration-corollary](model-supersession-as-forward-migration-corollary.md), which lifts this theorem to the case where a successor rule system disagrees with a predecessor's derivations by encoding the disagreement as bilattice $\top$-cells rather than as content removal. Together the pair give the substrate a complete evolution story: any rule-system change a captain may want to make compiles either to (a) a forward-compatible addition (this theorem, content-preserving by structure), (b) a supersession via $\top$-tagged disagreement (the corollary, content-preserving by paraconsistency), or (c) an explicit breaking-change recipe (per [migrate-rule-system](../morphisms/migrate-rule-system.md), audited as such). The substrate has no fourth option — every change is one of these three, and the first two preserve content automatically.
