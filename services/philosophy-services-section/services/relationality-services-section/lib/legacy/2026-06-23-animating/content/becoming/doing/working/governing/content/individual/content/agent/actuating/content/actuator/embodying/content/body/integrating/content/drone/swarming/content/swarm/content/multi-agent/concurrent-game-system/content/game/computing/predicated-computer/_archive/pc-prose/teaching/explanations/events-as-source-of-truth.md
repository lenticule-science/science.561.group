# Events are the source of truth; the working model is a replay artifact

Persistence in a substrate-shaped system tempts a reasonable mistake: build a working model in memory that is the substrate's "real" state, persist a periodic snapshot of that working model to disk, and treat the on-disk snapshot as authoritative for restart purposes. The event log, if there is one, becomes a debugging aid — a sequence of "things that happened" the developer can scan when a bug surfaces, but not load-bearing for the substrate's correctness. The working model and the snapshot are the substrate's state; the log is informational.

This shape has a particular failure mode that is both common and structurally inescapable. The on-disk snapshot is a *moment* — the working model at the time of the snapshot. Events that arrive after the snapshot but before the next snapshot are in the log but not in the snapshot. If the runtime restarts after such an event, the snapshot loads, the events appear to have vanished, and the substrate's behavior diverges from what its history says it should be. The fix is always the same: replay events that arrived after the snapshot's cutoff against the loaded state. Once you've written that fix, the events have become authoritative and the snapshot has become a cache. The original architecture was wrong; the implementation now reflects the substrate's actual structure.

The substrate's response is to make this structure the architecture from the start. Per [source-of-truth](../teaching/explanations/source-of-truth.md), the [event log](../objects/event-log.md) is authoritative; the working model is a replay artifact; snapshots are accelerators that the substrate could lose without losing information. Three properties realize the discipline:

- **Saving the substrate is preserving the log.** When a substrate persists, what it persists is the sequence of reified messages it has admitted. The working model is reconstructed on the next load; nothing else needs to be saved.
- **Loading the substrate is replaying the log.** Reconstruction is deterministic per [determinism](../teaching/explanations/determinism.md): the same log produces the same working model on any conforming runtime.
- **Snapshots are write-anytime, throw-away-anytime caches.** A substrate may write snapshots when it wants, with whatever frequency makes runtime restart fast enough. On load, the substrate restores the snapshot AND replays events with timestamp greater than the snapshot's cutoff. If the snapshot is missing or corrupt, the load falls back to a full replay.

The discipline is the structural realization of "the substrate's history is its state." A substrate that has admitted a particular sequence of messages, processed by a particular algebra, is in a particular state — and the state is recoverable from the messages and the algebra alone. Anything else is a derived view.

Several engineering consequences follow:

- **Replay determinism is a substrate-level property.** Per [hash-discipline](../teaching/explanations/hash-discipline.md), events are content-addressed: the event identifier is the canonical hash of the event's content. Two byte-identical events have the same identifier; appending the same event twice is idempotent. Combined with reducer purity (per [read-discipline](../teaching/explanations/read-discipline.md), reducers do not branch on substrate content) and elision determinism (the elision pass that filters superseded events from the replay stream is itself deterministic), replay produces byte-identical working models from byte-identical logs.
- **Multi-writer is structurally safe.** Two writers admitting events to the same log produce a sequence whose order is the substrate's append order; replay applies the events in append order; the resulting working model is consistent with the substrate's value-domain join applied across the writers' contributions. The substrate's CRDT-style convergence is operative because the log is the source of truth.
- **Replication is event-stream replication.** Per [replication](../teaching/explanations/replication.md), copying a substrate to another host is copying its event log. The destination replays the log; the working models converge. There is no "replicate the working model" operation; the working model is derived.
- **Schema migration is replay with a new reducer set.** When the substrate's reducer specifications change (a new closure rule is added, an old one is retired, a shape is revised), the substrate's working model can be regenerated by replaying the log under the new reducers. The log is unchanged; the derived state reflects the new specifications. This is the substrate's answer to "schema migration": the log is the schema-independent record; the working model is the schema-applied view.
- **Audit is replay-equivalent.** An auditor reconstructs the substrate's state at any past moment by replaying up to that moment. The audit's authority is the same as the substrate's authority: both rest on the log.

The discipline composes with the substrate's *elision* pass. Some events supersede earlier ones — a file-changed event supersedes the prior file-ingest for the same path; a retraction event supersedes the admission it retracts. The elision pass filters superseded events from the replay stream before reducer application, keeping the working model from accumulating no-longer-relevant content. Elision is a meta-operation on the event stream rather than a closure-rule application, because the substrate's algebra does not yet have a primitive for second-order rules over logs (per [holographic-projection](../learning/questions/holographic-projection.md), this is a research direction). The post-elision stream is still a deterministic function of the original log, so replay determinism holds.

Snapshots compose with elision in a particular way. A snapshot's cutoff is a timestamp; on load, the substrate restores the snapshot AND replays events with timestamp greater than the cutoff. The snapshot's content reflects the elision that applied at write time; the delta-replay reapplies elision against the post-cutoff events. Two substrates loaded from the same log under the same snapshot produce byte-identical working models — the snapshot is not a privileged artifact; it is a function of the log up to its cutoff.

The pattern composes with [reification](../teaching/explanations/reification.md) (every event in the log is a reified message), with [two-store-coherence](../teaching/explanations/two-store-coherence.md) (the predication-graph store and the event log are coherent because the predication-graph is derived from the event log, not maintained separately), with [canonical-form](../teaching/explanations/canonical-form.md) (events' content-addressing depends on canonical-form discipline), and with [federation-as-substrate-join](federation-as-substrate-join.md) (federation is event-stream exchange, with the substrate's algebra producing convergence at the receiver).

The discipline's hard edge is the refusal to maintain authoritative state outside the log. A runtime that maintains an in-memory counter, applies operations to the counter, and persists the counter periodically has erected a state the substrate is unaware of. The state will drift. The substrate's response is to put the counter in the log: every increment is a reified message, the counter's current value is a derived view, replay reconstructs it.

A substrate that has fully internalized this discipline has a single-question contract for state: *what is in the log?* Every other question — what is the working model, what does the snapshot contain, what does the cache hold — has the same answer: a function of the log. The substrate's state is its history.
