The system works as a generative harness: structured data → deterministic composition → rendered text → inference only where necessary.

**The datastore.** `knowledge-graph.json` is an EAVT (entity-attribute-value-transaction) store built by `install.js` via `generate-library-graph.js`. It contains 10,935 entities with 122,683 facts from all markdown frontmatter. Hooks MUST read from this datastore (`require('./datastore.js').load()`), NOT scan directories or parse files individually. The datastore query module is at `operations/engineering/fars/agentic/hooks/datastore.js`.

**Composition pipeline.** CLAUDE.md and AGENTS.md are composed by `generate-root-agentic-files.js` from component frontmatter. The `compose-environment.js` UserPromptSubmit hook composes per-turn context from the datastore: agent location, scoped records with descriptions, matched skills/commands, relevant terms with definitions inline. Install.js composes session-level context. One command regenerates everything: `node operations/engineering/fars/harnesses/agentic/claude-code/install.js`.

**Why:** Hand-maintaining indexes doesn't scale and creates contradictions. Deterministic composition eliminates desync.

**How to apply:** When adding new components, write one file with correct frontmatter in `operations/engineering/fars/agentic/`. Run `install.js`. Don't hand-edit CLAUDE.md or AGENTS.md. When building hooks that need entity data, use the datastore, not file scanning.
