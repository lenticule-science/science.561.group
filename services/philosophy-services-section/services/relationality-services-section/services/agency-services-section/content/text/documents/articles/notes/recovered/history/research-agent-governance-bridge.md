**Action:** Synthesize findings from the completed disambiguation and practice-text work into a deeper analysis of how governance theory should inform harness design.

**Why:** The multi-agent-orchestration-in-practice text identifies mappings (delegation invariants → dispatch constraints, roles → agent definitions, offices → agent persistence), but these are observations, not yet a design specification. This task asks: given the theory, what *should* the harness do that it doesn't yet?

**Key questions:**
- Should agent definitions carry Hohfeldian position frontmatter (powers, duties, privileges, immunities)?
- Can role subsumption ordering generate the agent hierarchy instead of hand-maintaining it?
- What does investiture look like for software agents — is `install.js` the constitutive speech act?
- How does the four-invariant delegation structure constrain what `/dispatch` and `/orchestrate` can do?

**Dependency:** This task depends on having clean terms and the practice text, which are now done. It also benefits from the orchestration/choreography survey.
