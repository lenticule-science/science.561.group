A valid FARS substrate encodes a predication fibration $(\mathbf{FOUR}, \mathcal{C}, E)$ as a directory of frontmatter-markdown files.
The following requirements are derived from the predication-fibration structure with no exemptions.

## Entity set (E)

**R1.** Every `.md` file in the substrate is an [entity](../../structures/entity.md) and a member of $E$.
No file is excluded.

**R2.** The structural kind of an entity is determined by its directory path, not by any frontmatter key: - Files in `structures/` are structures. - Files in `transformers/` are transformers — objects of $\mathcal{C}$. - Files in `concepts/` are concepts. - Other directories establish further kinds as the substrate requires.

## Predicate category (C)

**R3.** Every file in a `transformers/` directory is an object of $\mathcal{C}$ and a member of $\mathrm{Ob}(\mathcal{C})$.

**R4.** The morphisms of $\mathcal{C}$ are generated by four canonical transformer predicates: [specializing](../../transformers/specializing.md), [conversing](../../../code/transformers/conversing.md), [projecting-to-subject](../../../code/transformers/projecting-to-subject.md), and [projecting-to-object](../../../code/transformers/projecting-to-object.md).
These four classes exhaust all natural bottom-preserving bilattice homomorphisms between predication fiber algebras under $\mathrm{Sym}(E)$-equivariance with $|E| \geq 3$ (predicate-generator-exhaustiveness).
No other morphism classes between transformers are admitted.

**R5.** A transformer $q$ carries morphism cells in its frontmatter only using the four generator transformers as keys.
These cells have transformer-typed values.

## Predication cells

**R6.** A frontmatter entry `q: e₂` in file $e_1$ asserts the predication cell $(e_1, q, e_2)$ at [true](../teaching/explanations/true.md).
Absence of the entry leaves the cell at [mystery](../../../bilattice/mystery/mystery.md).

**R7.** Every frontmatter key (other than `name` and `description`) must be the slug of a transformer in $\mathrm{Ob}(\mathcal{C})$ — a file in some `transformers/` directory of the substrate.

**R8.** Every frontmatter value that is an entity reference must be the slug of a member of $E$ — a `.md` file in the substrate.
List-valued frontmatter entries assert one cell per list element.

**R9.** The values of `name` and `description` are string literals, not entity references.
`name` records the canonical human-readable label for the entity; `description` records a one-sentence declarative statement of what the entity is.
These two keys are valid in every entity's frontmatter without requiring a corresponding transformer in $\mathcal{C}$.

## No metadata

**R10.** There are no metadata keys, pre-approved exemptions beyond `name` and `description`, or "bootstrap exceptions."
Every frontmatter key other than `name` and `description` must satisfy R7.
A key that does not name a transformer in $\mathcal{C}$ is a lint violation, not a permitted exception.

## Self-application

**R11.** The FARS theory is itself a valid FARS substrate.
The entities describing the FARS theory — its structures, transformers, and concepts — are members of $E$.
The four generator transformers are members of $\mathrm{Ob}(\mathcal{C})$.
The theory encodes itself: the system and the theory are the same object.

**R12.** Any claim, property, or relationship that is expressible as a predication cell MUST be expressed as a predication cell in frontmatter, not only as prose in the body.
The body may express the same data in human-readable form, but meaningful data must not live only in prose.

**R13.** No `.md` file in the substrate contains a level-1 heading (`# ...
`) in its body.
The canonical name is recorded in `name:` frontmatter (R9); a body H1 is redundant and misleads processors that treat the first heading as the document title.
H2 and deeper headings are permitted in the body.
