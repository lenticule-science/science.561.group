Two related principles:

**1. Synthesize, don't catalog.** When mining triage into records, the new record must stand alone. Don't list "go read these 30 files." Read the source, decide what's valuable, write it as if the source didn't exist.

**2. Update existing records, don't accumulate new ones.** The less deterministic a record is, the more it should absorb new knowledge. Tasks are specific (don't change). Projects are broad (update to be more specific). Memories should be updated rather than accumulated. Before creating any new file, check if an existing one at a higher abstraction level could absorb the information.

**Why:** The user has corrected both patterns: creating catalog files that just reference triage (3 idea files were pure catalogs), and creating new memories/records when existing ones overlap. New files create noise and fragmentation. Making an existing record more precise IS the work.

**How to apply:** Before creating a new record: (1) check if an existing record covers the topic, (2) if so, update it. Before mining triage: (1) read the source, (2) write the value into a self-standing record. The determinism gradient: tasks (don't change) → plans → objectives → projects → goals → memories (most appropriate to update).
