# Objects

The parent-level formal models the markdown-vault knowledge system commits to, before any predication-categorical specialisation. Three objects suffice:

- [vault](../../../../../../../../../../../engineering-science-services-section/services/computer-science-services-section/services/markdown-services-section/content/text/glossary/terms/vault.md) — the formal model of a vault as a directory tree of typed notes plus a relation graph derived from frontmatter.
- [note](../../research/2026/07/31/lenticule-import/animating/content/becoming/doing/working/governing/knowing/content/knowledge-science/systems/archive/note.md) — the formal model of a single note record (frontmatter + body + path).
- [relation-graph](../../research/2026/07/31/lenticule-import/animating/content/becoming/doing/working/governing/knowing/content/knowledge-science/systems/archive/relation-graph.md) — the formal model of the typed relation graph derived from notes' frontmatter edges.

These are the parent-side objects the [predicated markdown-vault knowledge system](../../research/2026/07/31/lenticule-import/animating/content/becoming/doing/working/governing/knowing/content/knowledge-science/systems/archive/theories/predicated-markdown-vault-knowledge-system) refines into typed-note-as-predication-cell, predicated-note, and predication-graph respectively. The relationship is *specialisation*, not *replacement*: anything true of these objects is true of their predicated refinements; the predicated theory adds structure (predication cells, the bilattice valuation) on top.
