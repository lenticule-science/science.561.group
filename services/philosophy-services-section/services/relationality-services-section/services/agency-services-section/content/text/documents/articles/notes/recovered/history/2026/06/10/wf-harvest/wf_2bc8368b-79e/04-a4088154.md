**1. FATAL — Wave 1 violates the plan's own wave definition: it has no production proof.**
*Attacked element:* "Waves, not phases — each wave is provable in production" vs. the Wave 1 scope (completed lib + site-morphism carrier + incremental settling + audit fixes + API/docs + serialization boundary + workbench app + settling daemon).
*Argument:* Nothing in Wave 1 touches the live wire; the first production contact is Wave 2.1. So Wave 1 is a big-bang greenfield phase — three bodies and two brand-new mathematical structures built to completion against no consumer — hidden inside a plan whose decided frame is "rewiring is the route." This is precisely the cleanroom-beside pattern the frame rejects, relabeled. The strangler-fig discipline that justified choosing rewiring over greenfield does not begin until the second wave, by which point the largest design decisions (carrier shapes, daemon API) are already frozen without a live oracle.
*Amendment:* Pull Wave 2.1 (replacing newsroom's four settling functions — claimSetsFromTrace, assertionFromClaim, newsClaimFromTraceEntry, stableJsonKey — with bedrock settling) into Wave 1 as the lib's acceptance gate. Split Wave 1 into 1a (lib core + incremental settling, proved by newsroom parity in production) and 1b (daemon + workbench, proved by serving the same sections the wire publishes).

**2. SERIOUS — Wave 3.2 re-founds web-server in place, contradicting both "old code is never improved, only vacated" and the human's explicit 06-10 rejection of the seam strategy.**
*Attacked element:* Wave 3.2: "Re-found web-server's six old-kernel imports on meme-topology(+addressing). Correctness propagates through all ~25 web packages through one seam."
*Argument:* This is, word for word, the rejected first plan of 06-10 ("re-found X on meme-topology as the seam through which correctness propagates to dependents" — "THE PACKAGE DECOMPOSITION ITSELF IS THE DISEASE… there is no seam"). lib/web-server's module boundaries, request-as-trace plumbing, and platform modules were all shaped by the old kernel; swapping six imports keeps the diseased decomposition and improves old code, which the plan forbids one paragraph earlier. The plan cannot hold both doctrines.
*Amendment:* Either (i) birth a new web substrate package on bedrock and vacate web-server package-by-package, or (ii) explicitly record Wave 3.2 as a sanctioned doctrine exception with the reason (25-package fan-out makes vacating prohibitively serial) — but then the "never improved, only vacated" aphorism must be amended, because it is currently false.

**3. SERIOUS — The parity oracle is only defined for deterministic surfaces; the plan tacitly extends it to waves where it cannot hold, and where it does hold it enshrines accidental behavior. (Steelman (a) partially wins.)**
*Attacked element:* Wave 2.1 "verify the wire publishes identically (tests + before/after diff of all public surfaces)"; Wave 3.1 swarm extraction implicitly inheriting the same proof discipline.
*Argument:* Two failure modes. (i) Byte-identity in Wave 2.1 imports accidents as spec: newsroom's stableJsonKey and meme-topology-addressing's termKey are different canonical encodings (termKey is type-prefixed non-JSON); honoring "identical" means either replicating the old encoding inside the bedrock or shimming it forever. (ii) Wave 3.1 severs lib/swarm, whose behavior routes through LLM observers and agent loops — nondeterministic; "publishes identically" is unfalsifiable there, so the strangler discipline silently has no proof obligation exactly at the riskiest cut. This is the strongest form of the greenfield steelman: every live cut needs a parity argument, and where parity is undefinable, rewiring is slower than greenfield without being safer.
*Amendment:* Declare per-wave proof obligations now: Wave 2 = codec-level contract (IPTC/feed spec conformance + named editorial invariants such as GateReport semantics), with diffs triaged into essential/accidental residue; Wave 3 = trace-level contract tests (admission gates, charge folding, joinKnowledge semantics), never output identity.

**4. SERIOUS — The general-residuated-lattice charge is a decided frame with no consumer in any wave and open convergence mathematics. (Steelman (b) is stronger than the plan.)**
*Attacked element:* The FOUR-as-shadow doctrine ("the general charge… should be the primary carrier") as a Wave 1 bedrock demand.
*Argument:* Every consumer through Wave 5 — news gates, archive statuses, swarm charges, web flags — is FOUR-valued. The proved results (four-regime dichotomy, CRDT/CALM, finite closure realization) live in the FOUR/finite setting; the q-fuzzy general case is where the status ledger says "draft/sketch/open" (ω₁-cofinal Tarski–Lawvere convergence is explicitly the deepest open piece). Making the unproved general case the *primary carrier* of the package everything stands on means every downstream signature pays a generality tax for a light source that has not moved and cannot yet be shown to converge. The cosmogony note itself offers the correct fallback ("at minimum the API should be shaped so that generalizing later is a widening") — and the plan never says which of the two it commits to. That ambiguity is unpriced scope.
*Amendment:* Commit in writing to the fallback: FOUR-primary public API; value-category kept opaque/parametric internally; one test asserting the widening path compiles. Cut the general carrier from Wave 1.

**5. SERIOUS — The site-morphism carrier is Wave 1 critical path with zero consumers before Wave 4 and no proved theorem behind it. (Steelman (c) mostly wins.)**
*Attacked element:* Wave 1.1's site-morphism carrier as "the mathematical home for codecs, federation, parsing, actuation."
*Argument:* Codec-as-geometric-morphism appears in the program map's *Implications* section, not its status ledger — it is a framing, not a proved result (Verdier, its nearest neighbor, is itself sketch-level). The first forcing function is Wave 4.1's news-codecs retrofit; Wave 2's production proof needs only settling + addressing. Meanwhile news-codecs already works as a pure, zero-dep engineering convention — the plan's own facts say it is the *healthiest* package in the vertical. A carrier designed in Wave 1 for four prospective consumers (one of which, actuation, has no implementation anywhere) will be designed against imagination and ossify wrong, then Wave 4 will deform around it.
*Amendment:* In Wave 1, produce only an interface sketch validated against news-codecs-iptc as the single worked example; land the carrier in Wave 4 when the retrofit can falsify it. Codecs remain conventions until the residue-measurement claim is demonstrated on one real round trip.

**6. SERIOUS — The status-recovery scheme is circular and violates Way 4's own admission discipline.**
*Attacked element:* The "statuses are lower bounds" caveat as load-bearing justification, plus Wave 2.2 / continuous-thread archive status-settling.
*Argument:* The plan leans on sketch-status mathematics (Verdier composition, incremental-settling naturality, MHC) as if proved-pending-bookkeeping, and plans to *upgrade* those statuses using the daemon whose design those same results justify — the tool validates its own foundations. Worse, the recovery witness ("a later note builds on a sketch without flagging gaps") is citation, not verification; unflagged downstream use is exactly the weak-provenance input Way 4 says to quarantine, not fold. The plan applies the caveat only in the optimistic direction.
*Amendment:* Before Wave 1 freezes any API, hand-verify the two or three results the bedrock actually stands on (finite/Scott-continuous Tarski–Lawvere convergence; locality-preserves-sheafhood at the finite regime; incrementality of the iteration). Archive re-settling may only ever emit "potential," never auto-promote to proved.

**7. SERIOUS — The Phase C judge panel has been quietly downgraded from independent design to incumbent review, insulating the plan from the only process that could catch findings 1–5.**
*Attacked element:* Wave 0: "the panel's job is to attack and improve it (decomposition AND route), not design from scratch."
*Argument:* The 06-10 agreement was several *independent* decompositions from different pressures, adversarially compared — that is what the 1280-line capabilities map and the atlas were built to feed. Anchoring every judge to the incumbent proposal converts the panel into a red-team of a fixed frame (this very document), which cannot surface a better decomposition, only better arguments about this one. The plan was written by the same session that decided the frames it instructs the panel not to revisit.
*Amendment:* At least one panel member produces a blind decomposition from the atlas alone, before reading the 06-11 plan; the comparison is then incumbent-vs-blind, not incumbent-vs-nothing.

**8. SERIOUS/MINOR — The ecology vision is pulling sketch-grade actuation machinery into Waves 1–4 scope, and the economic loop has zero evidence behind it. (Steelman (d) half-wins.)**
*Attacked element:* Actuation/MHC named in the Wave 1 carrier's purpose and Wave 4.2's "admission discipline pattern for anything that actuates"; Wave 5's keyword-research loop.
*Argument:* MHC is sketch-status; there are no effectors in production and none planned before Wave 5+; drones and printer farms are appearing in the scope sentence of the bedrock's most critical Wave 1 structure. Separately, the ecology's reproduction step ("spawn mills when settled demand persists") presumes demand readings for which there is no recorded evidence the wire has *any* reception traffic today. Where the steelman fails: "one daemon, many mounts" survives the attack — Wave 2 already has two genuine domains (news + archive), so multi-tenancy is consumer-driven, not vision-driven.
*Amendment:* Strike actuation/MHC from all Wave 1–4 scope language (keep it as a recorded future conduit class); make Wave 5.2 conditional on a measured baseline of webmention/citation intake, gathered as a Wave 3-4 continuous thread.

**9. MINOR — Governance questions are sequenced one wave too late.**
*Attacked element:* "Governance questions… needed before Wave 2 ships."
*Argument:* Questions 1 and 2 (package scope; where new packages live while old ones occupy lib/) block Wave 1's own births — the workbench app, the daemon service, and any extracted module all need a scope and a directory on day one. Deferring them to Wave 2 guarantees either a mid-wave rename or a unilateral agent decision of exactly the kind question 3 exists to prevent.
*Amendment:* Move questions 1–2 to a Wave 1 entry gate.

**10. MINOR — The daemon API treats settling regimes as operational scheduling facts when only two regimes are realizable in a running process.**
*Attacked element:* "a daemon in the transfinite regime needs different scheduling than one in the strict regime" (program map item 4, inherited by Wave 1.3).
*Argument:* A persistent service can execute finite and Scott-continuous (ω-limit) iterations; transfinite and aperiodic regimes are classification mathematics, not schedulable behaviors — and the four-regime dichotomy says regime is determined by the rule-language fragment, which the daemon controls at mount time. Baking regime into the service contract is speculative surface.
*Amendment:* Regime is a *reading* over a mounted topology (a diagnostic), not a daemon scheduling mode; the daemon's contract admits only rule fragments whose convergence is proved.

(c) wins on sequencing, not on principle — the math may well be right, but Wave 1 is the wrong wave (finding 5). (d) half-wins — actuation/economics are vision-pulled, but daemon multi-tenancy is legitimately consumer-driven (finding 8). (e) substantially wins — the plan's load-bearing trust in sketch-status results is circular and self-confirming (findings 6, 7).
