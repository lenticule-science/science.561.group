# Arenas, Plays, and Strategies

## Abstract

An arena is the mathematical space in which play can occur. It is not a score
table, a rules document, a player list, or a software object. At its most precise
concurrent-game-theoretic form, an arena is a polarized event structure equipped
with symmetry:

```text
A = (E_A, <=_A, #_A, pol_A, Sym_A).
```

The events are possible move occurrences. The causal order says which moves must
precede which other moves. The conflict relation says which moves cannot
co-occur. The polarity function separates moves of the environment/opponent from
moves of the system/player. The symmetry groupoid identifies event occurrences
which differ only by inessential choice of name, copy, thread, participant, or
other structural presentation. From this object one derives configurations
(reachable positions), plays (histories or secured linearizations of positions),
strategies (lawful policies over plays or event-structure maps into interaction
arenas), and morphisms between arenas.

This paper gives a self-contained definition of arenas and their constituent
objects, then organizes the surrounding theory: ludic loci and designs, play as
configuration history, strategy as receptive/innocent/symmetric behavior,
categorical composition by interaction and hiding, settlement by monotone
closure, and cultural readings of play as predicates over arenas rather than as
primitive data. The goal is a public mathematical account. Implementations may
instantiate these definitions, but no implementation is a definition.

## 1. Introduction

Game theory, game semantics, ludics, and concurrency theory all need a
distinction between a game as a mathematical space and a play as one passage
through that space. Ordinary game descriptions often blur these levels. Chess,
for example, is not a sequence of moves; a chess play is. A concurrent protocol
is not one interleaving of messages; an execution trace is. A proof interaction
is not merely a static sequent; it is a policy for surviving tests. The concept
of an arena is the object that restores this separation.

In sequential game semantics an arena is often presented as a structured set of
moves with polarity and enabling. In concurrent game semantics the better object
is an event structure: it remembers that two moves may be independent rather
than merely ordered one way or the other. That distinction matters. A total
sequence cannot tell the difference between true concurrency and arbitrary
interleaving. An arena can.

The paper adopts the concurrent definition as primary:

```text
Arena = polarized prime event structure with symmetry.
```

The sequential Hyland-Ong style arena is recovered as a special case in which
the dependency relation is tree-like and the plays are justified sequences. The
ludic design is recovered as a focused, locus-addressed strategy presentation.
The social and aesthetic notions of play - magic circle, paidia/ludus, flow,
deep play - are then read as predicates, measurements, or valuations on arenas
and plays, not as additional primitive components of the arena.

## 2. Mathematical Preliminaries

### 2.1 Relations and finite downsets

Let `E` be a set. A relation `<=` on `E` is a partial order when it is reflexive,
antisymmetric, and transitive. For `e in E`, write

```text
down(e) = { d in E | d <= e }.
```

In event-structure semantics one typically requires finite causes:

```text
for all e in E, down(e) is finite.
```

This condition ensures that an event has a finite enabling history.

### 2.2 Conflict relations

A binary relation `#` on `E` is a conflict relation when it is irreflexive and
symmetric:

```text
not (e # e)
e # d  =>  d # e.
```

In a prime event structure, conflict is hereditary upward along causality:

```text
e # d and d <= d'  =>  e # d'.
```

If an event conflicts with a cause of another event, then it conflicts with that
event as well. Conflict therefore propagates into the future.

## 3. Event Structures

### Definition 3.1: Prime Event Structure

A prime event structure is a triple

```text
P = (E, <=, #)
```

where:

1. `E` is a set of events;
2. `<=` is a partial order on `E` with finite causes;
3. `#` is an irreflexive symmetric conflict relation;
4. conflict is hereditary:

```text
e # d and d <= d'  =>  e # d'.
```

Events are occurrences, not states. An event may be a move, a message, an
observation, a claim, a refutation, a resource use, or a termination act,
depending on the interpretation.

### Definition 3.2: Configuration

A configuration of `P` is a finite subset `x subseteq E` satisfying:

```text
down-closed:   e in x and d <= e  => d in x
conflict-free: not exists e,d in x with e # d.
```

Write `Conf(P)` for the set of finite configurations.

Configurations are positions. They forget the order in which independent events
were observed. This is the key advantage of event structures over plain traces:
they separate causal order from mere recording order.

### Proposition 3.3: Prefix Closure of Configurations

If `x in Conf(P)` and `y subseteq x` is down-closed, then `y in Conf(P)`.

Proof. Since `y` is assumed down-closed, it satisfies the first configuration
axiom. If `e,d in y` and `e # d`, then `e,d in x`, contradicting that `x` is
conflict-free. Thus `y` is conflict-free. Since `x` is finite, so is `y`. Hence
`y` is a configuration.

### Definition 3.4: Enabled Event

For `x in Conf(P)`, an event `e notin x` is enabled at `x` when:

```text
down(e) \ {e} subseteq x
and
for all d in x, not (d # e).
```

Write:

```text
En_P(x) = { e in E \ x | e is enabled at x }.
```

### Proposition 3.5: Legal Extension Criterion

For `x in Conf(P)` and `e notin x`,

```text
x union {e} in Conf(P)  iff  e in En_P(x).
```

Proof. If `x union {e}` is a configuration, then it is down-closed, so every
proper cause of `e` lies in `x`; it is conflict-free, so no element of `x`
conflicts with `e`. Conversely, if the enabling conditions hold, adding `e`
preserves down-closure and introduces no conflict. Thus the extended set is a
configuration.

## 4. Polarity

### Definition 4.1: Polarized Event Structure

A polarized event structure is a prime event structure equipped with a polarity
map:

```text
pol : E -> {O, P}.
```

The two polarities are read as:

```text
O = Opponent, environment, input, challenge, negative move
P = Player, system, output, response, positive move.
```

The letters do not designate human persons. They designate the side of an
interaction boundary. In a protocol, `O` may be the environment and `P` the
process. In a proof game, `O` may be the test and `P` the proof. In a social
game, either side may be occupied by many agents after symmetry is added.

### Definition 4.2: Polarity Dual

The dual of a polarized event structure is obtained by swapping polarity:

```text
P^perp = (E, <=, #, pol^perp)
```

where:

```text
pol^perp(e) = P if pol(e) = O
pol^perp(e) = O if pol(e) = P.
```

The causal and conflict structures are unchanged.

### Proposition 4.3: Duality Is Involutive

```text
(P^perp)^perp = P.
```

Proof. Polarity is swapped twice; the event set, order, and conflict relation
are not changed.

## 5. Symmetry

### 5.1 Why symmetry is part of the arena

Without symmetry, event structures are too concrete. If a game contains two
identical copies of a resource, two alpha-equivalent names, two indistinguishable
threads, or two representatives of one structural role, then the raw event set
contains distinctions that should not change the play's meaning. Symmetry marks
which distinctions are presentational.

The mathematically clean form is a groupoid of isomorphisms between
configurations, as in event structures with symmetry. A stricter but often
sufficient special case is a group of global automorphisms of the event
structure. This paper states the global version first because it is concise, then
records the groupoid refinement.

### Definition 5.2: Global Symmetry

Let `P = (E, <=, #, pol)` be a polarized event structure. A global symmetry of
`P` is a bijection

```text
g : E -> E
```

such that for all `e,d in E`:

```text
pol(g e) = pol(e)
e <= d iff g(e) <= g(d)
e # d  iff g(e) # g(d).
```

The global automorphisms of `P` form a group, written:

```text
Aut(P).
```

### Definition 5.3: Symmetry Groupoid

A symmetry groupoid `Sym(P)` is a groupoid whose objects are finite
configurations and whose arrows are structure-preserving bijections between
configurations. Concretely, an arrow

```text
theta : x ~= y
```

is a bijection `theta : x -> y` preserving polarity, causality restricted to the
configuration, and conflict inherited from the ambient event structure.

Global symmetries induce such a groupoid by restriction. Event-structure
symmetry is more general because an isomorphism may exist locally between
configurations even when it does not extend to one global automorphism of all
events.

### Proposition 5.4: Symmetry Preserves Configurations

If `g in Aut(P)` and `x in Conf(P)`, then

```text
g[x] in Conf(P).
```

Proof. Finiteness is preserved by bijection. If `e in g[x]` and `d <= e`, write
`e = g(e0)`. Since `g` preserves and reflects causality,
`g^{-1}(d) <= e0`; down-closure of `x` gives `g^{-1}(d) in x`, hence
`d in g[x]`. If `e,d in g[x]` conflicted, their inverse images would conflict in
`x`, impossible.

## 6. Arena

### Definition 6.1: Arena

An arena is a polarized prime event structure with symmetry:

```text
A = (E_A, <=_A, #_A, pol_A, Sym_A).
```

Here:

1. `E_A` is the event set;
2. `<=_A` is causal dependence;
3. `#_A` is conflict;
4. `pol_A : E_A -> {O,P}` is polarity;
5. `Sym_A` is a symmetry groupoid, or in the strict global presentation a
   subgroup `Sym_A <= Aut(E_A, <=_A, #_A, pol_A)`.

An arena is a space of possible interaction. It does not contain a selected
strategy, actual play, payoff, objective, or winner.

### Definition 6.2: Position Space of an Arena

The position space of an arena is:

```text
Pos(A) = Conf(E_A, <=_A, #_A).
```

Thus the reachable positions of a game are generated by causality and conflict.

### Definition 6.3: Legal Moves of an Arena

For a position `x in Pos(A)`, the legal moves are:

```text
Legal_A(x) = En_A(x).
```

The legal `O`-moves and `P`-moves are:

```text
Legal_A^O(x) = { e in Legal_A(x) | pol_A(e) = O }
Legal_A^P(x) = { e in Legal_A(x) | pol_A(e) = P }.
```

### Definition 6.4: Dual Arena

The dual arena is:

```text
A^perp = (E_A, <=_A, #_A, pol_A^perp, Sym_A).
```

The symmetry data is unchanged because the same bijections preserve the swapped
polarity.

### Definition 6.5: Tensor or Parallel Product

For arenas `A` and `B`, the independent parallel product is:

```text
A || B =
  (E_A + E_B,
   <=_A + <=_B,
   #_A + #_B,
   pol_A + pol_B,
   Sym_A x Sym_B).
```

There is no cross-causality and no cross-conflict in the pure tensor. Specific
interfaces may add synchronization, hiding, or extra conflict, but that is not
part of the bare product.

### Proposition 6.6: Configurations of the Parallel Product

For independent parallel product,

```text
Conf(A || B) ~= Conf(A) x Conf(B).
```

Proof. A finite subset of `E_A + E_B` decomposes uniquely into its `A`-part and
`B`-part. Since order and conflict are componentwise, down-closure and
conflict-freeness hold exactly componentwise.

## 7. Play

### 7.1 Position versus history

A configuration is a position. A play is a history. In a concurrent arena, a
single position may have many histories because independent events may be
recorded in different orders. Treating histories as the primitive object erases
concurrency. Treating configurations as the primitive object erases observation
order. A full account needs both.

### Definition 7.2: Secured Linearization

Let `x in Conf(A)`. A secured linearization of `x` is a sequence

```text
p = e_1 ... e_n
```

such that:

```text
{e_1,...,e_n} = x
```

and for every prefix

```text
x_k = {e_1,...,e_k},
```

we have:

```text
x_k in Conf(A).
```

### Definition 7.3: Play

A finite play in arena `A` is a secured linearization of some finite
configuration of `A`.

Equivalently, a sequence `p = e_1 ... e_n` is a play iff:

1. no event repeats;
2. each event is enabled when it occurs:

```text
e_k in En_A({e_1,...,e_{k-1}})
```

for every `1 <= k <= n`.

The final position of a play is:

```text
|p| = {e_1,...,e_n}.
```

### Proposition 7.4: Plays Are Exactly Legal Growth Paths

A sequence is a play iff it starts at the empty configuration and grows by legal
extension at every step.

Proof. This is immediate from Proposition 3.5 applied to each prefix.

### Definition 7.5: Symmetry of Plays

For a global symmetry `g`, define:

```text
g . (e_1 ... e_n) = g(e_1) ... g(e_n).
```

By Proposition 5.4 and preservation of enabling, this is again a play. In the
groupoid presentation, play symmetry is defined by transporting finite
configuration histories along compatible configuration isomorphisms.

## 8. Strategies

### 8.1 Strategy as lawful behavior

A strategy is not a function from positions to moves in the naive sense. That
view is too sequential and too deterministic. In concurrent games a strategy is
itself an event structure whose events are the strategy's internal move
occurrences, mapped into an arena. It may expose concurrency, causal dependence,
and nondeterministic branching.

There is nevertheless a useful play-set shadow: a strategy determines the set of
plays it admits. The event-structure account is primary; the play-set account is
its extensional trace.

### Definition 8.2: Prestrategy

A prestrategy on arena `A` is an event structure `S` equipped with a polarity-
preserving map of event structures

```text
sigma : S -> A.
```

The map sends each strategy event to the arena event it realizes and preserves
configurations:

```text
x in Conf(S)  =>  sigma[x] in Conf(A).
```

It is locally injective on configurations:

```text
s,t in x and sigma(s) = sigma(t)  =>  s = t.
```

### Definition 8.3: Receptivity

A prestrategy `sigma : S -> A` is receptive when it cannot refuse an enabled
Opponent move. Formally, for every `x in Conf(S)` and every `a in Legal_A^O(sigma[x])`,
there exists a unique `s notin x` such that:

```text
x union {s} in Conf(S)
sigma(s) = a.
```

Receptivity is what makes a strategy a genuine behavior under tests. It may
choose its own Player moves; it must accept the arena's legal Opponent moves.

### Definition 8.4: Innocence

Innocence says that the strategy introduces no illicit dependence on hidden
history. In event-structure form, causal dependence in `S` must be justified by
causal dependence visible in the arena except where the dependence is a Player
choice made by the strategy.

For the finite arena theory used in this paper, take innocence to be the
following two-part condition.

First, the strategy may not create new Opponent causality:

```text
s ->_S t and pol_S(t) = O  =>  sigma(s) ->_A sigma(t).
```

Second, every Player causal dependence introduced by the strategy must be
anchored in the visible arena history at the same interface:

```text
s ->_S t and pol_S(t) = P
  => sigma(s) <=_A sigma(t) or pol_S(s) = O.
```

where `->_S` and `->_A` denote immediate causality. The excluded case is the
one in which a Player response may depend on an Opponent challenge. More refined
formulations in the event-structure literature distinguish positive and negative
causal components more finely; the purpose is always the same: Opponent behavior
is inherited, Player behavior is justified, and hidden history cannot be used as
an extra state variable.

### Definition 8.5: Symmetric Strategy

Let `A` be an arena with symmetry. A strategy is symmetric when its behavior is
stable under the arena symmetry. In the play-set shadow, if `P_sigma` is the set
of plays admitted by the strategy, then:

```text
p in P_sigma and theta : p ~= q in Sym_A  => q in P_sigma.
```

In event-structure form, this is expressed by lifting arena symmetries along
`sigma` to isomorphisms of strategy configurations. Strategy equivalence is then
taken modulo these symmetry witnesses.

### Definition 8.6: Strategy

A strategy on arena `A` is a receptive, innocent, symmetric prestrategy:

```text
sigma : S -> A.
```

Its extensional play set is:

```text
Plays(sigma) = { sigma[x] with a secured order | x in Conf(S) }.
```

This set is prefix-closed, receptive to Opponent extension, and closed under
arena symmetry.

## 9. Morphisms and the Arena Category

### Definition 9.1: Interaction Arena

A strategy from arena `A` to arena `B` is a strategy on the interaction arena:

```text
A^perp || B.
```

The dual on `A` reverses the direction of interaction: moves offered by `A` as
outputs become inputs to the strategy, and conversely.

### Definition 9.2: Morphism of Arenas

A morphism

```text
A -> B
```

is an equivalence class of strategies

```text
sigma : S -> A^perp || B
```

modulo the symmetry groupoids of the arenas and of the strategy event structure.

### Definition 9.3: Identity

The identity morphism on `A` is copycat:

```text
id_A : A -> A.
```

It is the strategy on `A^perp || A` that reflects each move on one side by the
corresponding move on the other side, respecting causality and symmetry.

In ludics this same role is played by Fax: the identity design which transports
interaction across a locus without changing its content.

### Definition 9.4: Composition

Given

```text
sigma : A -> B
tau   : B -> C,
```

their composite is obtained by:

1. placing the strategies in parallel;
2. synchronizing the `B` and `B^perp` interfaces;
3. hiding the internal `B` events.

Symbolically:

```text
tau o sigma = hide_B (sigma ||_B tau).
```

The hidden interaction is not discarded as meaningless; it is internal
communication. What remains externally visible is a strategy

```text
A -> C.
```

### Theorem 9.5: Arenas and Strategies Form a Category

With arenas as objects, equivalence classes of receptive innocent symmetric
strategies as morphisms, copycat identities, and interaction-plus-hiding
composition, one obtains a category of arenas.

Proof sketch. Copycat is receptive and innocent, and behaves neutrally under
interaction because every external move is forwarded to its dual occurrence.
Composition preserves receptivity because an external Opponent move is accepted
by the outer strategy and propagated through the synchronized interface.
Composition preserves innocence because newly introduced causal dependencies are
either visible external dependencies or hidden internal synchronization
dependencies eliminated by hiding. Associativity follows from associativity of
parallel composition and functoriality of hiding up to the strategy equivalence
relation. Full proofs are the substance of the concurrent-strategy construction
of Rideau-Winskel and the event-structure game accounts by
Castellan-Clairambault-Rideau-Winskel.

## 10. Loci, Designs, and Ludic Arenas

### 10.1 Locus trees

Ludics presents interaction at addressed loci. Let

```text
Loc = N*
```

be the tree of finite natural-number sequences. The root is `epsilon`; child
extension is `xi.i`; prefix order is:

```text
xi <=_pre zeta  iff  xi is a prefix of zeta.
```

A locus is not yet an event. It is an address where an action may occur.

### Definition 10.2: Ludic Action

A ludic action is one of:

```text
(+, xi, I)      positive action at locus xi opening finite ramification I
(-, xi, I)      negative action at locus xi opening finite ramification I
dagger_xi       Daimon, the terminating positive action
```

where:

```text
I subset_fin N.
```

### Definition 10.3: Design

A design is a finite, coherent system of actions over a locus tree. For the
arena-theoretic presentation, it is convenient to treat a design as a finite
partial valuation:

```text
D : Loc partial-> {none, positive, negative, daimon}.
```

Its support is:

```text
supp(D) = { xi | D(xi) != none }.
```

Coherence requires that supported loci form a finite forest closed under the
justification needed by the actions, and that polarity alternates along
chronicles.

### Definition 10.4: Chronicle

A chronicle of a design is a maximal branch:

```text
a_1 ... a_n
```

such that:

1. loci move by unit child steps;
2. polarity alternates;
3. each next child lies in the previous action's ramification;
4. the branch ends at Daimon or at a leaf.

Chronicles are the ludic counterpart of plays. A design is determined by its
compatible family of chronicles.

### Definition 10.5: Behaviour

Given a class `X` of designs, define orthogonality:

```text
D perp E  iff  the interaction of D and E converges.
```

Then:

```text
X^perp = { E | for all D in X, D perp E }
X^(perp perp) = (X^perp)^perp.
```

A behaviour is a biorthogonally closed class:

```text
B = B^(perp perp).
```

This is the ludic form of a semantic type: not a syntactic formula, but a active
class of designs under tests.

### Proposition 10.6: Design-Induced Arena

Every finite design induces a finite arena. Its events are the supported loci:

```text
E_D = supp(D).
```

Causality is prefix dependence:

```text
xi <=_D zeta  iff  xi <=_pre zeta.
```

Polarity is read from the action at the locus. Conflict is generated by branch
incompatibility: two loci conflict when neither can occur with the other in one
chronicle-compatible configuration.

The chronicles of `D` are secured plays in this induced arena.

Proof sketch. Prefix dependence supplies finite causes. Branch incompatibility
is symmetric and hereditary because once two loci diverge incompatibly, every
extension of either remains incompatible with the other. Chronicle conditions
are exactly the legal-growth conditions for secured plays in the induced event
structure.

## 11. Values, Settlement, and Four-Valued Play

### 11.1 Why arenas need valuations

An arena says what can happen. It does not say what has been asserted, denied,
observed, contradicted, or settled. For that one adds a valuation.

The useful valuation algebra is Belnap's four-valued algebra:

```text
FOUR = {bot, t, f, top}.
```

Read:

```text
bot = neither asserted nor denied
t   = asserted
f   = denied
top = both asserted and denied
```

Represent a value as a pair of evidence bits:

```text
v = (v^+, v^-).
```

Then:

```text
bot = (0,0)
t   = (1,0)
f   = (0,1)
top = (1,1).
```

### Definition 11.2: Knowledge Order

The knowledge order is componentwise:

```text
a <=_k b  iff  a^+ <= b^+ and a^- <= b^-.
```

The knowledge join is:

```text
a join_k b = (a^+ or b^+, a^- or b^-).
```

This operation accumulates evidence without resolving contradiction.

### Definition 11.3: Arena Valuation

An arena valuation assigns a FOUR value to events, configurations, or loci:

```text
v_E : E_A -> FOUR
v_C : Conf(A) -> FOUR
v_L : Loc -> FOUR.
```

The choice of domain depends on the phenomenon:

- event valuation marks which moves have support or denial;
- configuration valuation marks which positions are settled or contested;
- locus valuation marks ludic designs.

### Definition 11.4: Settlement Operator

A settlement operator on valuations is a monotone inflationary closure:

```text
Cl : Val(A) -> Val(A)
```

such that:

```text
v <=_k Cl(v)
v <=_k w  =>  Cl(v) <=_k Cl(w)
Cl(Cl(v)) = Cl(v).
```

A settled valuation is a fixed point:

```text
Cl(v) = v.
```

### Proposition 11.5: No Nontrivial Cycles for Finite Inflationary Settlement

Let `L` be a finite poset and `F : L -> L` be inflationary:

```text
x <= F(x).
```

If

```text
F^k(x) = x
```

for some `k >= 1`, then:

```text
F(x) = x.
```

Proof. Inflationarity gives the chain:

```text
x <= F(x) <= F^2(x) <= ... <= F^k(x) = x.
```

Antisymmetry forces every inequality in the chain to be equality, in particular
`F(x)=x`.

This proposition is the abstract settlement principle behind finite gaming
certificates: a returned monotone closure orbit is not a cycle of play; it is a
fixed point already reached.

## 12. Games Built on Arenas

### Definition 12.1: Game

A game is not just an arena. A game is an arena equipped with some additional
structure, for example:

```text
G = (A, Players, admissible strategies, observation, payoff, settlement).
```

The arena supplies the space of possible interaction. Other components specify
who may act, what each participant can observe, which strategies are admissible,
how values are assigned, and how outcomes are settled.

### Definition 12.2: Player

A player in an arena-based game is an occupant of one or more strategy roles. A
player is not a primitive of the arena. Formally, a player contributes or selects
a strategy:

```text
player i  |->  sigma_i.
```

In multi-agent games, players may also be acted on by symmetry: if two players
occupy structurally identical roles, a finite permutation of names should not
change the mathematical play.

### Definition 12.3: Rule

A rule is any constraint derivable from the arena or imposed as additional
structure:

```text
legal move rule       = enabling in A
resource rule         = linear constraint on configurations
information rule      = observation map on Conf(A)
settlement rule       = closure on valuations
payoff rule           = function from outcomes to values.
```

The arena itself supplies the legal move rule. It does not by itself supply
payoffs or objectives.

### Definition 12.4: Objective and Payoff

A payoff is a map:

```text
u_i : Outcome(G) -> V_i.
```

An objective is an order, predicate, or preference structure on outcomes.
Payoffs are therefore downstream of plays and settlements. They are not
constituents of the arena.

## 13. Cultural and Phenomenological Readings of Play

The classical humanistic vocabulary of play becomes mathematically useful when
read as structure over arenas.

### 13.1 Magic circle

A magic circle is a subarena or down-closed event region:

```text
M subseteq E_A
```

such that:

```text
e in M and d <= e  =>  d in M.
```

Its boundary is:

```text
partial M = { e in M | exists d notin M, d <= e or e <= d }.
```

This captures the play boundary: what is inside the game and what crosses into
or out of it.

### 13.2 Paidia and ludus

Paidia and ludus can be read as a causal-density axis. For a finite arena define:

```text
ludus(A) =
  #{ {e,d} subseteq E_A | e != d and (e <= d or d <= e) }
  /
  #{ {e,d} subseteq E_A | e != d }.
```

Then:

```text
ludus(A) = 0  means no two distinct events are causally comparable
ludus(A) = 1  means every pair is causally comparable.
```

The first pole is maximally free concurrency; the second is maximally sequenced
rule-order. Caillois's modes - agon, alea, mimicry, ilinx - are not computed by
this scalar alone; they are additional declared or measured coordinates over
the arena.

### 13.3 Flow

A minimal arena-theoretic flow diagnostic compares challenge and skill.

```text
challenge_A(x) = # Legal_A(x)
skill_sigma(x) = # { P-moves admitted by sigma after x }.
```

A play is in a flow band `epsilon` when:

```text
|challenge_A(x) - skill_sigma(x)| <= epsilon * max(1, challenge_A(x))
```

along the relevant positions of the play. Excess challenge yields anxiety;
excess skill yields boredom. Flow is therefore not a mystical primitive; it is
a balance condition between arena branching and strategy capacity.

### 13.4 Deep play

Deep play concerns stakes. Let:

```text
stakes(p) in R
instrumental(p) in R
```

for a play `p`. The play is deep when:

```text
stakes(p) > instrumental(p).
```

The symbolic excess is:

```text
stakes(p) - instrumental(p).
```

This is a valuation over plays, not an alteration of the arena definition.

## 14. Summary of Constituent Objects

The arena stack is:

```text
Event
  an occurrence that may happen

Causality
  e <= d means e is required for d

Conflict
  e # d means e and d cannot co-occur

Prime event structure
  (E, <=, #)

Polarity
  pol : E -> {O,P}

Symmetry
  groupoid of structure-preserving event/configuration isomorphisms

Arena
  (E, <=, #, pol, Sym)

Configuration
  finite down-closed conflict-free subset of E

Enabled move
  event whose causes are present and conflicts absent

Play
  secured linearization of a configuration

Prestrategy
  event-structure map sigma : S -> A

Strategy
  receptive innocent symmetric prestrategy

Morphism
  strategy sigma : S -> A^perp || B, up to symmetry

Identity
  copycat/Fax

Composition
  parallel interaction plus synchronization and hiding

Design
  finite coherent locus-addressed presentation of strategy

Behaviour
  biorthogonally closed class of designs

Valuation
  assignment of values to events, loci, or configurations

Settlement
  monotone closure whose fixed points are settled states
```

## 15. Main Definition

The mathematical definition to retain is:

> An arena is a polarized prime event structure with symmetry. It is a tuple
>
> ```text
> A = (E_A, <=_A, #_A, pol_A, Sym_A)
> ```
>
> where `E_A` is a set of move-events, `<=_A` is finite-cause partial order,
> `#_A` is hereditary symmetric conflict, `pol_A : E_A -> {O,P}` is polarity,
> and `Sym_A` is a groupoid of isomorphisms preserving the event-structure and
> polarity. From this tuple one derives positions as configurations, plays as
> secured linearizations, strategies as receptive innocent symmetric
> event-structure maps, and morphisms as strategies on `A^perp || B`.

This definition is independent of any implementation. It is strong enough for
concurrent games because it remembers independence, not merely sequence. It is
strong enough for game semantics because it supports duality, copycat, and
composition. It is strong enough for ludics because locus-addressed designs
induce arenas and behaviours arise by orthogonality. It is strong enough for
play theory because cultural readings become predicates and valuations over the
arena rather than informal supplements to it.

## 16. Research Frontier

The remaining mathematical work is not to find an arena in a program. It is to
prove the following structures uniformly.

1. The passage from locus designs to event-structure arenas is functorial.
2. Behavioural biorthogonal closure agrees with strategy equivalence under
   copycat tests.
3. Symmetry groupoids support nominal agents, resources, and replicated
   subgames without quotienting away causal information.
4. Settlement operators on FOUR-valued arena valuations commute with strategy
   composition under explicit hypotheses.
5. Arena sheaves and Laplacians characterize best-response fixed points as
   harmonic sections.
6. The category of settled arenas is obtained from the category of arenas by a
   closure or reflective-subcategory construction.

These are publication-grade theorem targets. They are not software tickets and
not documentation chores. They are the mathematical program of arenas as the
general form of playable, testable, concurrent interaction.
