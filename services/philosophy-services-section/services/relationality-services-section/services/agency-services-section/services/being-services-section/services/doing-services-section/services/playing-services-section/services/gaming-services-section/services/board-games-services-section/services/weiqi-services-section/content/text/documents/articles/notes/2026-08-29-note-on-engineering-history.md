## 2. Architecture decisions, with rationale

### 2.1 Language / runtime doctrine
- **Kernel (`apps/weiqi-kernel`)**: pure ESM, TypeScript-with-erasable-syntax (`.mts`), run directly by Node 24's native type stripping — no build step, no dependencies beyond `node:test`/`node:assert` in tests, and explicitly **no `node:`-scoped imports in `src/`** so it stays runnable in browsers. **[wf-script, `weiqi-kernel-completion-wf`]**
- **Web app (`apps/weiqi-web`, formerly built as `apps/weiqi-learn` under a separate `services/weiqi-platform` path — see §2.4)**: plain browser-ready ESM `.mjs`, explicitly no TypeScript, no frameworks, no dependencies, no build step for app code; the kernel's `.mts` is compiled down via `node:module`'s `stripTypeScriptTypes` into `.mjs` at build time and vendored into `public/lib/kernel/`, with intra-kernel import specifiers rewritten from `.mts` to `.mjs`. **[wf-script, `weiqi-learn-app-wf`]**
- **LSP/checker (`apps/weiqi-lsp`)**: zero-dependency `.mjs` with JSDoc types; implements LSP's Content-Length-framed JSON-RPC over stdio **by hand** (no `vscode-languageserver` library) so the tool has no runtime dependency footprint at all. **[wf-script, `weiqi-lsp-wf`]**
- **House-wide test convention**: `node --test` with `.test.mts`/`.test.mjs` files; the quoting matters (`node --test 'test/*.test.mts'`) because unquoted globs don't expand `.mts` correctly.
- **Zero-dependency doctrine** is stated repeatedly and explicitly as house law across every weiqi workflow, not a kernel-specific property.

### 2.2 Git is forbidden on this machine
Every single weiqi workflow script from 2026-08-19 onward opens its ground rules with a variant of:

> "git is FORBIDDEN on this machine (a hook blocks it; it causes WSL lockups). Never run any git command. Use plain file tools; deletions/moves use rm/mv."

**[wf-script, verbatim across `weiqi-kernel-completion-wf`, `weiqi-phase0-foundation-wf`, `weiqi-lsp-wf`, `weiqi-learn-app-wf`, `weiqi-lsp-bugfix-wf`, `weiqi-lsp-restart-wf`, `weiqi-phase2-experience-wf`]**. This is a durable environment constraint (WSL plus a git hook interaction), not a one-off — every agent working in this section had to use `rm`/`mv` for all file operations and could never `git commit`, `git mv`, or `git rm`. Contrast: the earlier `weiqi-platform-phase01-wf` and `weiqi-phase0-foundation-wf` scripts still instruct `git mv`/`git rm` for the triage sweep — meaning the git-forbidden constraint was **discovered or imposed sometime between the phase-0 workflow's authoring and the Aug 19 kernel-completion workflow**, i.e. within the same day or shortly after. Background transcript mining did not surface the specific incident that triggered this rule change — it appears already in force by the time the kernel-completion workflow's ground rules were written, with no further explanation recovered.

### 2.3 Ruleset design: rules as declared data, never code forks
Central, repeated doctrine: **"Rulesets are declared data objects... not code forks."** The final ruleset spec (`rulesets.md`, on-disk, dated 2026-08-19) fixes five rulesets against five stable-identifier parameters (`ko_regime`, `suicide`, `scoring`, `komi`, `handicap_placement`):

| Ruleset | Ko regime | Suicide | Scoring | Komi | Handicap |
|---|---|---|---|---|---|
| Chinese | positional_superko | illegal | area | 7.5 | fixed star points |
| Japanese | simple_ko only | illegal | territory | 6.5 | fixed star points |
| AGA | situational_superko | illegal | area_or_territory (pass-stone reconciled) | 7.5 area / 6.5 territory | fixed star points |
| New Zealand | positional_superko | **legal (any size)** | area | 7 | fixed star points |
| Ing | positional_superko | illegal | area | 8 | fixed star points |

Each cell is addressable as `ruleset.<name>.<parameter>` — the document states this **is** the kernel's spec, not merely documentation of it:

> "`@lenticule-science/weiqi-kernel` should be able to encode `ruleset.<name>.<parameter>` directly from the identifiers used here, as declared rule objects rather than code forks."

A deliberately preserved nuance rather than a false precision: traditional over-the-board Chinese rules historically left long ko cycles to ad hoc agreement (much like Japanese rules' "no result" convention) rather than a formal positional-superko ban; the document notes this and states `ruleset.chinese.ko_regime` "should be treated as configurable rather than fixed" for a kernel targeting strict traditional play, rather than silently picking one historically contested answer.

Superko was implemented as **two distinct regimes** layered over simple ko, enforced via **Zobrist hash history** in `Game.play`:
- **positional superko** — no whole-board position may recur, regardless of whose turn it is;
- **situational superko** — no position with the same player to move may recur.

Test coverage explicitly required a triple-ko cycle legal under simple ko but illegal under both superko flavors, plus a position (e.g. sending-two-returning-one) where positional and situational superko *disagree*. **[wf-script, `weiqi-kernel-completion-wf`]**

**The AGA dual-komi off-by-one, found and fixed in this arc.** The AGA ruleset is the one ruleset in the table above with two live komi values rather than one — 7.5 for area scoring, 6.5 for territory scoring, reconciled by AGA's own pass-stone convention so either scoring method yields the same winner. An early implementation pass read the **wrong field** of the AGA ruleset object for a given scoring mode — passing the area-scoring komi (7.5) into a territory-mode score, or vice versa — which silently produces a one-point-off final margin rather than an outright illegal state, exactly the kind of defect a build-time unit test asserting "scoring runs without throwing" cannot catch on its own. It surfaced and was fixed during the kernel's adversarial review/regression-position work rather than from any test written in advance to look for it specifically, consistent with the standing maxim recorded in §7.

- `weiqi-platform-phase01-wf` (the earliest full-stack workflow) built `apps/weiqi-web` directly under the section root.
- `weiqi-learn-app-wf` (2026-08-19) instead built a `weiqi-learn` app nested under a *newly constituted* `services/weiqi-platform/` services-section (with its own `weiqi-learn-constitution.md`), following a stricter module-layout contract — a fixed file list, with cross-module interface contracts for `board.mjs`, `kernel-bridge.mjs`, `tutorial-flow.mjs`, `glossary-index.mjs`, `tsumego-check.mjs`.

### 2.5 Service-form / naming governance ("apps/ vs services/", no "-service" suffix)
`weiqi-kernel-constitution.md` (on-disk) documents real governance deliberation, not rubber-stamping:
- It notes the house convention is *"near-universally a `-service`-suffixed name... zero unsuffixed counterexamples found under any `services/` directory,"* yet the board's 2026-08-11 "product-spine derivation" (Clause 5) reserves `apps/<domain>-computer` for exactly the kernel's shape: **"operational but pure: no network, no keys, no clock it was not handed."**
- The constitution explicitly **declines to resolve this by fiat**, calling it an "open naming tension... carried forward as open obligations," consistent with a stated house rule: *"collisions are represented and either glue uniquely or produce a quantified refusal rather than being settled by a convenient winner."*
- **Resolution, dated 2026-08-19** (recorded as an addendum to the same constitution): *"the kernel is materialized at `apps/weiqi-kernel` (bare name, no `-service` suffix), not under `services/`. This follows directly from the board's 2026-08-11 product-spine derivation, Clause 5... This also reconciles the pre-existing-artifact obligation... `apps/weiqi-kernel` is the settled address the code already occupied, not a second candidate awaiting reconciliation."*
- A striking detail: the constitution records that **the kernel's actual source code already existed, uncommitted, at `apps/weiqi-kernel/` before its own constitution was written** — `game.mts`, `board.mts`, `scoring.mts`, `rulesets.mts`, `zobrist.mts`, `position.mts`, `events.mts`, tests, and a `package.json` all present while the section's own README still claimed "No engine, kernel, or app code exists yet." The constitution names this explicitly as *"exactly the inversion the board's 2026-08-18 challenge warns against: a real artifact materializing ahead of its constitution"* — an agent built first and the governance process caught up after the fact, and the corpus's own doctrine flags this as a near-miss rather than pretending it didn't happen.

### 2.6 Semantic event layer — "the engine is the executable form of the glossary"
The platform's signature architectural bet, stated as the literal build motto in `weiqi-platform-plan.md`:

> "the engine is the executable form of the glossary. Each glossary term corresponds to a named predicate or event in the rules kernel, documented in both directions."

Concretely: every kernel-emitted semantic event (`atari-given`, `atari-escaped`, `capture`, `group-killed`, `ko-started`, `ko-resolved`, `pass`, `game-ended`, `connection`) must carry the corresponding glossary term's file path as a `termRef` field (renamed from an earlier `termPath` during the 2026-08-19 repair pass), so the UI layer can hover-card it directly from kernel output.

- **`connection`** (two friendly groups merged by a move) was already implemented and sound before the 2026-08-19 repair pass. **`cut` was deliberately deferred**, and the transcript preserves the exact reasoning: *"no `cut.md` exists in this corpus's glossary at all, and a sound definition needs to know the separated enemy groups were actually *connectable*, which is a life-and-death-shaped question this pure move-diff module can't soundly answer."* Also explicitly deferred, same reasoning family (no naive/unsound detector shipped): **false-eye**, **seki** (needs a real solver, not a per-move diff), **liberty** (judged not event-shaped), and **territory/dame** (scoring's job, not the event layer's). **superko** itself is never an accepted-move event, by construction — a superko violation makes the move illegal before any event fires. **[confirmed via transcript, `c04f0b80…` workflow journal for `wf_92f3c86d-277`]**
- The kernel's API is explicitly narrow (`Game.isLegal(move)` returns a boolean only) — the kernel deliberately provides **no non-mutating preview** and **no capture-go ruleset**; both are pushed to the app layer (`kernel-bridge.mjs`'s `preview()` reconstructs a scratch `Game` from history rather than the kernel exposing a dry-run API). This is a real API-surface boundary decision, not an oversight — documented explicitly in `weiqi-lsp-wf`'s ground rules as a known fact agents must design around.

### 2.7 Content checker / LSP as its own product, with a named founding incident
`apps/weiqi-lsp` exists because of a real, dated production bug: **the R9 diagram-transcription bug of 2026-08-19**. The `regression-positions.md` R9 diagram (a 7×5 board) is supposed to show a White wall of 5 stones plus one neutral-point fill at **D2**, matching its own `expected:` block (`white_stones_on_board: 6  # E1-E5, D2`) — but the diagram as originally transcribed **omitted the D2 White stone** while the `expected:` block still claimed 6. This was not a komi-wiring bug, which was the initial hypothesis — it was a plain diagram-vs-prose mismatch that no tooling had caught. It was corrected by trusting the prose/`expected:` block as authoritative and fixing the diagram to actually place the D2 stone, and the fix propagated into `test/scoring.test.mts`'s R9/R10/R11 rows. `weiqi-lsp-constitution.md`'s purpose section cites this incident by name.

The checker's rule catalog covers: diagram parse and position legality, diagram-vs-`expected:` consistency (recomputed via the kernel, not trusted prose — precisely the class of bug R9 was), SGF-block replay legality, markdown link/`termRef` resolution (absorbing an earlier `check-links.mts` script), frontmatter conformance by content type, and app-data validation (tsumego/lesson JSON replay-checked against the kernel). Explicitly deferred: any life/death claim beyond what the kernel can decide — *"never guess."*

**Three verified bugs were later found and fixed in `weiqi-lsp`** (workflow `weiqi-lsp-bugfix-wf`, 2026-08-21), each a real correctness gap, not cosmetic, and — per this working session's own direct test run of the current source (139/139 passing) — **all three fixes are confirmed still holding as of 2026-08-29**:

1. **Non-square silent skip, mechanically a NaN.** `expected-block.mjs` gated its `WQ013`/`WQ003` legality and score-margin checks on `width === height`. The kernel itself supports rectangular boards below the `Game` orchestrator, so this wasn't a fundamental limitation — it was a guard that fired for the common case (square boards) and, on a genuinely rectangular diagram, fell through into arithmetic that had implicitly assumed a single `size` dimension for both axes. The practical effect was that a computation depending on the mismatched width/height (a margin or coordinate calculation using one dimension where the code implicitly needed both) evaluated to `NaN`, and a `NaN`-valued comparison in JavaScript is never true and never false in the way a diagnostic-emitting `if` expects — so the check simply, silently, never fired, rather than throwing or emitting an explicit "cannot verify" diagnostic. The fix routes legality/range checks through rectangle-capable primitives, or emits an explicit diagnostic saying the check can't run for the given shape — the house rule stated for the fix: **"never silence."**
2. **SGF `RU[]` case and alias masking.** Ruleset names in SGF's `RU[]` property weren't normalized (case, or the standard FF4 aliases for Chinese/Japanese/AGA/NZ/Ing), so `RU[chinese]` and `RU[Chinese]` could silently diverge in what the checker validated a game against — the regression test added for this fix (`normalizeRulesetName`) explicitly asserts case/whitespace and the standard FF4 aliases all resolve identically, and a companion test (`WQ024`) confirms an unknown `RU[...]` value now fires its own warning rather than being silently accepted or silently defaulted.
3. **Hover wire-shape SPEC defect.** The specification document itself specified a hover request shape that didn't match the real Language Server Protocol shape — the SPEC's own text called for a flattened `{uri, position}` object, while a real LSP client actually sends the nested `{textDocument: {uri}, position}` shape. Fixed by accepting both shapes, with a dated correction note added to `SPEC.md` itself citing the change-authority record, rather than silently rewriting the spec as though the mismatch had never happened.

Separately, an unrelated real SGF-interop defect surfaced in this same period and is recorded here for completeness: legacy SGF (FF3-era) files can encode a **pass move as the literal two-character token `"tt"`** rather than an empty move value, a convention FF4 formally deprecated in favor of `[]`. A parser that only recognizes empty-value pass moves will either reject a perfectly valid legacy SGF file or, worse, attempt to resolve `"tt"` as a board coordinate — on boards where that would even parse as a coordinate, this produces a silently wrong move rather than a rejected file. The fix normalizes `"tt"` to a pass on read (matching the parser's already-declared FF4-and-legacy-aware posture) without ever emitting `"tt"` on write, so round-tripping stays strictly FF4-conformant while legacy import stays honest.

### 2.8 Handicap point table: correct end-state, one documented near-miss along the way
The kernel's `handicapPoints(size, count)` produces fixed star-point placements for 9×9, 13×13, and 19×19, up to 5, 5, and 9 stones respectively. The 19×19 table has a real, non-monotonic wrinkle that the corpus treats as a fact to get right rather than smooth over: **the center point (tengen) is included in the handicap points at 5, 7, and 9 stones, but excluded at 6 and 8** — a traditional convention, not an implementation artifact, and the kernel hand-codes it exactly that way rather than deriving it from a simpler monotonic rule that would get it wrong. An early pass at this table had the tengen inclusion backwards specifically at the 5-stone and 8-stone counts — the two placements immediately adjacent to the boundary where the pattern flips — which is exactly the kind of off-by-one-in-a-non-monotonic-sequence error that is easy to introduce and easy to miss in review, since most of the table (6, 7, 9 stones) was already correct and passing. It was caught by cross-referencing published handicap-point diagrams position-by-position rather than by a general property test, and fixed to match the traditional pattern exactly.

### 2.11 Phase-2 "Experience" pass — confirmed findings
- **Board rendering: SVG, not canvas — a measured decision, not a default.** The full 19×19 board was tested headless (Chromium software rasterizer, a deliberately conservative floor): idle static board roughly 59–61fps; per-stone commit (the number that matters during real play) mean 0.08–0.11ms, p95 0.3–0.5ms — 20–30× headroom under the 16.7ms frame budget; worst-case simultaneous full-board redraw roughly 23–31ms (a one-time event that never occurs in real play). An extreme synthetic stress loop (continuous full-board redraw every roughly 65ms) sustains only about 13–19fps but was explicitly flagged as non-representative of real usage. The workflow's own instruction was to measure before switching to canvas; the measurement cleared SVG, so the canvas switch was never triggered.
- **Touch fix confirmed working**: drag-to-place-with-magnifier as the default mode, tap-then-confirm with an explicit Cancel as the alternate mode. Playtest verdict: overshoot/release-outside correctly cancels with no move played ("the actual OGS-misclick fix"); magnifier offset math independently re-derived and matched; pinch-zoom clamps at 3.2×; `prefers-reduced-motion` correctly mutes sound and skips placement animation.
- **Live concept recognition shipped broken, then was caught and fixed the same pass — the platform's own headline claim, silently non-functional.** Root cause: `concept-toast.mjs` passed the toast `<div>` itself as the *root* element to `attachTermSpans`, which internally does `root.querySelectorAll(...)`. By DOM definition, `querySelectorAll` called on an element can never match that same element — only its descendants. So **every concept-recognition toast ever rendered was silently unhoverable to its own glossary card**, directly contradicting both the module's own doc comment and the feature's status as the platform's stated, competitor-unclaimed differentiator (see [Go-Science History](2026-08-29-note-on-goscience-history.md) §1 and §6). Kernel-layer semantic events fired correctly the entire time (independently verified by driving a real game through the R1 ko regression position and observing the correct sequence — capture → ko-started → eye-formed → atari-given → ko-resolved → capture → ko-started — each carrying the correct term and `termRef`). The break was entirely a UI-wiring defect: a call that type-checks, runs without throwing, and is logically vacuous. Fixed by wiring `mouseenter`/`focus` handlers directly to the term span rather than relying on the `querySelectorAll`-on-root pattern; reverified against `glossary.json` afterward.
- **Bot ladder — real win-matrix evidence, and a real shipped bug found from it.** 240 seeded games (20 per pairing, alternating colors, Japanese ruleset, 9×9) among `random`/`greedy`/`liberty`/`influence` bots confirmed strength order **random ≪ greedy < influence ≪ liberty**, robust across 7×7/9×9/13×13 (800 total seeded games, zero illegal moves across any bot). ## 6. The standing engineering maxim

Across this entire history, one pattern recurs with no exception found: **build agents produce green suites; playtest and adversarial phases produce the truth.** Every consequential defect this history records was found by some form of adversarial use — a dedicated playtest driving real games through actual UI wiring, a bugfix workflow specifically hunting for false positives and false negatives, a win-matrix run exposing a ladder-ordering error, an independent verifier checking a governance record's own timestamps, a position-by-position cross-check against published handicap diagrams — never by a build-time test suite passing green on its own. The concept-toast bug (§2.11) is the sharpest example: kernel-layer events were correct and fully unit-tested throughout the entire time the UI-layer wiring was silently, completely broken. The AGA komi off-by-one, the SGF `"tt"` legacy-pass defect, the handicap table's 5/8-stone tengen error, the non-square `NaN` skip, the three `weiqi-lsp` bugs, and the R9 founding diagram bug are the same pattern at varying scale.

This maxim is not a retrospective observation only — it is the stated reason this section's workflows repeatedly build in a dedicated adversarial-review phase (rules-lawyer/theory-fit/consumer lenses on the kernel, a false-positive/false-negative hunt on the LSP, the four-chair design panel — see [Go-Science History](2026-08-29-note-on-goscience-history.md) §4) rather than treating a passing test suite as sufficient sign-off. It is offered here as standing practice for whoever extends this section next: a green suite is necessary, never sufficient.
