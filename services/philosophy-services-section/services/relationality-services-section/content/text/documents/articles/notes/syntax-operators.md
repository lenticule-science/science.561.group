## Types, terms, and raw operators

The [semiotic](../../../../../linguistics/topics/semiotics/index.md) universe's syntax is generated by a [typed lambda calculus](../../../../../../../../information-science-services-section/services/math-services-section/content/text/documents/articles/teaching-articles/explanations/typed-lambda-calculus.md). The type language $\mathsf{Ty}$ is built from:

- A base type $P$ — the type of semantic objects (elements of $H$).
- Function types $A \to B$ — the type of operations taking an $A$ and producing a $B$.
- Product types $A \times B$ — the type of pairs.

Terms are built from variables, lambda abstraction ($\lambda x.\ t$), application ($f\ a$), pairing, and projections, with standard typing rules. The important objects are the **operators**: closed terms of type $P^n \to P$ — functions that take $n$ semantic objects and produce a semantic object.

Operators are quotiented by definitional equality ($\beta\eta$-equivalence and any additional equational axioms). Two syntactically different terms that compute the same function are identified.

The set of all definable operators is:

$$
\mathsf{Op}^{\mathrm{def}} = \bigcup_{n \ge 0} \mathsf{Op}_n^{\mathrm{def}}
$$

where $\mathsf{Op}_n^{\mathrm{def}}$ is the smallest set of $n$-ary operators closed under primitive constants, lambda-definability, and composition.

Semiotically, the [typed lambda calculus](../../../../../../../../information-science-services-section/services/math-services-section/content/text/documents/articles/teaching-articles/explanations/typed-lambda-calculus.md) plays the role of **grammar** — the rules by which [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md) combine. Each operator is a combinatory rule: a way of taking [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md) and producing new [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md). The type system ensures that combinations respect the kinds of [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md) involved — you can't apply a rule that expects a proposition to something that isn't one.

## Interpretation

An interpretation maps each syntactic operator to a function on the semantic domain:

$$
\llbracket - \rrbracket_n : \mathsf{Op}_n^{\mathrm{def}} \to \mathrm{Hom}(H^n, H)
$$

This is where syntax meets semantics. Each syntactic rule (an operator) gets a meaning (a function on $H$). But not any mapping will do — the interpretation must satisfy seven conditions that ensure syntax respects the full semantic structure:

1. **Monotone and join-continuous**: each $\llbracket f \rrbracket$ preserves the order and directed joins in each argument. Syntax respects the logical structure.

2. **[Heyting](../../../../../../../../information-science-services-section/services/knowledge-services-section/services/research-services-section/content/text/documents/articles/notes/arend-heyting.md) compatibility**: the operators for $\wedge$, $\vee$, $\Rightarrow$, $\bot$, $\top$ on the base type are interpreted as the [Heyting](../../../../../../../../information-science-services-section/services/knowledge-services-section/services/research-services-section/content/text/documents/articles/notes/arend-heyting.md) operations on $H$. The logical connectives mean what they should mean.

3. **Modal homomorphism**: $j(\llbracket f \rrbracket(a_1, \ldots, a_n)) = \llbracket f \rrbracket(j(a_1), \ldots, j(a_n))$. Applying an operator and then stabilizing gives the same result as stabilizing the inputs and then applying the operator. Syntax commutes with modality.

4. **Trace compatibility**: $G(\llbracket f \rrbracket(a_1, \ldots, a_n)) = \llbracket f \rrbracket(G(a_1), \ldots, G(a_n))$. The same for the trace — tracing a combination is the combination of the traces.

5. **Definitional equality preservation**: if the lambda-theory proves $f \equiv g$, then $\llbracket f \rrbracket = \llbracket g \rrbracket$. Syntax that computes the same thing means the same thing.

6. **Fragment preservation**: $\llbracket f \rrbracket(F^n) \subseteq F$ for every fragment $F$. Operators don't break the locality structure — they keep fragments closed. (Fragments are defined in the next lesson.)

7. **Hereditary extensionality**: the family of all interpreted operators is hereditarily extensional — equalities valid on a fragment remain valid under all semantic construction steps.

Conditions 3 and 4 are the key coherence requirements. They ensure that the syntactic grammar is compatible with both the modal structure (the distinction between stable and provisional meanings) and the trace structure (provenance tracking). An operation that creates a new sign from existing [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md) must behave consistently with how those [signs](../../../../../../../../information-science-services-section/services/communication-science-services-section/services/linguistics-services-section/services/semiotics-services-section/content/text/glossary/terms/sign.md) stabilize and how their histories compose.

## What the interpretation provides

The interpretation turns the syntactic algebra into a layer of the semantic domain. Every syntactic operation has a precise semantic meaning, and that meaning respects the full algebraic, modal, and comonadic structure.

This is stronger than a typical semantics-of-programming-languages setup. There, interpretation preserves types and equality. Here, interpretation also preserves modality (which computations are stable), trace (which computations preserve provenance), and fragment structure (which computations are local). The [semiotic universe](../index.md) demands that syntax and semantics agree not just on what things compute, but on how they relate to stability, history, and locality.
