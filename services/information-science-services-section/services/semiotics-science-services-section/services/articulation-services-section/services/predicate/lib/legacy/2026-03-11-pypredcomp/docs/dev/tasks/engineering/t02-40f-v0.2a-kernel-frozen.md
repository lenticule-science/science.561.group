## Description

Per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md), every `t02-NN` task that ships normative substrate behaviour has a paired `t02-NNf` fixture-authoring task with its own conformance gate.
This is that pair for [t02-40](t02-40-v0.2a-kernel-frozen.md) — the **auth-fiber slice** of the four boundary projections.

The auth fiber is the projection that answers *who is this sender*, per [specs/security/user-as-boundary.md §2.1](../../specs/security/user-as-boundary.md).
The v0.2 minimum shape is a bearer-token-hash projection materialised on the convenience [`User`](../../../../src/process/user.py) record; the canonical *projection cell* `(user:<slug>, projects-auth-fiber) = TRUE` is emitted onto the boundary entity's fiber by [`init_boot.bootstrap_users`](../../../../src/init_boot/bootstrap_users.py) per [boot-sequence.md §4.1](../../specs/init-boot/boot-sequence.md).
The umbrella [`test_t02_34f_multi_user_authoring.py`](../../../../tests/conformance/test_t02_34f_multi_user_authoring.py) and the per-role slices [`test_t02_30f_admin_authoring.py`](../../../../tests/conformance/test_t02_30f_admin_authoring.py) / [`test_t02_31f_member_authoring.py`](../../../../tests/conformance/test_t02_31f_member_authoring.py) already pin the four-projection emission as a set; this paired fixture is the **per-fiber refinement** asked for by [t02-40](t02-40-v0.2a-kernel-frozen.md)'s acceptance — auth alone, isolated from authz / attention / history.
The narrower scope makes the auth-fiber emission and the bearer-token round-trip the single named hypotheses on test, so a future change that quietly drops the auth projection or weakens the failure-path semantics is the only thing that can break this fixture.

The fixture lives at [`tests/conformance/test_t02_40f_auth_fiber.py`](../../../../tests/conformance/test_t02_40f_auth_fiber.py) and witnesses the load-bearing acceptance items from [t02-40](t02-40-v0.2a-kernel-frozen.md):

- *"the auth-projection cell exists in the boundary entity's fiber after bootstrap"* — pinned by asserting `(user:<slug>, projects-auth-fiber) = TRUE` on each of three roles' boundary fibers (admin, member, observer).
  The auth fiber is role-orthogonal — every boundary projects it — so pinning all three roles in one manifest is the minimum that proves the projection is not accidentally role-gated.
- *"successful sender resolution"* — the plaintext bearer token returned by [`ensure_users_from_manifest`](../../../../src/init_boot/bootstrap_users.py) round-trips through [`process.user.authenticate`](../../../../src/process/user.py) to the same `user:<slug>`, and its SHA-256 hash matches the persisted `User.token_hash`.
  This is the *who is this sender* claim of the auth fiber in load-bearing form.
- *"failed sender resolution surfaces PCM_AUTH_FAILED"* — an unrecognised token raises [`PCM_AUTH_FAILED`](../../../../src/substrate/error_codes.py) and the event log advances by exactly zero events.
  Same gate-ordering invariant shape as t02-30f leg 4 (denial without state advance), retargeted to the auth surface.
- *"byte-identical fiber state across two runs"* — two fresh substrates running the same bootstrap manifest produce byte-identical `events.jsonl`, with `process.user.secrets` monkeypatched to a deterministic counter so the bearer tokens (and thus the persisted `token_hash` cells) match across runs.
  Note the monkeypatch target is `process.user.secrets`, not `process.session.secrets` (the t02-30f target) — `process.user.create_user` is the producer of the non-determinism on the bootstrap path.

The fixture's scope is **the auth fiber alone**.
The umbrella `t02-34f` remains the cross-role / cross-fiber conformance gate; the per-role slices remain the per-role regression fences; this fixture is the regression fence for the auth-fiber projection in isolation, complementing the (forthcoming) `t02-41f` (authz), `t02-42f` (attention), `t02-43f` (history) per-fiber slices.

## Acceptance

- The fixture file exists, is collected by pytest, and all four tests pass against the current implementation.
- The fixture exercises the spec's acceptance claims (auth-projection cell on every role, bearer-token round-trip, PCM_AUTH_FAILED on unknown token with no state advance, byte-identical replay), not just the implementation's incidental behaviour, per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md) §"Why".
