# Milestone v0.1 — Substrate boots

## Position in hierarchy

- Of campaign: [campaigns/ship-pypredcomp.md](../campaigns/ship-pypredcomp.md)

## Goal

The kernel is real.
The substrate boots from a Nix flake on commodity hardware, persists to disk, accepts messages over MCP and HTTP, executes closure rules to fixed points, and serves a default web GUI shell that demonstrates message-as-affordance.

**Implementation language:** Python (per [decisions/engine-language-rust.md](../decisions/engine-language-rust.md), [implementation/python.md](../implementation/python.md)).
Built on PydanticAI, LangGraph, FastAPI, pydantic, asyncio, cryptography, and the MCP Python SDK.
The Rust port begins at v0.2 using the existing `mash-engine` crate as the algebra seed.

## Deliverable

- A Nix-built OS image that boots and reaches `ready` state.
- The MCP server accepts substrate operations and responds correctly.
- The HTTP server serves cells, rules, fibers, events with byte-identical canonical output.
- The web GUI shell loads in a browser and updates over WebSocket on a respond.
- A 50-rule test substrate replays from event log to byte-identical fiber state.
- The conformance-vector round-trip suite passes on this implementation.

## Conformance gate

1. The Rust crate's algebra round-trips fixtures byte-identically (already passing in `mash-engine`).
2. The 50-rule replay test passes byte-identically.
3. The MCP server passes the conformance-vector round-trip suite.
4. The web GUI loads and demonstrates message-as-affordance.
5. `nix build .#default` produces the bootable image; the image boots and reaches `ready`.
6. The stratification conformance vectors per [specs/conformance-vectors.md](../specs/conformance-vectors.md) §11 pass: pure σ-only, pure Δ-only, combined σ-then-Δ, and retraction fixtures.
  Repair-log byte-identity across runs is included.
7. The presheaf projection fixtures pass: `project_stratum`, `project_peer`, `project_at_ord` and their compositions return byte-identical bytes; cache-discard-and-rebuild produces the same bytes.

## Shipped

v0.1 ships at substrate package tip on `main` (post-merge with `origin/main`).
All seven gate items are satisfied by the running implementation: the `substrate`, `storage`, `network`, `drivers`, `shell`, and `init_boot` top-level packages under [`pypredcomp/`](../../) are present and pass the 163-test gate; the `Start application` workflow boots the runtime (`substrate.runtime:main`) and serves the web GUI on port 5000.

## Erratum (2026-05-02)

The v0.1 plan, decisions, specs, and `implementation/python.md` originally named the Python source tree as `src/substrate/`, `src/storage/`, etc. *as if relative to the repo root*.
The shipped artefact is the `pypredcomp` package at `operations/engineering/tools/predication-computer/pypredcomp/`, with packages `substrate`, `storage`, `network`, `drivers`, `shell`, `init_boot` (and `process` added by v0.2 work).
The `Start application` workflow and the Nix flake already point at the real location; only the records were drifted.

This is a **relocation-of-citation only**.
No v0.1 conformance gate is weakened.
Per [decisions/pypredcomp-package-location.md](../decisions/pypredcomp-package-location.md), `pypredcomp` is the canonical Python substrate; the unrelated `operations/engineering/pypred/` tree is math-research tooling and is never cited by sprint records.

The cell-atom / fiber-snapshot normative-gap cleanup (e0 done; e1–e4 carry-forward) is owned by v0.2a's opening slice — see [v0.2a-multi-user-single-node.md](v0.2a-multi-user-single-node.md).
