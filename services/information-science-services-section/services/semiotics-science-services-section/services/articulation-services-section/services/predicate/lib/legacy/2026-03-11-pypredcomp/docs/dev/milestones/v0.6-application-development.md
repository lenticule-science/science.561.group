# Milestone v0.6 — Application development surface

## Position in hierarchy

- Of campaign: [campaigns/ship-pypredcomp.md](../campaigns/ship-pypredcomp.md)
- Decomposes into goal: [goals/v0.6-third-party-app-workflow.md](../goals/v0.6-third-party-app-workflow.md)
- Carried project tasks: pt-15.

## Goal

Third parties (developers outside the 561 group) can write, package, sign, distribute, and install applications for the OS.
The application development workflow is documented; capabilities are exposed as a stable API; package authoring tools exist; doc format (man-page equivalent) is shipped.

This release transforms the OS from "single-vendor system" to "platform third parties can build on."

## Tasks (intra-milestone implementation slices)

Task families:

- **SDK** (`t06-01..t06-03`): API definition; language bindings (Rust primary, TypeScript, Python); docs.
- **Capabilities-as-API** (`t06-10..t06-12`): typed capability cells; manifest declarations; non-amplifying composition.
- **Package authoring** (`t06-20..t06-23`): manifest format; Ed25519 signing; distribution registry; transitive dependency resolution.
- **Skill author tooling** (`t06-25..t06-27`): `lint-skills` validator; pre-commit hook; documented author workflow.
- **Doc format** (`t06-30..t06-33`): `doc:<topic>` cells; `materialize` shell rendering; `help` command; web GUI overlay.
- **Third-party app workflow** (`t06-40..t06-42`): developer onboarding; non-trivial example app; app removal flow.

## Deliverable

- A v0.6 OS image with the SDK installed by default.
- The example application (built using only the SDK) installs cleanly and runs.
- The example application's package round-trips signing and verification.
- A non-561-group developer can install the SDK and follow the documented workflow to build and ship an app.

## Conformance gate

1. All v0.5 vectors pass.
2. The example app is built using only the SDK and runs on a clean OS image.
3. The package signing/verification round-trips byte-identically.
4. Capability discipline rejects unauthorized capability access at install time and runtime.
5. Documented developer workflow produces a working app for a developer who hasn't worked with the OS before.
6. Skill author tooling (`t06-25..t06-27`): `lint-skills` returns no failures on a clean tree; produces documented codes on canonical error/warning trees; pre-commit hook exits non-zero on errors per the documented severity discipline.

## Out of scope (deferred)

- Agential layer (v0.8).
