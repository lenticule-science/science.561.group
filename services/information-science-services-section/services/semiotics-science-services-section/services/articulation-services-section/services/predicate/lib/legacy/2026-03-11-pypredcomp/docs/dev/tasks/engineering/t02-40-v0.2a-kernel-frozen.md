# t02-40 — Capability fiber: auth

## Description

Spec and source-cite the **auth fiber** projection from the boundary entity.
The auth fiber is the *who is this sender* dimension — bearer-token hash today, Ed25519 signature in v0.4-federation.
Every `respond` carries a `sender` that resolves through the auth fiber to a boundary entity; if resolution fails, the respond produces `PCM_AUTH_FAILED`.

Per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md), a user is a boundary that projects four canonical fibers — auth / authz / attention / history.
This task lands the **auth** projection cleanly and ships its spec citation in the source.
The other three projections are tasks `t02-41` (authz), `t02-42` (attention), `t02-43` (history); they are independent and can land in parallel.

**Spec citations.**

- User-as-boundary per [specs/security/user-as-boundary.md](../../specs/security/user-as-boundary.md) — the v0.2 minimum auth shape (slug + token-hash).
- Identity per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
- Signing-and-witnessing per [specs/security/signing-and-witnessing.md](../../specs/security/signing-and-witnessing.md) — Ed25519 path for v0.4 federation.
- Federation signatures per [decisions/federation-signatures-ed25519.md](../../decisions/federation-signatures-ed25519.md).
- Theory grounding: row 8 of [references/theory-for-developers.md](../../references/theory-for-developers.md) (capability and authorisation as modal restriction).
  Auth answers the *who*; authz answers the *what they can do* (`t02-41`); the two compose via $\Rightarrow$.

**Modules to touch** (proposed; confirm exact file boundaries with captain when picking up).

- [`src/process/user.py`](../../../../src/process/user.py) — already implements bearer-token-hash auth (`hashlib`, `secrets`, `PCM_AUTH_FAILED`).
  Confirm the projection cell `(user:<slug>, projects-auth-fiber) = t` is emitted per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
  Module docstring already cites [specs/security/user-as-boundary.md](../../specs/security/user-as-boundary.md) — confirm the citation is accurate against the current spec text.
- [`src/init_boot/bootstrap_users.py`](../../../../src/init_boot/bootstrap_users.py) — already emits the four `projects-<name>-fiber` cells per the docstring.
  Confirm the auth-projection emission is correct.
- [`src/substrate/respond.py`](../../../../src/substrate/respond.py) — the sender's auth fiber resolves through this code path on every `respond` invocation.
  The resolution path MUST be cited to the spec.
- [`tests/conformance/`](../../../../tests/conformance/) — auth-projection conformance test (paired with `t02-40f`).
