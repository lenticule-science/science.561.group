# t02-32f — Observer-role authoring fixture (paired)

## Description

Per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md), every `t02-NN` task that ships normative substrate behaviour has a paired `t02-NNf` fixture-authoring task with its own conformance gate.
This is that pair for [t02-32](t02-32-v0.2a-multi-user-authoring.md) — the **observer-role slice** of the multi-user authoring surface.

The umbrella fixture [`test_t02_34f_multi_user_authoring.py`](../../../../tests/conformance/test_t02_34f_multi_user_authoring.py) already exercises admin → member → observer end-to-end against the role-default capability fibers from [`init_boot.bootstrap_users.
ROLE_CAPABILITIES`](../../../../src/init_boot/bootstrap_users.py); this paired fixture is the **per-role refinement** asked for by [t02-32](t02-32-v0.2a-multi-user-authoring.md)'s acceptance — observer authority alone, without entanglement with the admin-asserts or member-retracts legs.
The narrower scope makes the observer's capability fiber the single named hypothesis on test, so a future change that quietly weakens the observer role (or accidentally widens it past `{shell:read, audit:read}`) is the only thing that can break this fixture.

The fixture lives at `tests/conformance/test_t02_32f_observer_authoring.py` and witnesses the load-bearing acceptance items from [t02-32](t02-32-v0.2a-multi-user-authoring.md):

- *"`bootstrap_users` emits the observer role from the bootstrap-user manifest with read-only grants per `boot-sequence.md` §4.1"* — pinned by asserting the observer's persisted `granted:*` cells on the boundary entity match the §6.4 spec literal `{shell:read, audit:read}` (not the runtime `ROLE_CAPABILITIES["observer"]` constant), and the four boundary-projection cells (`projects-auth-fiber`, `projects-authz-fiber`, `projects-attention-fiber`, `projects-history-fiber`) plus the `kind-user` and `role-observer` cells are all present at value `True` per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
  Per row 8 of [references/theory-for-developers.md](../../references/theory-for-developers.md): all four fibers project even on the read-only role — the observer is restricted by an empty authz fiber, not by an absent boundary.
- *"observer reads succeed under the attention fiber"* — admin pre-asserts `(task:demo, status-open) = TRUE`; the observer opens its own session and `project`-s the entity.
  The atom is visible, the recorded sender is the admin (not the observer), and the read does not advance the event log.
- *"observer authoring respond produces $\bot$ at every cell; the event log is byte-identical pre- and post-observer-respond; no `PCM_AUTH_FAILED`-style exception is raised — the restriction is algebraic, not raised"* — the gate-ordering invariant of [capability-permissions.md §6.3](../../specs/filesystem/capability-permissions.md) in load-bearing form.
  In v0.2a the gated `signal:*` substrate-action surfaces use a thin `require_capability` guard that raises `PCA_SCOPE_INSUFFICIENT` rather than running a Phase-2 box_R restriction; the structural claim of t02-32 is witnessed by the role-default fiber leg (the observer holds *no* `signal:*` cell of any kind), so the denials are the algebra's image regardless of where in the call stack they materialise.
  The fixture pins three per-surface denial legs — `set_current_scope` (signal:session-scope:set), `attach_mount` (signal:mount:attach), `record_snapshot` (signal:snapshot:record) — so a regression on any one of them is the single named hypothesis on test, and three different action namespaces is the smallest convincing witness that the restriction is *structural* rather than per-surface.
  Each leg asserts the denial code is `PCA_SCOPE_INSUFFICIENT` with `needed` naming the specific signal surface, AND the denied call advances neither the event log nor the per-surface fiber.
- *"byte-identical fiber state across two runs"* — the observer slice (admin pre-seeds + observer opens + observer reads) is replayed against two fresh substrates with `process.session.secrets` monkeypatched to a deterministic counter; `events.jsonl` is byte-identical between runs.

The fixture's scope is **observer authority**, not the full three-role surface.
The umbrella `t02-34f` remains the cross-role conformance gate; this fixture is the regression fence for the observer slice in isolation.
