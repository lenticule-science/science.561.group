## Description

The matrix-driver spec is normative.
This task is the Python implementation that takes the spec from "documented" to "conforming" — the chat driver that proves the v0.2b driver framework actually carries a real protocol.

**What this consumes from the rest of v0.2b.** The driver-record + registry from [`task:t02-50`](t02-50-v0.2b-driver-model-and-three-drivers.md) and the attach/detach lifecycle from [`task:t02-53`](t02-53-v0.2b-driver-model-and-three-drivers.md) are the substrate this driver registers into.
The counit-fidelity sub-section from [`task:t02-65`](t02-65-v0.2b-drivers-lossy-counit-discipline.md) names `matrix-driver`'s counit as `lossy` (E2EE keys not preserved across the substrate→host adjunction); this task emits the per-call `driver-fidelity` witness when an encrypted room is touched.

**Procedure.** Follow [implementation/workflows.md recipe 1](../../implementation/workflows.md#1-landing-a-v02a-task-end-to-end).

The counit-witness emission discipline is the failure mode to watch: any encrypted-room operation that does not emit the `driver-fidelity` witness is a `t02-65` violation.

**Ship-target role.** Counts as one of the three conforming drivers in gate item 1 of [milestones/v0.2b-drivers-observability-packaging.md §Ship targets](../../milestones/v0.2b-drivers-observability-packaging.md).
Matrix is the network-protocol exemplar (the other two — hledger, mqtt — exercise file-format and pub/sub respectively).
