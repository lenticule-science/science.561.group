## Grounding

[decisions/self-representation-everywhere](../../decisions/self-representation-everywhere.md) + [decisions/drivers-are-substrate-entities](../../decisions/drivers-are-substrate-entities.md) — deployment state is content-addressed substrate cells; replay reproduces the deployed configuration byte-identically.
By Unix reflex the systemd-integration spec stub would be authored as "drop a unit file in `/etc/systemd/system/`"; the substrate's discipline is that the *unit file is generated from* a `(node:<id>, systemd-unit-spec, …) = t` cell, and edits to the cell propagate via the substrate to the host filesystem.
Library grounding:

- [`recovery-via-event-log-replay-determinism`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/recovery-via-event-log-replay-determinism.md) — replay determinism is the structural guarantee that requires deployment config IS a cell, not a side-file (otherwise replay reconstructs the substrate but not the host).
- [`witness-as-cell`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/witness-as-cell.md) — config-edit witnesses are substrate cells; the cell IS the audit trail.
- [`cache-coherence-via-functorial-projection`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/cache-coherence-via-functorial-projection.md) — the host filesystem is a *cache* of the substrate's deployment cells; the renderer projection must be functorial for the host to stay coherent.

## Description

Round-4 §1.4 named *deployment-config-as-substrate-cell-not-side-file*.
This task adds a §"Configuration as substrate cell" sub-section to each deployment spec.

**What this consumes from v0.2a + v0.2b.**

- v0.2a substrate cell-shape discipline supplies the cell encoding.
- v0.2a `t02-43` (event log + replay) supplies the determinism guarantee that motivates this discipline.
- v0.2b `t02-50` (driver model) supplies the *renderer driver pattern*: the host filesystem is the external system, the renderer driver is the faithful-counit interfacer that projects the cell to the unit file.
  Without `t02-50` first, the renderer pattern is unnamed.
- v0.2b `t02-90` (packaging skeleton) supplies the host-process boundary the renderer driver lives at.

**Spec citations.**

- Driver model: [`task:t02-50`](t02-50-v0.2b-driver-model-and-three-drivers.md) — the renderer driver IS a driver per this model; faithful-counit discipline applies.
- Decision (substrate-resident config): [decisions/self-representation-everywhere](../../decisions/self-representation-everywhere.md).
- Decision (drivers as substrate entities): [decisions/drivers-are-substrate-entities](../../decisions/drivers-are-substrate-entities.md).

**Modules to touch.** Each spec under `specs/deployment/` gains a §"Configuration as substrate cell" with: (a) per-knob substrate cell shape `(node:<id>, <config-key>, <value>) = t`; (b) renderer-driver pipeline (cell → renderer → host filesystem); (c) faithful-counit discipline per the driver-model; (d) edit-as-respond invocation pattern (the captain edits via a substrate `respond`, the renderer fires on cell-change, the host file updates).

**Procedure.** Follow [implementation/workflows.md recipe 10](../../implementation/workflows.md#10-promoting-a-thin-t02-nn-task-record-into-a-procedural-plan).
For each spec: (1) name the per-knob cell-shape; (2) cite the renderer-driver per `t02-50`; (3) name the propagation path; (4) update conformance-vector backlog B5.

**Ship-target role.** Pre-condition for the v0.2b packaging normative gate.
Without this discipline, deployment cannot survive replay (a fresh `$ROOT` would have empty `/etc/systemd/system/`).

**Depends on.** [`task:t02-50`](t02-50-v0.2b-driver-model-and-three-drivers.md) — the renderer driver pattern.
Coordinates with [`task:t02-90`](t02-90-v0.2b-packaging-skeleton.md).
