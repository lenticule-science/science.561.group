# t02-30 — Multi-user authoring (admin role)

## Description

Admin-role authoring slice for the multi-user authoring goal: ship the admin capability fiber and the admin-only `respond` paths per the boundary-projection identity scheme.
The admin role is the most-permissive of the three roles in v0.2a (admin, member, observer); landing it first proves the capability-fiber discipline before member/observer narrow it.

**Spec citations.**

- Boundary-projection identity per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md) — each user is a boundary entity that projects four fibers (auth, authz, attention, history).
- Capability model per [specs/security/capability-model.md](../../specs/security/capability-model.md); modal-restriction per [decisions/authorization-is-modal-restriction.md](../../decisions/authorization-is-modal-restriction.md).
- Multi-regime session discipline per [specs/process/multi-regime-session.md](../../specs/process/multi-regime-session.md) — admin asserts cells; the regime envelope governs what cells are admissible.
- Theory grounding: row 8 of [references/theory-for-developers.md](../../references/theory-for-developers.md) (capability and authorisation as modal restriction).

**Modules to touch** (proposed; confirm exact file boundaries with captain when picking up):

- [`src/process/user.py`](../../../../src/process/user.py) — boundary entity for the admin user.
- [`src/substrate/authorization.py`](../../../../src/substrate/authorization.py) — admin's authz fiber composes via $\Rightarrow$ in `respond` Phase 2.
- [`src/init_boot/bootstrap_users.py`](../../../../src/init_boot/bootstrap_users.py) — emit the admin role in the per-user capability fibers per [boot-sequence.md §4.1](../../specs/init-boot/boot-sequence.md).
- [`tests/conformance/`](../../../../tests/conformance/) — admin-asserts conformance test (paired with `t02-30f`).

**Procedure.** Follow [implementation/workflows.md recipe 1](../../implementation/workflows.md#1-landing-a-v02a-task-end-to-end) end-to-end.
The cross-cutting nature (process + substrate + init_boot + tests) is a feature, not a reason to slice — see [pypredcomp/AGENTS.md hard scope rule 2](../../../../AGENTS.md).

**Ship-target role.** This task contributes to the v0.2a ship target covering multi-user respond fixtures (admin asserts, member retracts, observer reads); confirm the exact gate against [milestones/v0.2a-multi-user-single-node.md §Ship targets](../../milestones/v0.2a-multi-user-single-node.md) when picking up.

**Depends on.** None.
(`t02-31` member-role and `t02-32` observer-role build on the capability-fiber discipline this task establishes; ship `t02-30` first.)
