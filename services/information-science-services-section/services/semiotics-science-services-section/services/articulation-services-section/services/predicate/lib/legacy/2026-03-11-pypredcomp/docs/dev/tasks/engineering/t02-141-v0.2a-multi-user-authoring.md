# t02-141 — Bootstrap-users idempotence

## Description

Prove and pin the **idempotence** property of the bootstrap-users routine: re-booting against an existing event log with an unchanged manifest hash MUST produce zero new events.
This is the determinism gate for boot — without it, the boot-determinism theorem (`predicated-computing/theorems/boot-determinism`) is not realised in code.

The implementation already supports this (per [`src/init_boot/bootstrap_users.py`](../../../../src/init_boot/bootstrap_users.py)'s docstring: "Re-boot against an existing log: If the manifest hash matches the latest recorded hash → no-op").
This task adds the conformance fixture that *gates* the property and the byte-comparison assertion that proves it.

**Spec citations.**

- [specs/init-boot/boot-sequence.md §4.1](../../specs/init-boot/boot-sequence.md) — the four-step bootstrap routine + the manifest-hash recording.
- [decisions/single-respond-primitive.md](../../decisions/single-respond-primitive.md) — bootstrap NEVER modifies an existing user; user lifecycle changes go through `respond`.
- [decisions/event-log-is-jsonl.md](../../decisions/event-log-is-jsonl.md) — the event log is byte-comparable; this is what makes the idempotence property checkable.
- Theory grounding: row 12 (boot sequence and the four-layer rule architecture) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
  Specifically: "Boot is a deterministic function of (deployment image, persistent set).
  Caches are recomputable from history, never authoritative against history."
- Engineering theorem: [`predicated-computing/theorems/boot-determinism`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/boot-determinism.md) — the load-bearing claim.
