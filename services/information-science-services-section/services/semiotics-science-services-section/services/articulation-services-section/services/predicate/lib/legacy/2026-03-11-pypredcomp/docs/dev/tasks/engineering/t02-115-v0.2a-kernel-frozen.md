## Cancellation rationale

Cancelled per captain's hard rule "no inventing features; decide from theory".
The substrate's projection architecture is normatively defined in [specs/kernel/projection-naturality.md](../../specs/kernel/projection-naturality.md) §2 point 1:

> **Cache rebuilds are byte-deterministic.** Discarding the three by-stratum projection files and re-invoking `materialize_by_stratum_projections` MUST produce byte-identical bytes — **no stale-cache bug class exists, because there is no invalidation step**.

This is the implementation echo of the load-bearing theorem `cache-coherence-via-functorial-projection` from `predicated-computing/theorems/`: cache coherence is **structural** (the projection functor commutes with merge per the §1 naturality square), not **invalidation-driven**.
Every `respond` Phase 4b unconditionally re-materialises all three by-stratum files from the post-merge cell-history; there is no "upstream stratum cell changed → invalidate downstream" relation to maintain because the by-stratum files are not a downstream cache — they are projections of the same upstream history, recomputed each respond.

Authoring a "cache-invalidation rule" task would require:

- Defining what "stale" means for a by-stratum projection — but per the spec quoted above, no stale class exists.
- Adding an invalidation step to `materialize_by_stratum_projections` — but the spec mandates unconditional re-materialisation; an invalidation gate would be dead code at best, a correctness regression at worst (it would create the stale-cache bug class the architecture eliminates).
- Adding tests for invalidation correctness — but `test_stratum_e3.py` already pins gate 4 (discard-and-rebuild byte-identity), which is the architecture's *replacement* for invalidation correctness.

All three would constitute inventing a feature with no theoretical anchor and would actively undermine the cache-coherence-via-functorial-projection theorem.
This task is theory-rejected.
