## Grounding

The Nix flake's reproducibility hash is the *content address of the build output*.
By Nix-shop reflex this would be treated as an opaque string in `flake.lock`.
The substrate's discipline is that the hash IS a substrate cell `(node:<id>, build-hash, <hash>) = t`, so two questions become substrate queries: "did this node deploy the build I think it did?" and "do two nodes run the same build?".
Library grounding:

- [`recovery-via-event-log-replay-determinism`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/recovery-via-event-log-replay-determinism.md) — replay determinism extends to the *substrate*, but the substrate runs *on a build*.
  The build's reproducibility-hash is the structural hinge between substrate-replay and operational confidence.
- [`witness-as-cell`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/witness-as-cell.md) — the build-hash witness is a substrate cell; the cell IS the deploy-time audit trail.
- [`closure-rule-wire-format-canonicalization`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/closure-rule-wire-format-canonicalization.md) — canonicalization makes the hash content-addressed under the canonical encoding; the spec must name the canonicalization function.
- Decision: [decisions/trusting-trust-bootstrap-path](../../decisions/trusting-trust-bootstrap-path.md) — the build-hash is the v0.2b foothold for the v0.3 self-hosting trusting-trust defence.
