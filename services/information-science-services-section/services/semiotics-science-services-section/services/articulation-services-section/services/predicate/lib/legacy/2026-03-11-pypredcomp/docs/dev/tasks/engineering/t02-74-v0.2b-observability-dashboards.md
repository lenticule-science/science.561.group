## Grounding

Theory row 4 (stratified facts) and row 11 (sessions / dispatch / heartbeat) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
Dashboards are substrate cells of `kind = "dashboard"` owned by personnel; panels are widgets reading per-stratum projections; refresh is heartbeat-driven (not poll-driven).
The dashboard frame is the per-stratum-cohomology rendering surface.

## Description

`specs/observability/dashboards.md` defines dashboard records and widget types; `specs/observability/captain-home.md` defines the captain's default dashboard layout.
This task is the Python implementation of the dashboard *frame* — the loader, the layout engine, and the WebSocket subscription wiring — without yet implementing the H¹ panel or the diagnostic-projection panel (those are `t02-80` and `t02-81`).

**What this consumes from v0.2a.** Dashboards are substrate cells with `owned-by` and `shared-with` predicates referring to personnel; v0.2a's multi-user authoring ([`task:t02-30`](t02-30-v0.2a-multi-user-authoring.md) admin, `t02-31` member, `t02-32` observer) is the structural pre-condition — without personnel records and capability fibers, "owned-by" and "shared-with" are undefined.
Refresh is heartbeat-driven per the v0.2a-shipped heartbeat from [`task:t02-42`](t02-42-v0.2a-kernel-frozen.md).

**Procedure.** Follow [implementation/workflows.md recipe 1](../../implementation/workflows.md#1-landing-a-v02a-task-end-to-end).
The frame MUST stay agnostic of any specific widget — `t02-80` (H¹ panel) and `t02-81` (diagnostic projection panel) extend `Widget`; the frame just composes them.
Refresh discipline: never refresh on a wall-clock timer; only on heartbeat tick (recipe 7 determinism).

**Ship-target role.** Structural pre-condition for gate item 2 of [milestones/v0.2b-drivers-observability-packaging.md §Ship targets](../../milestones/v0.2b-drivers-observability-packaging.md) — "the observability dashboards consume H¹ audit cohomology from a live multi-user node."

## Acceptance

Proposed checkable acceptance items per [implementation/workflows.md recipe 10](../../implementation/workflows.md#10-promoting-a-thin-t02-nn-task-record-into-a-procedural-plan); confirm exact widget-base API and refresh hook with the captain.

- `src/observability/dashboards.py` loads a dashboard cell (by slug), resolves its `widgets` list to widget cells, and produces a layout JSON the GUI shell can render.
- `Widget` base class has a `render(view) → dict` method and a `subscribe(heartbeat) → None` method; `t02-80` / `t02-81` widgets extend this base.
- The captain-home dashboard fixture per [specs/observability/captain-home.md](../../specs/observability/captain-home.md) loads cleanly; missing widgets return a placeholder, never crash the frame.
- Refresh fires on heartbeat tick only; replaying the event log of a session that opened a dashboard reproduces the rendered layout byte-identically (recipe 7).
- Paired fixture `t02-74f` authored under `tests/fixtures/observability/` per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md); fixture covers (a) captain-home loads with empty widget set; (b) captain-home loads with one stub widget; (c) shared dashboard renders only widgets the viewer is authorized to see; (d) dashboard cell rebuilt from event log matches in-memory state.
