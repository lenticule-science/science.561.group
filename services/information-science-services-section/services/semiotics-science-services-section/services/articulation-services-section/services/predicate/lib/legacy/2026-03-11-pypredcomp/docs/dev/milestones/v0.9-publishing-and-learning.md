# Milestone v0.9 — Continuous learning + publishing

## Position in hierarchy

- Of campaign: [campaigns/ship-pypredcomp.md](../campaigns/ship-pypredcomp.md)
- Decomposes into goal: [goals/v0.9-learn-and-publish.md](../goals/v0.9-learn-and-publish.md)

## Goal

The system observes its own behaviour and improves.
Observations promote to instincts; instincts to skills; skills to tools; tools install as hooks.
The captain reviews each promotion through the governance app. Hugo-style site generation publishes from substrate fibers; persona-agents have live publication channels with subscription/feed support.

This release closes the loop from v0.8 (agents act) to v0.9 (agents learn from acting).

## Specs read

- All v0.8 specs.
- The continuous-learning material in agential-orchestration-platform.
- The captain's ideas-trove on continuous-learning, algebraic-learning-calculus, gamification-as-enrichment-prioritizer.

## Decisions in scope

All v0.8 decisions plus:

- (new for v0.9): observations-are-substrate-cells, learning-is-bilattice-ops, publishing-uses-hugo-shape.
- [cheapest-sufficient-computation-tier](../decisions/cheapest-sufficient-computation-tier.md) — carried forward from v0.8; v0.9 adds the Tier-2 *training* surface that produces model records the v0.8 invocation surface consumes.

## Tasks (intra-milestone implementation slices)

Task families:

- **Continuous learning pipeline** (`t09-01..t09-07`): observation → instinct → skill → tool → hook records and promotion paths; algebraic learning calculus.
- **Algebraic learning calculus — Tier-2 model training** (`t09-30..t09-37`): training-event records; two model families (decision-forest, Markov chain); algebraic learning calculus over substrate evidence; model-witnessing; retraction propagation; supersession; federated model sync; cheapest-sufficient progression integration.
- **Publishing** (`t09-10..t09-13`): Hugo-style site generation; persona publication channels; subscription support; site templates as cells.
- **Gamification (lightweight)** (`t09-20`): gamification-as-enrichment-prioritizer integrated with ledger and review apps.

## Deliverable

- A v0.9 OS image with the learning pipeline and publishing platform.
- An observation captured in v0.8 has been promoted through the pipeline to a tool, with the captain's review at each step.
- A persona-agent's site is live and federated via ActivityPub; subscribable via RSS.
- The system has learned at least one new pattern through observation; the pattern is now a substrate-resident closure rule.

## Conformance gate

1. All v0.8 vectors pass.
2. End-to-end pipeline: observation → instinct → skill → tool → hook, all visible in the governance app review queue.
3. A persona's site is live and reachable; RSS feed validates per the RSS 2.0 spec.
4. Federation: a stock Mastodon user can follow the persona's site and receive new posts.
5. The Tier-2 weights byte-identity vector (§12.4) passes: a training event run twice from a clean store on the same corpus + hyperparameters produces the same `produced-weights-cell` SHA-256, in both Python and Rust.
6. The model retraction vector (§12.6) passes: retracting a model invalidates every settled cell whose `derived_from` chain includes its weights, and the dispatch scheduler stops selecting it.
7. At least one observed Tier-3 behaviour has been promoted through the algebraic-learning-calculus path to a Tier-2 model artefact under captain review; subsequent dispatches against the same office × task shape route to Tier 2 instead of Tier 3.
