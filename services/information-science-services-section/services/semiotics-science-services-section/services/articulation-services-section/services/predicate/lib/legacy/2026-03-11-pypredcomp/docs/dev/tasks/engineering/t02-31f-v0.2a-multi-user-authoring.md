# t02-31f — Member-role authoring fixture (paired)

## Description

Per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md), every `t02-NN` task that ships normative substrate behaviour has a paired `t02-NNf` fixture-authoring task with its own conformance gate.
This is that pair for [t02-31](t02-31-v0.2a-multi-user-authoring.md) — the **member-role slice** of the multi-user authoring surface.

The umbrella fixture [`test_t02_34f_multi_user_authoring.py`](../../../../tests/conformance/test_t02_34f_multi_user_authoring.py) already exercises admin → member → observer end-to-end against the role-default capability fibers from [`init_boot.bootstrap_users.
ROLE_CAPABILITIES`](../../../../src/init_boot/bootstrap_users.py); this paired fixture is the **per-role refinement** asked for by [t02-31](t02-31-v0.2a-multi-user-authoring.md)'s acceptance — member authority alone, without entanglement with the admin-assert or observer-deny legs.
The narrower scope makes the member's capability fiber the single named hypothesis on test, so a future change that quietly weakens the member role (or accidentally widens it past the §6.4 spec literal) is the only thing that can break this fixture.

The fixture lives at `tests/conformance/test_t02_31f_member_authoring.py` and witnesses the load-bearing acceptance items from [t02-31](t02-31-v0.2a-multi-user-authoring.md):

- *"`bootstrap_users` emits the member role + member-scoped grants from the bootstrap-user manifest per `boot-sequence.md` §4.1"* — pinned by asserting the member's persisted `granted:*` cells on the boundary entity match the §6.4 spec literal `{respond:*, shell:read, shell:write, signal:session-scope:set, signal:session-message:*}` (not the runtime `ROLE_CAPABILITIES["member"]` constant), and the four boundary-projection cells (`projects-auth-fiber`, `projects-authz-fiber`, `projects-attention-fiber`, `projects-history-fiber`) plus `kind-user` and `role-member` are all present at value `True` per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
- *"a member can retract a cell it previously asserted"* — the member opens a session, asserts `(task:demo, status-open) = TRUE`, then retracts the same predicate.
  The post-retract fiber value is exactly `Both` per the cell-record monotonicity rule (`stdlib.retract_cell` docstring); both cell ids are real and distinct.
- *"member assert succeeds within scope"* — member positive control on the `signal:session-scope:set` surface: the member's `signal:session-scope:set` grant covers `set_current_scope`, the call advances the event log and writes the binary cell to the member's session-scope fiber.
  This is the load-bearing positive-side claim that distinguishes member from observer — same surface, different outcome, gated by the role-default fiber alone.
- *"a member CANNOT grant authority — an attempt to assert into another user's authz-fiber projection restricts to ⊥"* — capability non-amplification per row 8 of [references/theory-for-developers.md](../../references/theory-for-developers.md).
  Member attempting `attach_mount` (which gates on `signal:mount:attach`, not in the member's role-default fiber) raises `PCA_SCOPE_INSUFFICIENT` with `needed = signal:mount:attach`, and the denied call advances neither the event log nor the mount fiber.
  `signal:mount:attach` is the load-bearing target because the admin's `signal:*` super-grant covers it but the member's `signal:session-scope:set` + `signal:session-message:*` grants do not — same shape of capability, different prefix coverage, exactly the non-amplification claim t02-31 makes.
- *"byte-identical fiber state across two runs"* — the member slice (assert + retract + scope-set) is replayed against two fresh substrates with `process.session.secrets` monkeypatched to a deterministic counter; `events.jsonl` is byte-identical between runs.

The fixture's scope is **member authority**, not the full three-role surface.
The umbrella `t02-34f` remains the cross-role conformance gate; this fixture is the regression fence for the member slice in isolation, complementing the admin slice in [`test_t02_30f_admin_authoring.py`](../../../../tests/conformance/test_t02_30f_admin_authoring.py).

## Acceptance

- The fixture file exists, is collected by pytest, and all six tests pass against the current implementation.
