## Description

The spec at [specs/drivers/driver-model.md](../../specs/drivers/driver-model.md) is normative.
This task is the Python implementation slice: a driver-record loader, a driver registry, and the substrate hooks that make driver-cells first-class entities at runtime.
Without this slice, the v0.2b drivers (matrix, hledger, mqtt — `t02-60`/`t02-64`/`t02-70`) have nothing to register against.

**What this consumes from v0.2a.** v0.2a shipped the kernel: the bilattice algebra, the cell record format, the closure engine, the respond primitive, and — critically for drivers — the capability fibers ([`task:t02-40`](t02-40-v0.2a-kernel-frozen.md) auth, [`task:t02-41`](t02-41-v0.2a-kernel-frozen.md) authz).
Driver attach is a `respond(target=driver:<slug>, payload={action: "attach"})` per [specs/drivers/attach-detach.md](../../specs/drivers/attach-detach.md) §1, gated by the sender's shipped capability fiber.
The whole driver model is "what a sender authorized to call respond can register as a driver"; without v0.2a's shipped capability discipline, "authorized to register a driver" is undefined.

The capability discipline is the failure surface to watch — recipe 4 (adding a stdlib verb) is the closest existing analogue for "new substrate-targetable kind"; reread it before extending `respond`.
Driver-as-cell means every driver-record write goes through the same canonical-JSON / cell-id pipeline as any other cell — never patch the cell shape for drivers.

**Ship-target role.** Contributes to gate item 1 of [milestones/v0.2b-drivers-observability-packaging.md §Ship targets](../../milestones/v0.2b-drivers-observability-packaging.md) — "the driver model spec is normative and at least three drivers conform via paired fixtures."

## Acceptance

Proposed checkable acceptance items per [implementation/workflows.md recipe 10](../../implementation/workflows.md#10-promoting-a-thin-t02-nn-task-record-into-a-procedural-plan); confirm exact module boundaries and registry shape with the captain.

- `src/drivers/driver_record.py` Pydantic model round-trips driver records through canonical-JSON byte-identically; cell-id matches SHA-256 of the canonical bytes.
- `src/drivers/registry.py` registers, looks up by slug, and lists all attached drivers; the registry is rebuildable from the event log (theory row 4 / 12 — caches are recomputable).
- `src/substrate/respond.py` routes `respond(target=driver:*, payload={action: "attach"|"detach"})` to the lifecycle handler; unrecognized actions return `PCD_*` per the spec error vocabulary.
- Capability check: an attach call from a sender whose capability fiber does not include `driver-attach` for the target returns `PCA_SCOPE_INSUFFICIENT` and the driver remains in `unloaded` state per spec §1 phase 1.
- Paired fixture `t02-50f` authored under `tests/fixtures/drivers/` per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md); fixture path agreed with captain.
  Fixture covers (a) successful registration of a no-op test driver; (b) capability-insufficient registration is rejected; (c) registry survives a reboot via event-log replay.
