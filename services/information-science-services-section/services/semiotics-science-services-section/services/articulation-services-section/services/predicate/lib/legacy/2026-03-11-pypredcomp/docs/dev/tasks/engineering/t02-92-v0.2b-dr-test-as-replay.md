## Grounding

DR (disaster recovery) is structurally a property of the event log + replay, not an operational checklist.
By sysadmin reflex the dr-test spec stub would be authored as a "checklist runbook"; the substrate's discipline is that the DR test is a `respond` invocation that triggers replay-from-event-log on a fresh `$ROOT` and asserts byte-identical state.
Library grounding:

- [`recovery-via-event-log-replay-determinism`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/recovery-via-event-log-replay-determinism.md) — the structural guarantee: replay from event log produces byte-identical fibers.
  DR IS this guarantee exercised.
- [`backup-restore-fidelity`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/backup-restore-fidelity.md) — backup is content-addressed event-log capture; restore is replay; fidelity is a structural theorem, not an operational property.
- [`backup-as-cohomology-preservation`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/backup-as-cohomology-preservation.md) — DR preserves cohomology classes (including any H¹ inconsistency classes); a "DR" that loses inconsistency markers is not a DR, it is data corruption.
- [`audit-content-via-inconsistency-sheaf-cohomology`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/audit-content-via-inconsistency-sheaf-cohomology.md) — the H¹ panel from `t02-80` continues to read meaningful values after DR.
