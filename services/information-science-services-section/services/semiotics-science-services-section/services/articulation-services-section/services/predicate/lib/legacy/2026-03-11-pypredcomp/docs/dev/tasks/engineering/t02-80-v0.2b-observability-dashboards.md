## Grounding

Theory row 9 (inconsistency and H¹ audit) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
The H¹ audit pass computes the strict-regime cohomology of the substrate: 0 means consistent, non-zero classes name irreparable inconsistencies.
The panel is the captain-facing surface of this invariant — per [specs/kernel/inconsistency-repair.md](../../specs/kernel/inconsistency-repair.md), the H¹ class count is the operational integrity number.

## Description

The H¹ audit pass already exists per v0.2a (`t02-110` / `t02-120` / `t02-121` shipped).
What is missing is the *captain-facing surface* — a dashboard widget that surfaces the H¹ class count, names representative cocycles, and links into the inconsistency-repair flow.
This panel is the ship-target-2 deliverable.

**What this consumes from v0.2a.** The whole H¹ audit pass: `t02-110` (audit-pass implementation), `t02-120` (H¹ cocycle representative extraction), `t02-121` (irreparability gate).
All shipped.
This task is purely a presentation layer over those — no new audit logic, just rendering.
The dashboard frame from [`task:t02-74`](t02-74-v0.2b-observability-dashboards.md) is the structural pre-condition.
