## Description

Spec and source-cite the **authz fiber** projection from the boundary entity.
The authz fiber is the *what this sender can do* dimension — the modal restriction $\Rightarrow$ that bounds the sender's payload in `respond` Phase 2.
This is the single most load-bearing capability fiber: it is the algebraic reason capability non-amplification holds (row 8 of [references/theory-for-developers.md](../../references/theory-for-developers.md)).

The implementation exists at [`src/substrate/authorization.py`](../../../../src/substrate/authorization.py); the existing [`tests/conformance/test_modal_authz_box.py`](../../../../tests/conformance/test_modal_authz_box.py) and [`test_capability_permissions.py`](../../../../tests/conformance/test_capability_permissions.py) cover the modal box and the permission set respectively.
This task confirms the spec citations are accurate and authors the paired projection-emission fixture.

**Spec citations.**

- Capability model per [specs/security/capability-model.md](../../specs/security/capability-model.md) — the load-bearing spec.
- Modal-restriction per [decisions/authorization-is-modal-restriction.md](../../decisions/authorization-is-modal-restriction.md).
  Capability-not-ACL per [decisions/capability-not-acl.md](../../decisions/capability-not-acl.md).
- Identity per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
- Theory grounding: row 8 (capability and authorisation as modal restriction) and row 2 (the adjunction $a \odot p \le_t q \iff p \le_t (a \Rightarrow q)$) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
  Authorisation IS the $\Rightarrow$ direction of the adjunction; sender authority composes with payload via the adjoint.
- Engineering theorem: `functional-runtime-platform/theorems/capability-non-amplification` (cited in row 8) — the structural reason no admin-override is needed.

The most important discipline rule for this task is: **never add a guard clause that raises on insufficient authority**.
The restriction is algebraic — payload restricts to $\bot$ via $\Rightarrow$; no event is emitted.
If an existing code path raises rather than restricts, that is a bug to fix here, not a discipline to preserve.

**Ship-target role.** Contributes to gate item 1 of [milestones/v0.2a-multi-user-single-node.md §Ship targets](../../milestones/v0.2a-multi-user-single-node.md).
