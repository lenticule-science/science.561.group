## Grounding

[decisions/regime-classification-is-load-bearing](../../decisions/regime-classification-is-load-bearing.md) — each stdlib verb's semantics depend on which of the four envelope regimes the surrounding context evaluates under, but no per-verb spec records this dependency.
Without the addenda, dispatch-shell authoring at v0.2b will (by reflex) assume strict regime everywhere and silently mis-handle Scott-continuous / transfinite-bounded contexts.
Library grounding (one theorem per regime):

- [`strict-regime-engineering-envelope`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/strict-regime-engineering-envelope.md) — strict regime; the default admissibility class.
- [`scott-continuous-regime-engineering-envelope`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/scott-continuous-regime-engineering-envelope.md) — Scott-continuous; verbs that recurse must record this admissibility.
- [`transfinite-bounded-regime-engineering-envelope`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/transfinite-bounded-regime-engineering-envelope.md) — transfinite-bounded; verbs that need ordinal-indexed convergence record this.
- [`aperiodic-regime-engineering-envelope`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/aperiodic-regime-engineering-envelope.md) — aperiodic; verbs that depend on aperiodic settling record this and exclude transfinite-bounded.
- [`delta-pass-bounded-by-bilattice-orbit`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/delta-pass-bounded-by-bilattice-orbit.md) — the regime-meet at dispatch is bounded by the bilattice-orbit theorem; the addenda must respect this bound.

## Description

This task adds a §"Regime envelope" addendum to each stdlib verb spec.

**What this consumes from v0.2a + v0.2b.**

- v0.2a `t02-42` (settled bilattice ops) supplies the regime-classification primitive.
- v0.2a closure-rule discipline supplies the four-regime classification surface from [`decisions/regime-classification-is-load-bearing`](../../decisions/regime-classification-is-load-bearing.md).
- v0.2b `t02-100` (stdlib spec authoring) is the *first set of consumers* — every per-verb spec gains this addendum as it is authored.
- v0.2b `t02-102` (dispatch shell) consumes the addenda's regime-meet rule at runtime.

**Spec citations.**

- Multi-regime session: [specs/process/multi-regime-session.md](../../specs/process/multi-regime-session.md) — the regime-meet at dispatch composes the verb's regime-requirement with the session's regime.
- Decision: [decisions/regime-classification-is-load-bearing](../../decisions/regime-classification-is-load-bearing.md).
- Theory ground: row 5 (closure rules and the σ/Δ split) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
  The four-regime classification is named at decision-level rather than theory-row level: see [decisions/regime-classification-is-load-bearing](../../decisions/regime-classification-is-load-bearing.md) and the per-regime envelope theorems cited above.

**Modules to touch.** Each per-verb spec under `specs/stdlib/` gains §"Regime envelope" with: (a) the admitted-regime set (typically a subset; e.g., a verb requiring transfinite-bounded saturation is *not* admitted under aperiodic); (b) the per-regime semantics differential (what changes, what stays); (c) the regime-meet behaviour at dispatch (the verb's regime-requirement composes with the session's regime per `multi-regime-session.md`); (d) cross-citation to the per-regime envelope theorem(s) the verb depends on.

**Procedure.** Follow [implementation/workflows.md recipe 4](../../implementation/workflows.md#4-adding-or-extending-a-stdlib-verb) for the per-verb editing pattern (this task adds the regime addendum, not a new verb).
For each verb: (1) classify its admissible regimes by reading the verb's body; (2) author the §; (3) cross-cite the relevant theorems; (4) verify the regime-meet at dispatch matches the dispatch-shell expectation.

**Ship-target role.** Pre-condition for the v0.2b stdlib normative gate.
Without these addenda, the dispatch shell would silently assume strict regime everywhere and break under Scott-continuous workloads.

**Depends on.** [`task:t02-100`](t02-100-v0.2b-stdlib-and-dispatch-shell.md).
Coordinates with [`task:t02-102`](t02-102-v0.2b-stdlib-and-dispatch-shell.md) (dispatch shell consumes the addenda).
