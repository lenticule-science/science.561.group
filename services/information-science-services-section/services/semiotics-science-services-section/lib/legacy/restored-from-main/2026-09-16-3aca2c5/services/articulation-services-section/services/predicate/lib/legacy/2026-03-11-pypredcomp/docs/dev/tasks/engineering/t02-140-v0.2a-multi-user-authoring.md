## Description

Implement the bootstrap-users routine that runs in boot Phase 3 (sub-phase 4.1) on a freshly-initialised `$ROOT`.
The routine reads the deployment's bootstrap-user manifest and emits, for each manifest entry, the boundary cell + the four projection cells + the per-user capability fibers + the manifest-hash recording cell.
On a re-boot against an existing event log, the routine is a no-op.

**Spec citations.**

- [specs/init-boot/boot-sequence.md §4.1](../../specs/init-boot/boot-sequence.md) — the four-step bootstrap-users routine.
- [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md) — each user is a boundary entity that projects four fibers.
- [decisions/single-respond-primitive.md](../../decisions/single-respond-primitive.md) — user lifecycle changes go through `respond`; the bootstrap routine NEVER modifies an existing user.
- Theory grounding: row 12 of [references/theory-for-developers.md](../../references/theory-for-developers.md) (boot sequence and the four-layer rule architecture).
  Boot-determinism per the [boot-determinism theorem](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/boot-determinism.md) — the bootstrap routine MUST be a deterministic function of (manifest, persistent set).
