## Description

Round 3 §2.1 named the *drivers-lossy-counit* cross-cutting deferral: each driver implements the substrate→host adjunction whose counit ε must be either provably faithful (the driver round-trips the substrate cell byte-identically through the host surface) or explicitly recorded as lossy with a named per-driver fidelity-witness class (per the round-4 witness-lifecycle pattern §2 row 4).
Without per-driver discipline, the v0.2b drivers ship with implicit and inconsistent counit-handling.

This task adds a §"Counit fidelity" sub-section to each driver spec under `specs/drivers/` recording:

- The counit's fidelity status: `faithful` (round-trip is byte-identical) or `lossy` (round-trip drops named information).
- For lossy counits: what is dropped, why it cannot be preserved on the host surface, and the per-driver fidelity-witness emission shape per [`_patterns/witness-lifecycle.md`](../../specs/_patterns/witness-lifecycle.md).
- For faithful counits: the conformance-vector citation asserting byte-identical round-trip.
- Cross-citation to [`driver-as-adjunction-with-counit`](../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theorems/driver-as-adjunction-with-counit.md).

## Acceptance

- Each driver spec under `specs/drivers/` carries §"Counit fidelity".
- The fidelity status (`faithful` / `lossy`) is named explicitly per driver.
- Lossy counits emit a `driver-fidelity` witness per the witness-lifecycle pattern.
