## Description

`specs/drivers/attach-detach.md` defines a four-phase attach (capability check → load → register → schedule extract loop) and a drain-then-quiesce detach.
This task is the Python implementation: the attach/detach handlers, the in-flight-call tracker, and the cell-quiescing routine that marks a detached driver's cells stale.

**What this consumes from v0.2a.** The capability check at attach-phase 1 reads the v0.2a-shipped authz fiber from [`task:t02-41`](t02-41-v0.2a-kernel-frozen.md).
The drain-in-flight at detach-phase 1 reads the v0.2a-shipped session-attention fiber from [`task:t02-42`](t02-42-v0.2a-kernel-frozen.md) — "in-flight" is "currently in some session's attention fiber on this driver's surface."
The driver-record and registry from [`task:t02-50`](t02-50-v0.2b-driver-model-and-three-drivers.md) are the substrate this task animates.

## Acceptance

Proposed checkable acceptance items per [implementation/workflows.md recipe 10](../../implementation/workflows.md#10-promoting-a-thin-t02-nn-task-record-into-a-procedural-plan); confirm exact handler signatures and quiesce semantics with the captain.

- `src/drivers/lifecycle.py` implements `attach(driver_slug, sender)` running the four phases per spec §1; failure at any phase leaves the driver in the prior state and emits the spec-named error code (`PCA_SCOPE_INSUFFICIENT`, `PCD_LOAD_FAILED`, etc.).
- `detach(driver_slug, sender)` runs phase 1 (drain in-flight per `t02-42` attention fiber) before phase 2 (deregister); cells of the detached driver are marked stale (kind-specific `quiesced` predicate), not deleted.
- The lifecycle is replay-deterministic: replaying the event log of a session that attached, used, and detached a driver reproduces the exact same registry state byte-identically (recipe 7 discipline).
- Audit: every lifecycle transition is one or more cells in the event log; the captain can reconstruct "when did this driver attach and who attached it" from the log alone.
- Paired fixture `t02-53f` authored under `tests/fixtures/drivers/` per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md); fixture path agreed with captain.
  Fixture covers (a) clean attach + detach; (b) attach denied by capability; (c) detach with one in-flight call (drain waits, then quiesces); (d) reboot mid-attached state, replay reproduces registry byte-identically.
