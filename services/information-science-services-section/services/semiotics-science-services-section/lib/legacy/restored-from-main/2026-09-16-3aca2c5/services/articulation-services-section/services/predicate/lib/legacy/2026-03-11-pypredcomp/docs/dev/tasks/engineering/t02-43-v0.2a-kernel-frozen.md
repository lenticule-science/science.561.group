## Description

Spec and source-cite the **history fiber** projection from the boundary entity.
The history fiber is the *what this session/user has previously authored or attended to* dimension — the audit-side companion to authz (write) and attention (read).
Per row 12 of [references/theory-for-developers.md](../../references/theory-for-developers.md), caches are recomputable from the event log; the history fiber is one such cache, projected from the per-entity event-log slice.

A history-fiber read for `user:<slug>` walks the event log and surfaces every event whose `sender = user:<slug>` (for the authoring side) or whose target was attended to by `user:<slug>` (for the read side).
The fiber-cache reconcile routine (`t02-143`) rebuilds it from event-log truth on boot.

**Spec citations.**

- Identity per [decisions/identity-is-boundary-projection.md](../../decisions/identity-is-boundary-projection.md).
- User-as-boundary per [specs/security/user-as-boundary.md](../../specs/security/user-as-boundary.md).
- Event log is JSONL per [decisions/event-log-is-jsonl.md](../../decisions/event-log-is-jsonl.md) — the truth-source the history fiber projects from.
- Event ordinal is time per [decisions/event-ordinal-is-time.md](../../decisions/event-ordinal-is-time.md) — history is ordered by ordinal, not wall-clock.
- Theory grounding: row 12 (boot sequence and the four-layer rule architecture) and row 11 (sessions) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
  The history fiber is a derived cache; the algorithm "rebuild from history, never patch" applies (`predicated-computing/theorems/cache-coherence-via-functorial-projection`).
