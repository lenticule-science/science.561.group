## Description

Per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md), every `t02-NN` task that ships normative substrate behaviour has a paired `t02-NNf` fixture-authoring task with its own conformance gate.
This is that pair for [t02-33](t02-33-v0.2a-multi-user-authoring.md).

The fixture lives at `tests/conformance/test_t02_33f_inter_session_messaging.py` and exercises the ship-target-#5 behaviour from [milestones/v0.2a-multi-user-single-node.md](../../milestones/v0.2a-multi-user-single-node.md) against the spec [specs/process/inter-session-messaging.md](../../specs/process/inter-session-messaging.md) §11:

- **Scenario leg** (`test_inter_session_messaging_full_surface`) — provisions the 3-user manifest via `ensure_users_from_manifest`, opens admin/member/member sessions with the `ROLE_CAPABILITIES` defaults, and walks: every canonical `msg-type` round-trips (§11.2); an unknown `msg-type` is rejected with `PCS_MESSAGE_TYPE_UNKNOWN` and advances no event-log state (gate-ordering); a broadcast envelope addresses both recipients and `mark_read` on one recipient leaves the other's `has-unread-message` cell intact (§11.4); a `response`'s `responds-to` predicate is reachable from the original `query` via `stdlib.project` (§11.5); a session holding only `signal:session-message:query` is permitted that kind but denied `task-handoff` with `PCA_SCOPE_INSUFFICIENT` and the denial advances no event-log state (§11.3 + §6.3 gate-ordering invariant).
- **Determinism leg** (`test_scenario_replays_byte_identical`) — runs the full provision + scenario sequence twice on fresh substrates with deterministic session-slug generation, deterministic message-slug generation, deterministic `time.time_ns` for messaging-emitted events, and no `wall_clock_ns` injection on the genesis event, and asserts byte-identical `events.jsonl` plus passing hash-chain verification on both runs (§11.7).

## Acceptance

- The fixture file exists, is collected by pytest, and both tests pass against the current implementation.
- The fixture exercises the spec's claims (typed kinds, capability-bounded send, per-recipient broadcast read state, threading via `responds-to`, replay determinism, gate-ordering invariant), not just the implementation's incidental behaviour, per [decisions/fixture-authoring-paired-task.md](../../decisions/fixture-authoring-paired-task.md) §"Why".
