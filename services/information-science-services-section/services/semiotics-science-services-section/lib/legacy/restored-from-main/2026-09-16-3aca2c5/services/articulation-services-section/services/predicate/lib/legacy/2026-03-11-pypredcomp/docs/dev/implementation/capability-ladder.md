# Capability ladder

The next-stretch documents are organised by *release* — one section per stage, each stage closing one milestone.
This doc is organised by *capability dependency* — one rung per landing, each rung naming the prior rung that makes it possible and the next rung it makes possible.

The discipline (per [next-stretch.md §"How this plan was derived"](next-stretch.md#how-this-plan-was-derived)) is that **every stage's existence is forced by a theorem whose hypothesis is the previous stage's deliverable**.
The ladder makes that chain explicit.
If you can read down a column without skipping rungs, the plan is sound; if you find a rung whose theorem-hypothesis isn't the rung above's deliverable, surface it — the plan is wrong, not the theory.

## How to read

- **Rung** — short slug for the landing; the cross-reference into the per-stage plan.
- **Builds** — the artefact (spec, module, fixture, projection) the rung produces.
- **Theorem grounding** — the on-disk theorem (per [Thread H](next-stretch-v0.4-v0.6.md#thread-h-never-cite-a-theorem-name-that-is-not-on-disk)) that authorises the build.
  No phantom citations.
- **Trove reduction** — the captain-trove idea the rung specialises, plus the on-disk theorem the trove idea reduces to (per [Thread G](next-stretch-v0.4-v0.6.md#thread-g-every-claimed-new-primitive-must-be-reduced-to-an-existing-theorem)).
  Where a trove file is named, the file lives under [`operations/engineering/triage/operations/command/ideas/triage/`](../../../../../../triage/operations/command/ideas/triage/) and is catalogued in [references/ideas-trove.md](../references/ideas-trove.md).
- **Unblocks** — the specific later rung that cannot start until this rung is in.
  Cite the later rung by slug; "later landings depend on this" is too vague to verify.

The ladder is forward-only.
If a rung is in flight, every rung below it is *blocked*; that's the point — the ladder names the blocking, so the next agent picks the right rung.

## Work-theory frame

The ladder's structure is grounded in [predicated-work](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/_index.md); each column above is a specific instance:

- The ladder *as a whole* is [plan-as-tensor-of-task-cobordisms](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/plan-as-tensor-of-task-cobordisms.md): rungs in the same release row tensor in parallel; rungs across rows compose strictly.
  This is what "parallel-eligible rung from the same release row" in §"How the ladder is used" formally is.
- Each **Rung** is a [regime-of-task](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/regime-of-task.md) instance — the rung's regime tag is what makes it dispatchable, and "in flight" vs "landed" are positions in the rung's own regime, *not* states of a separate scheduler.
- The **Builds** column names the [witness-as-increment](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/morphisms/witness-as-increment.md) deposit the rung produces — the artefact's existence on disk is the witness that the rung's settling has occurred.
  "Conformance proof" sub-sections in the per-stage docs are the explicit settling reads.
- The **Theorem grounding** column is the math substrate the rung settles into; the rung's existence is licensed by the named theorem and *only* by it.
  "Phantom rungs" (Thread G) are exactly rungs whose theorem-grounding does not on-disk-exist, i.e. rungs whose [regime-of-task](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/regime-of-task.md) regime is not yet authored.
- The **Unblocks** column encodes the [workflow-composition](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/workflow-composition.md)-induced precedence: rung B unblocks rung C iff C's hypothesis is B's deliverable, which is the workflow-composition law read on the rung graph.
  "Spotting a phantom rung" in §"How the ladder is used" is detecting a violation of this composition.
- The "Conformance proof" sub-sections in the per-stage docs are [completion-as-quiescence](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/completion-as-quiescence.md) at rung scope: a rung is landed iff its predicate column has quiesced, not iff someone marks it `status: done`.
- The release-row partitions (v0.2a, v0.2b, v0.3, v0.4, ...) are the rung-scope projection of the [cadence-as-step-shift-rg-flow](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/cadence-as-step-shift-rg-flow.md) cadence carried by [milestones/_index.md](../milestones/_index.md): each release-row settles, then the next opens at the post-shift fixed-point.
- The ["Candidate landings not yet on the ladder"](#candidate-landings-not-yet-on-the-ladder) appendix carries items that are regime-known but not yet [dispatch-readiness](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/concepts/dispatch-readiness.md)-licensed; promotion to a formal rung is the act of demonstrating their readiness predicate holds at the named release.
  The 10C "geometric-computation" candidate is the limiting case — its regime cannot be tagged until the math-side authoring closes the open theorem, so per [dispatch-readiness-regime-is-strict](../../../../../../../../theories/humanities/theories/sociology/theories/work/theories/predicated-work/theorems/dispatch-readiness-regime-is-strict.md) it cannot be promoted at all until then.

## How the ladder is used

1. **Picking the next landing.** Find the lowest unlanded rung; verify every rung above it is in.
  If a rung above is in flight rather than landed, the lower rung is *blocked*; pick a parallel-eligible rung from the same release row instead.
2. **Scoping a session.** A session whose horizon is a single rung uses the per-stage doc directly.
  A session whose horizon spans multiple rungs uses this ladder to verify the order is forced by the dependency chain.
3. **Spotting a phantom rung.** If you find yourself wanting to add a rung whose theorem-grounding is "TBD" or whose unblocked-rung is "lots of stuff", per Thread G ([next-stretch-v0.4-v0.6.md](next-stretch-v0.4-v0.6.md#thread-g-every-claimed-new-primitive-must-be-reduced-to-an-existing-theorem)) the rung is the wrong shape — either reduce its theorem to an existing on-disk slug, or surface a new theorem for the math-side to author.
  Do not add the rung silently.
4. **Surfacing a dependency error.** If you discover a rung's claimed prerequisite is not actually load-bearing, the dependency arrow is wrong; surface and edit *here*, not in the per-stage doc — the per-stage doc inherits the dependency from this ladder.
