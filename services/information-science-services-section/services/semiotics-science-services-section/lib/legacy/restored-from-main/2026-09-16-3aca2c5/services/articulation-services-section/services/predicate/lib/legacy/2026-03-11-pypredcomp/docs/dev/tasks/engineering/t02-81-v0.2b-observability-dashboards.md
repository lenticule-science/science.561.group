## Grounding

Theory row 4 (stratified facts) and row 5 (closure rules) of [references/theory-for-developers.md](../../references/theory-for-developers.md).
When a cell is saturated to a value that surprises the captain, the diagnostic projection answers "which closure-rule firings, in which order, produced this saturation?" — it surfaces the *derivation tree* of a saturated cell.
This is the operational form of [`flatfile-agentic-resource-system/concepts/four-layer-rule-architecture`](../../../../../../../../../theories/engineering/theories/tech/theories/computing/theories/predicated-computing/theories/agential-orchestration-platform/theories/flatfile-agentic-resource-system/concepts/four-layer-rule-architecture.md) made captain-visible.

## Description

The diagnostic-projection backend (`project_derivation`) lives in the kernel per [`task:t02-75`](t02-75-v0.2b-observability-dashboards.md) (per `pt-03`).
This task is the dashboard panel that surfaces it: given a saturated cell, render its derivation tree in a captain-readable form, with click-through to each closure-rule firing.

**What this consumes from v0.2a + v0.2b.** v0.2a shipped the closure engine and stratified facts (`t02-43` history fiber); the derivation is computed against those settled surfaces.
From v0.2b: the dashboard frame from [`task:t02-74`](t02-74-v0.2b-observability-dashboards.md), and the `project_derivation` backend from [`task:t02-75`](t02-75-v0.2b-observability-dashboards.md) / [`pt-03`](pt-03-diagnostic-projection.md).
This task is pure presentation; if the backend isn't ready, the panel surfaces a "diagnostic-projection backend not available" affordance and degrades gracefully.
