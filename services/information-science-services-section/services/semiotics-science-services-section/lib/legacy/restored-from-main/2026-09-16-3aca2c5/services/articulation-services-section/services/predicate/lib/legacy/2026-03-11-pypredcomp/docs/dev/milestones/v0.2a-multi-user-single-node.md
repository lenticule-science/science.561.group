## Goal

The substrate supports **multiple users on a single node** with full capability discipline, per-stratum projection materialisation, and inconsistency-repair lifecycle.
The kernel surfaces (`respond`, σ/Δ passes, projection naturality, fuel composition, binary-cell emission) are shipped and fixture-covered.
Boot ships bootstrap-users and fiber-cache reconcile.
This is the first of two milestone halves that together replace the original v0.2 plan per [decisions/v0.2-split-into-v0.2a-and-v0.2b.md](../decisions/v0.2-split-into-v0.2a-and-v0.2b.md).

v0.2a does **not** ship: drivers (v0.2b picks up), observability/governance dashboards (v0.2b), Nix-flake skeleton (v0.2b), stdlib verb specs beyond what the kernel needs (v0.2b), federation/network (deferred per [decisions/network-spec-defer-until-implementer-named.md](../decisions/network-spec-defer-until-implementer-named.md)), self-hosting (retargeted to v0.3 per [decisions/trusting-trust-bootstrap-path.md](../decisions/trusting-trust-bootstrap-path.md)).

## Scope

### Kernel - `respond` Phase 1–4 shipped per [specs/kernel/respond.md](../specs/kernel/respond.md), including §3.1 fuel-and-determinism reconciliation and §8 binary-cells cross-reference. - σ-saturation and Δ-stabilisation passes per [specs/kernel/sigma-delta-passes.md](../specs/kernel/sigma-delta-passes.md), including §9 H¹ audit pass. - Projection naturality per [specs/kernel/projection-naturality.md](../specs/kernel/projection-naturality.md) — per-stratum materialisation under presheaf functoriality. - Fuel composition per [specs/kernel/fuel-composition.md](../specs/kernel/fuel-composition.md) — five fuel surfaces under the Lawvere-quantale. - Inconsistency-repair lifecycle per [specs/kernel/inconsistency-repair.md](../specs/kernel/inconsistency-repair.md) — witness emission, source classification, optional `repair_resolution`. - Binary-cell emission per [specs/kernel/binary-cell-emission.md](../specs/kernel/binary-cell-emission.md) — sibling primitive for s ≠ o cells. - Cost model per [specs/kernel/computational-model.md](../specs/kernel/computational-model.md) §9 — per-respond bound in strict regime.

### Multi-user - Multi-user authoring (admin, member, observer roles) per the boundary-projection identity scheme. - Capability fibers (auth / authz / attention / history) per user. - Inter-session messaging via the multi-regime-session discipline per [specs/process/multi-regime-session.md](../specs/process/multi-regime-session.md). - Bootstrap-users routine per [specs/init-boot/boot-sequence.md](../specs/init-boot/boot-sequence.md) §4.1. - Fiber-cache reconcile per [specs/init-boot/boot-sequence.md](../specs/init-boot/boot-sequence.md) §4.2.

### Fixtures - Paired `t02-NNf` fixture-authoring tasks per [decisions/fixture-authoring-paired-task.md](../decisions/fixture-authoring-paired-task.md).
Every implementation task in v0.2a ships against fixtures.

## Ship targets

v0.2a ships when six gates close.
Pick them up in landing order; L1/L2 are sequential, L3/L4 are parallel-eligible after L1.

**Current focus: L2 — `bootstrap_users` and `fiber_reconcile` divergence-free reconcile against a multi-user manifest of ≥3 users** (closes gate 3).
L1 (personnel → boundary migration) closed 2026-05-03 — module + conformance test (incl. byte-identical replay) + sequencing decision ([personnel-migration-sequenced-before-bootstrap-users](../decisions/personnel-migration-sequenced-before-bootstrap-users.md)) + spec §4.0 are all in.
