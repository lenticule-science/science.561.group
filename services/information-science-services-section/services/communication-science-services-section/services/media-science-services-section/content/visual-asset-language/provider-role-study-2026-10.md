# Image-provider role study — 2026-10

This is a capability-routing note, not a vendor endorsement.

## Stable layer

Do not bind the Koios visual language to provider names. Providers are interchangeable renderers beneath `koios.visual-scene/v3`.

## Current useful provider roles

### Google Nano Banana 2 / Pro

Useful for:

- multi-reference consistency;
- broad scene understanding;
- complex compositional instructions;
- high-resolution production;
- batch generation.

Operational role: generalist renderer and reference-driven scene renderer.

### Ideogram 4 / 4.5

Useful for:

- precise edit chains;
- transparent-background generation;
- strong prompt fidelity;
- reference-image steering;
- clean designed illustration.

Operational role: component renderer, revision renderer, transparent asset producer.

### Recraft

Useful for:

- vector-oriented production;
- geometry-sensitive editorial illustration;
- repeatable style systems;
- production workflows.

Operational role: preferred vector/shape renderer. Red Cup now carries an admitted credential-blind V4.1 vector request/execution path.

### OpenAI GPT Image family

Useful for:

- broad semantic composition;
- edits from image references;
- alternative renderer for provider-diversity assays.

Operational role: generalist comparator and difficult-scene renderer. Red Cup now carries an admitted credential-blind GPT Image generation path for the current GPT Image 2 / 2.5 family.

## Routing policy

Route by **component need**, never by publication brand. All Koios scene renderers must preserve the canonical isometric/axonometric projection contract; provider-specific perspective drift is a conformance failure.

Examples:

- transparent symbolic actor → Ideogram, with GPT Image / Gemini fallbacks
- reusable vector institution, trajectory, evidence lattice, network geometry → Recraft V4.1 Vector
- complex multi-reference world/terrain scene → Nano Banana 2 / Pro
- independent generalist comparison → GPT Image 2 family
- fast variant exploration → lower-latency healthy generalist provider
- final layout/text → deterministic assembler, never a generator

## Research backlog

Measure providers on:

- semantic-role adherence;
- transparent-edge quality;
- geometry cleanliness;
- palette compliance after normalization;
- reference-image consistency;
- cross-seed stability;
- output editability;
- cost per admitted component;
- latency per admitted component;
- recognizability after deterministic Koios assembly.

Provider scores should be empirical and refreshed. No model name is part of the durable Koios grammar.
