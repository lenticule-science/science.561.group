# Candela et al. 2007 — The DELOS Manifesto

Read at the D-Lib Magazine URL above, 2026-09-08. Companion journal-article
form of the fuller DELOS Digital Library Reference Model (Candela et al.,
eds., version 0.98, DELOS Network of Excellence on Digital Libraries, EU
FP6 project no. 507618, December 2007); the definitions are stated
identically in both, and this shorter, openly hosted article is the disk
source cited here.

## Why this is central

The Manifesto is the field's standard three-way split of what "a digital
library" names, and it is the split
[digital-library](../../../glossary/terms/digital-library.md) is built on:

- **Digital Library (DL)**: "A possibly virtual organization that
  comprehensively collects, manages, and preserves for the long term rich
  digital content, and offers to its user communities specialized
  functionality on that content, of measurable quality and according to
  codified policies."
- **Digital Library System (DLS)**: "A software system that is based on a
  defined (possibly distributed) architecture and provides all
  functionality required by a particular Digital Library. Users interact
  with a Digital Library through the corresponding Digital Library
  System."
- **Digital Library Management System (DLMS)**: "A generic software system
  that provides the appropriate software infrastructure both (i) to
  produce and administer a Digital Library System incorporating the suite
  of functionality considered foundational for Digital Libraries and (ii)
  to integrate additional software offering more refined, specialized, or
  advanced functionality."

This distinguishes the organization/policy layer (DL) from the running
software (DLS) from the generic software that builds DLSs (DLMS) — a
distinction amusewiki collapses (amusewiki is a DLMS that TAL runs one DLS
instance of) and one a house library has to place its own components
against.

## What it does not settle

The Manifesto is a foundations paper, not an implementation; it does not
specify a discovery protocol, a preservation model, or a metadata schema —
those are OPDS, OAIS, and Dublin Core/MARC/schema.org's jobs respectively,
each a separate term in this glossary.
