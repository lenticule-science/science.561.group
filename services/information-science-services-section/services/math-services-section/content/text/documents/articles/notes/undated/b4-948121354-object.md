An **object** is an element of $\mathrm{Ob}(\mathcal{C})$ for a category $\mathcal{C}$ [@maclane1971, Ch. I]. In the 561 predication category — the category whose objects are predicates and whose morphisms are typed relations between predicates [@lambek1958] — an object is the basic kind. Every other categorical thing (morphisms, fibers, settlings) is defined relative to objects.

An object's identity is its name in the object-set. Two objects are equal iff their names are equal. The object carries no further inherent data; cells about an object — its description, its incident predications, its position in any fibration — live as separate predication cells in the object's fiber, not as fields on the object itself.

The minimality is load-bearing. If an object carried built-in cells (description, references, kind-tag, etc.), the categorical machinery operating over objects (the predication-fibration, the closure operator, the hyperdoctrine adjoints) would have to know about those cells and preserve them under reindexing, composition, and adjunction. Keeping objects minimal keeps the categorical machinery uniform.

A 561-OS thing — a directory in the recursive layout — projects to an object at the math layer. The projection is a specific direction: math → realization. The same object can project to many realizations (POSIX directory, in-memory node, content-addressable cell, wire-format envelope); object itself carries none of those realizations' data.
