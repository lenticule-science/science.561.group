# Relational and Informational Mathematics

Obsmetrologia is not a library that imports ordinary subject areas and then
renames them. The live checkout presents it as a dependency-free Lean 4 library
whose import spine is a derivation order:

`Primitive`, `Articulation`, `Language`, `Calculus`, `Site`, `Closure`,
`Cohomology`, `Dynamics`, `Persistence`, `Relational`, `Thermodynamics`,
`Computing`.

That spine is the first reference point for relational/informational
mathematics in this repository. The words "relational" and "informational" name
the downstream mathematics generated from marks, utterances, articulation,
predication, positing, settling, charge, valuation, closure, and cohomological
obstruction. They do not license a shortcut back to familiar external
foundations.

## What Is Re-founded

The live project describes itself as a generative foundation. A mark is admitted.
Marks appear in token and claim positions. An utterance pairs those positions.
Utterances articulate recursively. Articulation produces a four-corner cell.
That cell is read again as charge. Charge supports two orders, valuation,
closure, quantification, equality readings, sheaves, cohomology, dynamics,
persistence, relational boundary sectors, thermodynamics, and computing
formats.

This is why the documentation cannot start with "category theory", "logic",
"topology", "physics", or "information theory" as given subjects. Those names
can appear only as recovered comparisons, downstream projections, or frontier
bridges when the local construction earns them.

## The Four Main Evidence Carriers

Use these surfaces together:

- Lean is settlement: declarations, proofs, examples, docstrings, and compiled
  dependency order.
- Blueprint is incidence: precise claim-sites, dependency edges, green proved
  nodes, and red frontier obligations.
- Verso is exposition: reader-facing explanations, tutorials, examples, and
  conceptual routes through the proved and stated material.
- Corpus and notes are provenance: generative source, exploratory pressure, and
  older language that may or may not have been promoted.

No one carrier is the whole mathematics. A mature documented claim is glued
across them: Lean declaration, Blueprint node, Verso explanation, API lookup,
and provenance path.

## The Agent-Facing Documentation Role

The `.agents/docs` tree is not a replacement for Verso. It is an operating layer
for future agents. It should answer:

- How do I enter the mathematics without normalizing it?
- Which path should I read first?
- How do I decide where a new concept belongs?
- How do I keep Lean, Blueprint, Verso, and provenance aligned?
- Which claims are proved, frontier, recovered, or only provenance?

The agent docs are allowed to be explicit about work procedure. Verso should
teach readers. Blueprint should audit claims. Lean should settle declarations.

## What Counts As Coverage

Complete Diataxis coverage here does not mean four long essays for every term.
The existing Verso rule says coverage is attached to claim-sites:

- namespace-scale topic;
- module-scale concept;
- declaration-scale term.

Every topic, concept, and term should have an addressable tutorial, guide,
explanation, and reference surface. A topic may inherit a general tutorial; a
term may have a compact reference entry rather than an essay. Missing modes
should be visible obligations, not silent gaps.

## What Was Revealed While Constructing This

The documentation object is itself relational. The first hidden requirement is
not "write more pages"; it is "maintain a fibered coverage map over claim-sites."
Each claim-site can have tutorial, guide, explanation, reference, Lean,
Blueprint, Verso, API, and provenance fibers.

The second hidden requirement is maturity-bounded speech. A downstream
relational physics theorem, a Collatz frontier node, an aperiodic classification
claim, and a primitive mark definition cannot be documented with the same voice.
The status is part of the meaning.

The third hidden requirement is inheritance. Because the proof tree is large,
coverage must be reusable by level. A topic page can establish the tutorial
entry path. Concept pages can explain local generation. Term references can stay
compact and point back to the topic/concept coverage.
