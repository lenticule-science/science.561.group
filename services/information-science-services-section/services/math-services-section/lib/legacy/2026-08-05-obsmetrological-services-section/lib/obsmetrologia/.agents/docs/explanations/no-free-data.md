# No Free Data

The live project guidance states the core law plainly: past `Mark` and
`Articulating`, nothing is free. This is both a proof discipline and a
documentation discipline.

In Lean work it means later modules must not introduce hard trust surfaces such
as `axiom`, `opaque`, `constant`, or `native_decide`. A missing proof may remain
visible as a frontier marker, but a later module must not smuggle in an
unearned substrate.

In documentation work it means later explanations must not pretend a familiar
object was present from the beginning. If order appears, say how it is generated.
If equality appears, say which valuation, order, and quantifier machinery
generates the equality reading. If a physical or thermodynamic reading appears,
say which finite relational carrier, obstruction, closure, or cohomology surface
currently witnesses it.

## Primitive Admission

The bottom surface admits a mark and the articulating recursion. The root
project orientation and the current module spine place those at the beginning:

- `Obsmetrologia.Primitive.Mark` carries `Mark` and `Kind`.
- `Obsmetrologia.Articulation.Articulating.Utterance` pairs token and claim
  positions.
- `Obsmetrologia.Articulation.Articulating` gives the recursive articulating
  carrier.

Everything after this must be generated from earlier material.

## Derived Rather Than Imported

A received mathematical term can be useful as a comparison, but it is not
evidence. For example:

- predication generates subject-predicate-object cells and their operations;
- positing generates charge and the two order surfaces;
- settling generates closure behavior and fixed-point readings;
- hyperdoctrine and equality appear after valuation and reindexing;
- sheaf and cohomology surfaces appear after settling and valuation;
- relational boundary sectors appear downstream of closure, cohomology,
  persistence, and finite carriers.

When writing docs, avoid sentences of the form "Obsmetrologia is just X." A
better shape is "Obsmetrologia recovers or projects an X-like surface from Y,
under status Z."

## Documentation Consequences

Every explanatory page should name its inputs and outputs.

Inputs are the earlier Obsmetrologia objects the page relies on. Outputs are the
later objects, constructions, examples, or frontier obligations the page makes
possible.

If those cannot be named, the page is not yet an explanation. It may be
provenance, a question, or a frontier note.

## Agent Failure Modes

The most common failure mode is pattern-matching a local word onto a public
discipline. Do not do that. Search and read the local corpus, Lean module,
Blueprint node, and Verso page first.

The second failure mode is overclaiming prose over a weak Lean statement. A
statement in docs must match the maturity of the carrier. If Lean proves a
finite witness, call it a finite witness. If the analytic or continuum reading is
only a Blueprint frontier obligation, call it frontier.

The third failure mode is inventing a missing classical object. Absence can be a
design judgment. If an expected object is missing, look for the local generated
form instead of reconstructing the external one.
