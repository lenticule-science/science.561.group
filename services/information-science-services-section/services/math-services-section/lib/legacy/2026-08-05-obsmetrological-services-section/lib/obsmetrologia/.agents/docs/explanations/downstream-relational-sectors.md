# Downstream Relational Sectors

The live spine places `Relational`, `Thermodynamics`, and `Computing` after the
primitive, articulation, language, calculus, site, closure, cohomology,
dynamics, and persistence surfaces. That order is a warning: downstream sectors
must not be documented as independent foundations.

Relational and informational sector docs should always start by naming the
carrier that generates the sector.

## Relational Boundary Sectors

The current Blueprint chapter set includes relational boundary sectors:

- quantum contextuality;
- material states;
- finite gauge, horizon, and dense matter projections;
- reaction networks.

The Lean tree includes modules under `Obsmetrologia/Relational` for dense matter,
fluid, gaming, kinetic, liquid, material, plasma, quantum, reaction, thermo, and
filter/fiber sector surfaces.

These are downstream projections. Their docs should answer:

- Which earlier charge, closure, cohomology, persistence, or finite carrier is
  being used?
- Which part is a proved finite or algebraic witness?
- Which part is a continuum, analytic, empirical, or physics-facing frontier?
- Which Blueprint node states the dependency edge?

## Information Projection

The Blueprint includes an information projection chapter around tiles, beads,
InfoHair, and format carriers. The current persistence modules carry aperiodic
classification, finite autocorrelation, diffraction, port growth, finite local
rules, substitution and metallic moduli, and related witnesses.

The documentation should distinguish finite readouts from full analytic claims.
For example, finite autocorrelation is not automatically full diffraction; a
finite carrier can be a proved witness while the stronger analytic reading stays
frontier.

## Thermodynamics

The thermodynamics surface is downstream of closure, valuation, reaction,
probability-like carriers, and flow. Agent docs should avoid importing external
thermodynamics as a given explanatory substrate. Instead, name the local
temperature, entropy, free-energy, or transition carrier and its dependencies.

## Computing Formats

Computing docs should treat formats as projections of the same fourfold and
settlement machinery, not as unrelated serialization utilities. The computing
surface should say what mathematical structure a format preserves or exposes.

## Agent Rule

For every downstream sector page, include a "not foundation" sentence:

`This page documents a downstream projection from <inputs>, not a new primitive
substrate.`

That sentence is not defensive prose. It is a guardrail against the most likely
misdocumentation of these sectors.
